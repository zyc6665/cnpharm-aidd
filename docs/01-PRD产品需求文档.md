## 2. 产品定位

面向中国医药本部药物研发人员的 **AI 药物研发统一工作环境**。以「研发项目」和「靶点」为主线，把分散的化合物数据、蛋白结构与序列、活性与性质数据、文献、实验数据和计算结果集中管理，并串接靶点分析 → 分子/多肽设计 → 性质预测 → 虚拟筛选 → 计算评估的研发链路，形成可复用、可追溯的研发流程。

**一句话定位**：一个围绕项目与靶点组织数据、用国产算力调度模型、每一次计算结果都可回溯的 AI 药物研发工作台。

V3.0 §2.2 给出的项目目标与本平台的对齐关系：

| V3.0 项目目标 | 本平台的承载点 |
|---|---|
| 统一研发工作环境，减少在多个工具间切换 | §4.2 数据底座（项目空间 + 统一导入 + 检索）+ §4.7 工作流（预置流程一键运行） |
| 复用已验证的模型与计算工具 | §4.7.1 预置工作流 + 工具注册体系（附录 B 的 9 个预置模型全部接入） |
| 研发过程可追溯、结果可复现 | §4.8.2 计算任务过程追溯（六类元数据 + 追溯包导出） |
| 提升研发效率 | §4.6 批量虚拟筛选 + §4.7.3 队列调度（10 万条级任务分档） |

| 角色 | 代号 | 主要诉求 | 高频操作 | 平台权限档 |

## 5. 功能需求条目（以 V3.0 原文为准）

> 每条的「功能综述」「功能要求」为 V3.0 原文照录（仅做 PDF 折行还原）；「实现状态」取自 `26`，明细落点见 `02`。

### 5.1 AI 药物研发数据底座（V3.0 §4.2 ｜ 内部编号 M1）

#### AIYF-DATA-01　研发项目空间管理（V3.0 §4.2.1）

**需求编号**：`AIYF-DATA-01-SRS` ｜ **实现状态**：部分实现（已实现 2 / 部分实现 3 / 行为相反 1）

**功能综述**：平台支持按照实际研发任务建立独立的研发项目空间，将项目相关的靶点资料、化合物信息、蛋白质结构、设计结果、计算任务及分析报告统一归集。研发人员进入相应项目后，可在项目范围内开展数据管理和计算分析，避免不同研发项目之间的数据混杂。

**功能要求**：

1）**项目创建与维护**。支持创建研发项目，填写项目名称、基本信息及相关描述，对已有项目进行查询和维护。项目作为研发数据和计算成果的组织单元，与后续数据导入、模型任务和分析结果建立关联。

2）**项目资料归集**。支持将化合物、蛋白质序列与结构、活性数据、理化性质、文献及实验结果等资料关联至对应项目。项目内可集中查看已导入的研发数据及相关计算结果，形成项目级研发资料集合。

3）**项目成员管理**。支持为研发项目配置参与成员，根据项目使用需要设置基础访问权限，控制项目资料的查看、编辑及相关操作。项目成员在授权范围内开展研发工作和结果查看。

4）**项目概览**。支持查看项目基本信息、已关联研发数据、计算任务及分析成果，帮助研发人员了解项目资料和任务情况，为项目日常研发活动提供统一入口。

**业务规则**：仅可访问当前项目权限范围内的数据；模型、工具及工作流均为平台预置，用户不得自行新增或修改执行节点；预测与计算结果仅作为研发辅助参考，不作为实验验证结论

**判定与缺口**：见 `26` §3 的 AIYF-DATA-01 相关行。

#### AIYF-DATA-02　研发数据导入与接入（V3.0 §4.2.2）

**需求编号**：`AIYF-DATA-02-SRS` ｜ **实现状态**：部分实现（已实现 1 / 部分实现 4 / 未实现 3）

**功能综述**：平台面向不同类型的药物研发数据提供统一导入功能，支持通过文件上传、批量导入及必要的单条信息录入等方式，将已有研发数据纳入项目空间。

**功能要求**：

1）**化合物数据导入**。支持导入SMILES、SDF、MOL2 等常见化合物结构数据，解析分子结构信息，并关联相应的化合物名称、结构标识及已有属性信息。对于批量化合物数据，支持集中导入和解析，便于建立项目候选化合物集合。

2）**蛋白质数据导入**。支持导入蛋白质氨基酸序列及三维结构文件，兼容PDB、mmCIF 等常见结构格式。导入后可在项目内查看和管理蛋白质序列、结构文件及相关靶点信息，为后续蛋白质结构分析提供输入。

3）**活性与性质数据导入**。支持通过常见表格文件导入候选化合物的活性数据和理化性质数据，对相关字段进行解析和关联，使研发人员能够结合分子结构查看已有活性及性质信息，为后续筛选和预测分析提供参考。

4）**文献与实验数据导入**。支持将研发文献、实验记录及相关结果文件导入平台，并关联到对应项目或候选物，形成与研发对象相对应的资料记录。

5）**批量数据导入**。支持常见结构文件和表格文件的批量上传，减少大量研发数据逐条录入的工作量。导入过程中对文件格式及必要字段进行检查，对不符合要求的数据提供相应提示，方便用户修正后重新导入。

**业务规则**：仅可访问当前项目权限范围内的数据；模型、工具及工作流均为平台预置，用户不得自行新增或修改执行节点；预测与计算结果仅作为研发辅助参考，不作为实验验证结论

**判定与缺口**：见 `26` §3 的 AIYF-DATA-02 相关行。

#### AIYF-DATA-03　研发数据标准化处理（V3.0 §4.2.3）

**需求编号**：`AIYF-DATA-03-SRS` ｜ **实现状态**：部分实现（已实现 1 / 部分实现 2）

**功能综述**：不同来源的研发数据在文件格式、字段组织和结构表示方式上存在差异。平台对导入数据开展必要的标准化处理，形成适用于后续模型调用、计算分析及数据查询的规范化记录。

**功能要求**：

1）**化合物结构标准化**。对导入的化合物结构进行格式解析和必要的结构规范化处理，识别分子中的原子、化学键及相关结构信息，形成平台可识别的分子结构记录。

2）**蛋白质结构标准化**。对PDB、mmCIF 等结构文件进行格式解析，提取蛋白质结构及残基等基本信息，根据后续计算工具的输入要求进行必要的格式转换。

3）**序列数据处理**。对导入的蛋白质序列进行必要的格式和内容检查，形成标准化序列记录，为结构预测及后续结构分析提供输入。

4）**数据质量检查**。在数据导入和处理过程中检查文件完整性、格式有效性及必要字段，对存在格式错误或信息缺失的数据给出提示，减少不规范数据进入后续分析流程。

5）**数据来源与版本记录**。对研发数据记录其来源及相关版本信息，便于后续查询、引用及数据更新时进行区分，保证研发数据具有明确的来源依据。

**业务规则**：仅可访问当前项目权限范围内的数据；模型、工具及工作流均为平台预置，用户不得自行新增或修改执行节点；预测与计算结果仅作为研发辅助参考，不作为实验验证结论

**判定与缺口**：见 `26` §3 的 AIYF-DATA-03 相关行。

#### AIYF-DATA-04　专业研发数据资源管理（V3.0 §4.2.4）

**需求编号**：`AIYF-DATA-04-SRS` ｜ **实现状态**：未实现（未实现 1 / 存疑 1）

**功能综述**：平台对已有及已授权的专业研发数据资源进行统一编目、查询和调用，支持研发人员在项目范围内查阅和使用相关数据资源。专业数据资源的具体范围、数据内容和接入方式以平台交付版本及已授权数据范围为准。

**功能要求**：

1）**资源目录管理**。对平台已具备的专业数据资源进行统一编目，记录资源名称、类型、来源和可用范围等信息。

## 8. 关键设计约束：追溯模型

V3.0 `AIYF-RES-04` / `AIYF-RES-06` 要求任一计算结果可回溯到「输入数据 + 模型/工具版本 + 运行参数」。平台把这条落成**六类必须固化的元数据，缺一不可**：

| 追溯项 | 内容 | 实现落点 |
|---|---|---|
| 输入快照 | 输入文件清单 + SHA-256 + 数据版本 | `task_input_snapshots`（`backend/app/models/traceability.py`） |
| 执行环境 | 计算镜像 digest、模型名+版本、工具名+版本 | `gpu_allocations.image_ref`、`tools`/`tool_versions` |
| 运行参数 | 完整参数 JSON（含随机种子） | `Task.parameters` |
| 执行过程 | 提交人、提交时间、起止时间、退出码、日志 | `Task` + `task_logs`（`log_data.source="runtime"`） |
| 输出产物 | 产物清单 + 哈希 + 存储路径 + 大小 | `artifact_versions` + `artifact_version_files` |
| 归属关系 | 项目 / 靶点 / 候选物 / 工作流节点 | `Task.project_id`、`TaskInputSnapshot.detail` |

导出契约：`GET /api/v1/results/{id}/traceability/export`，`packageVersion = "traceability.v1"`（`backend/app/services/traceability.py` 的 `build_traceability_package`）。

**已知缺口**（详见 `26` H-15）：追溯包内的执行过程一项**不含进程退出码**、日志只给索引不含正文。若甲方按「执行过程可复核」逐字验收，这两处会被追问。

### 13.1 验收方式

1. **功能验收**：按 `02` 的需求追踪矩阵逐条演示；★ 条款（§5.1~§5.4）必须现场跑通真实数据。
   V3.0 §1.1(5) 已声明「功能原型界面图片为演示数据，不构成对数据、模型、界面细节或性能指标的承诺」——因此**原型图不能作为已实现的证据**，验收证据只能用真实任务记录。
2. **性能验收**：按 §9.1 的 300ms / 1000ms / 2s / 99.95% / 0.01% 口径压测，10 并发场景。
3. **追溯与复现验收**：验收不要求「每个模型复算结果一致」——扩散/采样类模型（Pocket2Mol、TheraPainter 等）物理上做不到。实际验收两件事：
   - **① 平台可复现能力**：D1 抽 1 个必须逐字节一致（SHA-256）；D2 抽 1 个按该模型已标定的容差比对（初值如结构 RMSD ≤ 0.5 Å、对接评分偏差 ≤ 0.5 kcal/mol）；D3 抽 1 个重复 3 次取统计量；容差初值需甲方书面确认（`D-03-12`）。
   - **② 如实声明**：不可复现的模型必须在 manifest 与详情页标注，不参与复现验收，只核对声明与实际是否一致。
4. **文档验收**：编号件 00~18 齐套（含 `03A`/`03B`/`08A` 三份补充件），并按本文件 v2.0 完成 V3.0 口径对齐。
5. **安全验收**：权限矩阵测试 + 审计日志抽查 + 备份恢复演练。
