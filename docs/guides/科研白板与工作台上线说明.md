# 科研白板与工作台上线说明

## 交付范围

- 删除积分、会员、邀请和支付产品面，不再提供相关 API、数据库字段或前端入口。
- 新增用户级科研白板，支持结构化节点、连线、视口、自动保存和工作流草稿转换。
- 新增用户工作台聚合接口，集中返回任务状态、最近白板、工作流、文件和常用工具。
- 工作流画布与科研白板共享缩放边界逻辑，缩放后拖拽坐标保持准确。

## 部署步骤

1. 部署前备份生产数据库，并确认当前 Alembic 版本。
2. 执行 `cd backend && alembic upgrade head`。
3. 部署后端和 Celery Worker，再部署前端静态资源。
4. 请求 `/health`，并以普通用户访问 `/api/v1/workspace/overview` 和 `/api/v1/research-boards`。
5. 创建白板，添加节点与连线，刷新页面确认内容、视口和版本均已保存。

## 数据与并发约束

- 单个白板最多 500 个节点、1000 条连线，笔记正文最多 20000 个字符。
- 文件与图片节点只能引用当前用户可访问且有效的文件；工具节点只能引用已发布且可访问的工具。
- 更新白板必须携带当前 `version`。并发修改返回 HTTP 409，客户端需重新载入后再编辑。
- 工作台所有资源均按当前用户过滤，不返回已删除、损坏或过期文件。

## 回滚

代码回滚前先保留数据库备份。迁移 downgrade 会删除科研白板表并恢复旧产品字段，仅用于紧急技术回滚；被删除的积分、邀请数据不会由本次迁移自动恢复。生产回滚应优先回退应用版本并从部署前备份恢复数据库。

## 验收命令

```bash
pytest test
cd frontend && npm test -- --run
cd frontend && npm run build
```

重点回归文件：`test/test_research_boards_api.py`、`test/test_workspace_overview_api.py` 和 `frontend/src/components/__tests__/ResearchBoardCanvas.spec.ts`。
