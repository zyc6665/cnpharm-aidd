## 1. 认证 / 授权 / 多租户

### P1-1 跨租户读取全平台化合物主数据
- 位置：`backend/app/api/v1/compounds.py:365-376` → `backend/app/services/domain_compounds.py:801-823`
- 证据：端点仅 `get_current_user`；`search_similar` 的 SQL 为 `select(Compound, MoleculeFingerprint).join(...).where(fp_ecfp4.is_not(None))`，无 user/project 过滤，注释即 “Tanimoto similarity search over the whole compound table”。
- 影响：任意登录用户 `POST /api/v1/compounds:search`，`threshold=0&limit=200` 即遍历全库，返回 `serialize_compound`（id/name/inchikey/smiles/mol_formula/props/created_by 等），可换探针 SMILES 反复枚举。与 `GET /compounds/{id}` 的“仅可见项目引用”口径不一致（`compounds.py:352-362`、`require_compound_read_access`）。
- 修复：`search_similar` 增加“当前用户可见化合物”子查询（EXISTS Candidate→ProjectMember，admin 全量），或端点复用 `require_compound_read_access` 口径。
- 置信度：**确认**

### P1-2 文件下载 / 删除：被移出项目的 owner 仍可操作
- 位置：`backend/app/api/v1/files.py:471-499`（download-url）、`:360-419`（download，关键 `:400` token 分支）、`:510`（delete）、`:538`（batch-delete）；判定 `backend/app/files/file_records.py:83-96`
- 证据：
  - `get_download_url` 用 `user_can_access_file`（仅 `owner_id==user.id or admin or public`，`file_records.py:89`）签发绑定本人的 browser token；
  - `download_file` 仅在 `remote_token_claims is None` 时才做项目成员校验（`files.py:400`），持有效 token 即跳过；
  - `_user_can_access_download_file` 的 docstring 明说本意是“阻止被移出项目的 editor 凭 owner_id 继续下载”（`files.py:336-357`），但 token 路径整体绕过它；
  - `delete_file` / `batch_delete_files` 用 `user_can_manage_file`（owner 语义，`file_records.py:96`）。
- 影响：曾是项目成员并上传过文件者，被移出后仍可 `download-url`→`download` 持续下载项目文件（token 可续签至 24h），并可删除项目文件（完整性/破坏）。
- 修复：download-url/download/delete 统一“项目成员 ∪ 属主”判定，且以项目成员为权威；token 只证明 file_id 绑定，不替代当前授权。
- 置信度：**确认**

### P1-3 默认 / 示例密钥（条件性 P0）
- 位置：`backend/app/config.py:158`（`ENVIRONMENT="development"`）、`:186`（`JWT_SECRET_KEY=""`）、`:227-257`（仅 staging/production 校验）；`deploy/compose/.env.k100-test.example:27-28`（内置具体 JWT、可猜 `SETTINGS_ENCRYPTION_KEY`）、`deploy/compose/docker-compose.k100-test.yml:5`（`ENVIRONMENT:-development`）
- 影响：无密钥注入直接启动 → HS256 空密钥可自签任意 `role=admin` 令牌；按示例部署且 `ENVIRONMENT=development` → 校验全跳过、示例 JWT/加密钥可被离线复用。
- 修复：所有环境启动即拒绝空/弱/示例 JWT 与 SETTINGS_ENCRYPTION_KEY；示例只留 `change-me` 并由启动校验强制替换；k100 改 `staging`。
- 置信度：**疑似（部署侧确认后即 P0）**

### P2（认证授权）
- **登录无账户级锁定**：仅按 IP 限流且缓存异常 fail-open（`backend/app/middleware/rate_limit.py:77-96`）。建议 username+IP 失败计数 + 退避。
- **refresh 无吊销/轮换**，logout 不失效（`backend/app/api/v1/auth.py:182-231`）。建议 jti 存储 + 轮换复用检测。
- **口令策略弱 + bcrypt 72 字节冲突**：`min_length=6`、`max_length=100`（`backend/app/schemas/users.py:14/76`），73–100 字符会触发未捕获 ValueError。建议 ≥12 位且 schema 与 72 字节对齐。
- **token 走 query**：refresh 与 SSE access token（`auth.py:182`、`tasks.py:495`）易进日志/Referer。建议改 Body/Cookie 或一次性 ticket。
- **GPU 端点无鉴权**（`backend/app/api/v1/gpu.py:145/184/218/254/266`）。建议至少登录，汇总走 admin。
- **属主旁路一致性**：被移出项目者仍可读/操作自己的 task/run（`backend/app/services/task_access.py:28/48`、`workflow_run_access.py:23`）。按产品口径收敛为“有 project_id 时以项目成员为权威”。

## 2. 注入 / 命令执行 / 文件与存储 / SSRF

### P1-8 python_script 执行器在宿主执行且透传环境变量
- 位置：`backend/app/tasks/executors/python_script.py:46-62`、`backend/app/tasks/executors/script_trust.py:10-13`
- 证据：`subprocess.run(["python", script_path, ...], cwd=work_dir, env={**os.environ, ...})`，在 worker 宿主以 app 用户执行；`script_trust.py:12` 非 staging/production 且无白名单时直接放行。
- 影响：管理员/工具包发布者路径可写入 `script_content` 并在宿主执行任意 Python，且继承 `DATABASE_URL`/`JWT_SECRET_KEY`/MinIO 等环境变量——爆炸半径是宿主而非容器（对比 `docker` 执行器有隔离）。仅管理员/发布者可达，故列 P1 而非 P0。
- 修复：生产强制非空白名单（已有）+ 开发改显式开关；更彻底复用 docker 执行器，并最小化 env 透传。
- 置信度：确认（代码行为）/ 利用取决于部署 ENVIRONMENT 与发布权限

### P2（注入/执行/文件）
- **分片上传无单分片大小上限**（`backend/app/api/v1/uploads.py:89`、`services/uploads.py:299-302`，`Body(...)` 整段入内存）→ 内存/磁盘 DoS。建议流式 + 单分片上限 413。
- **`/files/convert/sdf-to-pdb` 先 `await file.read()` 再判大小**（`files.py:258-262`）→ 内存 DoS。建议流式累计。
- **搜索 LIKE 通配符未转义 / keyword 无长度上限**（`compounds.py:116-118`、`targets.py:156`、`tools_public.py:155-157`、`users.py:420-422`）——无 SQL 注入，仅 `%`/`_` 放大；建议转义 + 限长。
- **解压无解压后大小上限**（`tasks/molecule_scoring.py:142-146`、`services/image_asset_import.py:115`）→ zip/tar 炸弹 DoS；建议校验 `file_size` 累计上限。
- **`Content-Disposition` 原始 f-string 拼接**（`files.py:438`）→ 低危头注入；建议走 `artifact_responses.py` 的 `content_disposition()`。
- **本地存储 `_get_full_path` 接受绝对路径、无根约束**（`storage/local.py:27-33,80-137`）——当前不可达，纵深防御；建议 `is_relative_to(base_path)` 校验。

### 已排除（注入域）

- **命令注入：无**（除 P1-8；docker/k8s/ssh 均 argv 列表 + `shlex.quote`，无 `shell=True`）。

- **反序列化：无**（无 pickle/joblib/yaml.load 非 safe/eval/exec 处理不可信输入）。

## 4. 前端与依赖

### P1-6 工具文档 Markdown 链接协议白名单可绕过 → 存储型 XSS
- 位置：`frontend/src/domain/tools/tool-documentation.ts:28,39-45,55-56`；`frontend/src/components/tools/ToolDetailModals.vue:28`
- 证据：`UNSAFE_PROTOCOL_RE=/^\s*(javascript|data|vbscript):/i` 只匹配开头连续 scheme；`sanitizeHref` 仅 `trim()` + 该正则；`java\t script:` 之类夹控制字符可绕过，浏览器解析 URL 时剥离 TAB/CR/LF 归一为 `javascript:`，最终经 `v-html` 渲染。
- 影响：有工具编辑权者提交恶意文档，受害者点击链接即执行 JS，可读 `localStorage` 令牌（见 P1-7）。
- 修复：改 `marked + DOMPurify`，或 `new URL()` 解析后仅放行 http/https/mailto/相对路径，先剥离 C0 控制字符再校验 scheme。
- 置信度：疑似（需编辑权限 + 点击）

### P1-7 令牌长期存 localStorage（无 httpOnly / 无 CSP 兜底）
- 位置：`frontend/src/utils/auth-storage.ts:1-2,12,24-32`；`frontend/src/stores/user.ts:26-27,67-68,191-194`
- 影响：任意 XSS 即可窃取 access+refresh（refresh 可长期续期，且后端无吊销）。
- 修复：access 仅内存，refresh 改 httpOnly+Secure+SameSite Cookie；加 CSP。

### P2（前端）
- **安全响应头缺失**（`frontend/nginx.conf` 无 CSP/X-Frame-Options/nosniff/HSTS/Referrer-Policy）。
- **前端依赖命中**：axios@1.13.2（GHSA 原型污染 gadget，升 ≥1.20）、vue-i18n@9.14.5（翻译 XSS，升 11.4.16）、lodash-es@4.17.22、vite@7.3.0（dev server 文件读取，升 ≥7.3.7；且 `server.host:'0.0.0.0'`）。多数 critical/high 来自 molstar→express 与构建链，不进浏览器运行时包。
- **管理端仅前端守卫**：篡改 localStorage `userInfo.role` 可进 /admin 界面，但后端 `get_admin_user` 拦截，无数据越权（纵深防御）。
- **错误 detail 原样弹窗**（`frontend/src/api/request.ts:176-177`）。
