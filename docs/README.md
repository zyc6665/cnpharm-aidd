# 中国医药 AI 药物研发平台 · 文档导航

**需求基线**：甲方确认版《AI 药物研发平台需求规格说明书》V3.0（`AIYF-SRS-001`，2026-11-09 定稿）——7 个功能域 / 44 条需求 / 206 条功能要求子项 / 4 个 ★ 关键指标专项（§5.1~§5.4）。此前我方据《技术规范书》第五章自拟的「37 条条款 / 62 个功能点」基线**已作废**，仅作为历史编号说明保留在 [`01`](01-需求/01-PRD产品需求文档.md) §6。

**部署形态**：甲方内网私有化离线部署，Kubernetes 承载前后端，算力为 2 台 8 卡海光 K100-AI DCU（共 16 卡 / 1024GB 显存）。

### 0.1 编号规则

编号是**一条全局序列，不代表所在目录**：看到 `17` 不代表它一定在 `docs/` 下某一类里，位置由「是否需要交付」与「属于哪一类」共同决定。

| 编号 | 位置 | 性质 |
|---|---|---|
| `00` `03` `04` `06` | `docs/02-架构/` | 交付文档：架构 |
| `01` `02` `03B` `26` | `docs/01-需求/` | 交付文档：需求 |
| `05` `07` `32` | `docs/03-接口/` | 交付文档：接口 |
| `08` `12` | `docs/04-测试/` | 交付文档：测试 |
| `09` `13` `19` `24` | `docs/05-部署/` | 交付文档：部署 |
| `14` `15` | `docs/06-运维/` | 交付文档：运维 |
| `16` `18` | `docs/07-验收/` | 交付文档：验收 |
| `10` `11` `20` | `docs/08-开发与工程/` | 交付文档：开发与工程 |
| `03A` `17` `21` `25` `27` `28` `29` `30` | `docs/internal/` | 内部工程记录，交付时可不提供 |
| `08A` `22` `23` | `docs/archive/` | 一次性记录或已弃用，**只读** |

正文里出现的 `docs/05`、`docs/13:123` 这类旧写法一律**按编号理解**，不是路径——编号到目录的对应以上表为准。

带字母后缀的（`03A`/`03B`/`08A`）是主件的补充件，不占新号。新文档取当前最大号 +1（现在是 `32`），**不复用已归档的号**。

## 10. 文档治理规则

改文档时按这几条走，否则链接检查和 CI 会拦你，或者半年后没人找得到。

| 规则 | 做法 |
|---|---|
| **放哪** | 交付文档按 §0.2 的八类放进 `docs/0N-xxx/` 对应目录（`docs/` 根只留 `README.md`）；内部记录放 `docs/internal/`；一次性记录（审计快照、环境清点、已弃用方案）放 `docs/archive/`。拿不准就先问域 owner，别往 `docs/` 根堆文件 |
| **编号** | 全局序列递增，取当前最大值 +1（现在是 `32`）；补充件用字母后缀（`03A`/`03B`）不占新号；**已归档的号不复用、文件不删**，只在文件头标「已弃用」并指向替代文档 |
| **命名** | `NN-中文标题.md`，不带空格；标题里确有英文/空格时才用 `%20` 转义（见 `24`、`28` 的链接写法） |
| **链接** | 相对路径 + 锚点，必须通过 `python scripts/check_doc_links.py`（CI 的「文档链接检查」作业）；引用别的 `docs` 文件用 `./NN-xxx.md`，引 `internal/` 用 `./internal/...` |
| **不放二进制** | 截图放 `docs/screenshots/`、附件放 `docs/evidence/`，**交付文档目录里不放压缩包与大文件**；与同名目录重复的压缩包不提交（曾经有 41.6 MB 的重复 zip，已清除） |
| **改完同步索引** | 新增/移动文档必须同时改本文件的 §0 计数、对应分节表格，以及 [`00`](02-架构/00-项目总览与研发流程总纲.md) §4 的份数——这两处是唯一被当作清单读的地方 |
| **谁负责** | 每个文档归属于一个业务域（D1–D8）或平台层（L1–L4），归属见 [`30`](./internal/30-团队协作与域划分.md) §4；改动跨域文档时按契约层处理——单独 PR、提前一天报 |
| **决策类要留痕** | 结论性文档（口径变更、方案取舍）在文件头记录版本与日期，正文只写最终口径，过程争议放 `03A` 修订记录 |

> 新加入项目的人：先读仓库根 `AGENTS.md`（环境、命令、边界、常见坑），再读 [`30`](./internal/30-团队协作与域划分.md)（谁负责什么），然后按 §7 的阅读顺序挑自己角色的文档。
