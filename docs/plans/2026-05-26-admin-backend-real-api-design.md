# 管理后台真实 API 收口设计

## 目标

将当前管理后台从“演示态页面”收口为“真实管理界面”：

- 删除系统状态、趋势图、假表单、假按钮等无后端支撑内容
- 将后台核心页面统一接入现有真实 API
- 仅在影响后台可用性时补充最小后端能力

## 范围

### 包含

- 管理仪表板改为真实概览页
- 用户管理页接入真实用户列表与编辑/删除接口
- 任务管理页接入真实任务列表、详情、取消、重试、删除接口
- 工具管理页完善真实筛选与分页行为
- 系统页改为只读信息/配置页

### 不包含

- 不新增管理员创建用户、重置密码等后端未提供能力
- 不保留系统状态、服务状态、趋势图等非必要运行态展示
- 不做后台页面大规模状态层重构

## 设计原则

1. 只展示真实能力，不保留纯前端模拟交互
2. 优先复用现有 API，不轻易扩展后端接口面
3. 缺少支撑的按钮直接删除，而不是保留假占位
4. 改动保持局部、可验证，避免把后台改造演化成重构

## 页面设计

### Dashboard

保留：

- 总用户数、今日新增用户：`GET /api/v1/users/admin/stats`
- 总工具数、总任务数、运行中任务数：`GET /api/v1/system/stats`
- 最近用户：`GET /api/v1/users/admin?page=1&page_size=5`
- 最近任务：`GET /api/v1/tasks?page=1&page_size=5`

删除：

- 任务趋势图
- 系统状态卡片
- CPU / 内存 / 磁盘进度条
- 服务状态列表

### Users

保留：

- 关键词搜索
- 角色筛选
- 状态筛选
- 分页
- 编辑用户（邮箱、手机号、角色、状态）
- 删除用户（后端实际为封禁）

接入：

- `GET /api/v1/users/admin`
- `GET /api/v1/users/admin/stats`
- `PATCH /api/v1/users/admin/{user_id}`
- `DELETE /api/v1/users/admin/{user_id}`

删除：

- 创建用户
- 重置密码
- 纯前端 ban / unban 假实现

### Tasks

保留：

- 状态统计卡片
- 状态筛选
- 工具筛选
- 分页
- 详情抽屉
- 取消 / 重试 / 删除

接入：

- `GET /api/v1/tasks`
- `GET /api/v1/tasks/{task_id}`
- `POST /api/v1/tasks/{task_id}/cancel`
- `POST /api/v1/tasks/{task_id}/retry`
- `DELETE /api/v1/tasks/{task_id}`

调整：

- 工具筛选下拉使用真实工具列表
- 列表统计先由当前已加载任务数据聚合，不增加新聚合接口
- 批量操作移除

### Tools

保留管理员工具管理页现有结构，但完善为真实查询页：

- 分类下拉继续走 `GET /api/v1/admin/tool-categories`
- 工具列表走 `GET /api/v1/tools`
- 创建 / 编辑 / 删除继续走现有真实工具接口
- 筛选参数优先透传给后端，不再仅依赖前端内存过滤

### System

改为只读系统信息页，展示：

- 系统信息：`GET /api/v1/system/info`
- 系统统计：`GET /api/v1/system/stats`
- 系统配置快照：`GET /api/v1/system/config`

删除：

- 基本设置保存
- 任务设置保存
- 存储连接测试
- 邮件测试
- 所有假表单与写操作按钮

## 后端最小补充

优先不改后端；若前端接入时出现明显缺口，只允许补最小能力：

- 任务列表 `GET /api/v1/tasks` 可选补充 `keyword` 查询支持
- 如工具列表管理员筛选存在明显缺口，再补工具列表对应的查询参数处理

除此之外，不新增专用后台聚合接口。

## 风险控制

- 先写表层测试锁定“后台不再依赖模拟功能”
- 删除假功能时保持页面结构稳定，避免导航大改
- 类型定义与后端响应对不齐时，只做最小兼容修正
- 所有页面改造后必须重新构建验证

## 验证标准

- 管理后台不再展示系统状态、趋势图、假保存配置表单
- 用户页、任务页、工具页均使用真实 API 数据
- 不存在“看起来可操作、实际上无后端支持”的后台按钮
- 相关前端表层测试通过
- 前端构建通过
