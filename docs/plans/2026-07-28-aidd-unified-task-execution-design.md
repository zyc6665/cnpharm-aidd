# AIDD 统一任务执行设计

## 目标

将 AIDD 从“平台工具任务 + API 进程内虚拟工具”的双轨执行模型，收敛到平台任务系统。
所有可执行步骤都通过 `Task`、`TaskInput`、`TaskOutput`、队列和任务状态机运行。

## 执行架构

- 为工具版本配置增加 `builtin` 执行类型，并由 `TaskExecutor` 分发到内置执行器。
- 内置执行器在 worker 或 direct runner 中执行格式转换、Vina 和数据库查询；不再从 AIDD API 请求路径调用 `run_builtin_tool`。
- 内置执行器的结果转换为平台任务输出，由现有任务日志、进度、取消与产物存储流程统一管理。
- AIDD 调度器对所有步骤只创建平台任务，并根据关联任务的终态提取语义输出。

## 能力可用性

- 当前仅保留已有真实执行路径的内置能力：SDF 转换、Vina 和已启用的数据库查询。
- ADMET、毒性、合成可及性、分子动力学和相互作用分析在接入真实服务前不对规划器暴露。
- 能力解析按单个工具执行：数据库能力记录、工具版本 `agent_capability`、静态能力三层回退；一个已登记能力不得隐藏其他工具。

## 可靠性与状态

- 调度前以原子条件更新领取 `pending` 步骤，确保后台协调循环与手动同步不会重复分发下游任务。
- 取消 AIDD Run 时逐一调用平台任务取消服务，随后将未执行步骤标记为取消。
- 计划持久化前验证工具可用性、能力输入契约、输入来源、上游语义产物和无环依赖。
- 历史列表使用真实数据库分页；详情接口保留完整计划与步骤。

## 兼容与迁移

- 旧的虚拟工具 slug 保持为静态能力标识，但调度时解析为平台中的 `builtin` 工具记录。
- 没有对应已发布 `builtin` 工具记录的能力不可规划，并返回明确配置错误。
- 保留 `AgentRun` 和 `AgentRunStep` 数据模型，避免破坏现有历史数据与前端契约。

## 验证

- 内置执行器通过平台任务输出产物。
- Agent 取消会取消关联任务。
- 两个并发协调者只会创建一个下游任务。
- 预检拒绝缺失输入、错误上游输出和不可用能力。
- 能力目录同时包含数据库登记和配置登记工具。
- 列表接口遵守页码、页大小和总数。
