# 工具执行器结构化编辑器设计

## 背景

工具创建页已经按执行器类型显示不同字段，但 API 请求头、Docker 环境变量、SSH 环境变量和 SSH 输出匹配仍要求管理员手写 JSON。Docker 命令与 Python 参数使用空格分隔字符串，无法保留包含空格的单个参数。Python 表单生成的 `config.args` 当前未被执行器消费。

## 目标

- 执行器常用 map/list 配置不再要求手写 JSON。
- 编辑旧工具时无损加载既有 object/array 契约。
- 提交时拒绝重复键，忽略完全空白行，保留单个参数内部空格。
- Python 脚本执行器真实消费表单保存的参数。
- 保持后端工具配置格式不变，避免数据迁移和 API 破坏。

## 方案

采用结构化单一数据源，不提供与结构化字段并存的原始 JSON 模式，避免双向同步漂移。

新增两个无业务依赖的编辑组件：

- `StructuredKeyValueEditor`：用于 API 请求头、Docker 环境变量和 SSH 环境变量；每行包含键、值和删除动作。
- `StructuredStringListEditor`：用于 Docker 命令 token、Python 参数和 SSH 输出 glob；每行代表一个完整字符串。

新增纯转换工具：

- object 与键值行双向转换；
- 重复键和空键校验；
- array/旧字符串配置归一化；
- 空白项过滤但不拆分数组项内部空格。

输入/输出 JSON Schema 和 Agent 默认参数继续使用 JSON 编辑器，因为它们是任意嵌套结构，不适合简单键值表；本任务不构建不完整的 Schema 设计器。

## 表单行为

- 切换执行器类型时保留各类型尚未提交的编辑值。
- 旧的 object/array 配置加载为结构化行。
- 旧的字符串 command/args 仅作为兼容输入按空白拆分；新保存配置始终为字符串数组。
- 重复键在提交前显示明确字段错误，不再使用笼统的“JSON 格式错误”。
- 空 map/list 不写入配置，保持现有紧凑 payload。

## Python 执行语义

Python 执行命令改为：

```text
python <script_path> <config.args...> --params-file <params.json> --output-dir <output>
```

参数继续通过 `subprocess.run` 的数组形式传递，不经过 shell。非字符串 `args` 在执行前明确拒绝，避免隐式转换掩盖错误配置。

## 视觉与可访问性

沿用现有后台的紧凑、工业化表单语言：不增加嵌套卡片，行编辑器使用稳定网格、编号、图标删除按钮和可见添加动作。移动端改为单列，按钮有 aria label，文本不会溢出父容器。

## 验证

- 纯工具测试覆盖 round-trip、重复键、空行、数组参数保真和旧字符串兼容。
- 页面源契约测试覆盖三个键值字段和三个列表字段均接入结构化组件。
- Python 执行器测试覆盖参数顺序、包含空格的参数和非法配置拒绝。
- 前端全量测试/构建与后端全量测试通过。
