# 工具示例一键运行设计

## 目标

为每个工具提供可查看、可一键套用的示例输入。用户在工具详情页点击“使用示例”后，平台自动填充示例参数并绑定示例文件；用户也可以预览示例文件内容后再运行。

## 背景

当前工具详情页根据 `ToolVersion.config.input_schema` 动态渲染参数表单，部分 `platform_tool.json` 已存在 `example_params`。任务提交时，前端会上传或绑定文件并生成 `params` 与 `file_ids`。因此示例功能优先复用当前工具配置，不新增独立示例表，降低迁移成本。

## 推荐方案

复用 `ToolVersion.config` 中的示例定义，并新增后端示例接口：

- 兼容现有 `example_params`。
- 支持新增规范化 `examples` 数组，便于后续扩展多个示例。
- 示例文件路径相对导入配置所在目录或显式 `example_base_dir`。
- 后端负责路径校验、文件预览和把示例文件注册为当前用户可用文件。
- 前端负责展示“使用示例”按钮、示例文件列表和预览弹窗。

## 示例配置

现有格式继续可用：

```json
"example_params": {
  "n_samples": 5,
  "seed": 42,
  "device": "cpu"
}
```

推荐新格式：

```json
"examples": [
  {
    "name": "默认示例",
    "description": "使用内置 PDB 文件运行默认参数",
    "params": {
      "model_choice": "auto",
      "device": "auto"
    },
    "input_files": {
      "protein_pdb": "input/protein.pdb"
    }
  }
]
```

## 后端接口

`GET /api/v1/tools/{tool_id}/example`

返回默认示例元数据，包括参数、输入文件字段、文件名、大小、是否可预览。

`POST /api/v1/tools/{tool_id}/example/apply`

需要登录。把示例文件复制/注册为当前用户文件，返回字段到文件记录的映射，供前端直接绑定表单。

`GET /api/v1/tools/{tool_id}/example/files/{field}/preview`

读取配置中声明的示例文件。只允许访问工具示例目录下的文件，拦截 `..` 等路径穿越。文本类文件返回截断预览，二进制文件返回不可预览提示。

## 前端交互

在工具详情页参数表单上方展示示例区域：

- 有示例时显示“使用示例”按钮。
- 展示示例文件列表，文件支持预览。
- 点击“使用示例”后填充普通参数，并把后端返回的文件记录绑定到对应文件字段。
- 未登录用户可以查看示例；点击使用示例时提示登录。

## 错误处理

- 工具无示例：隐藏示例区域。
- 示例文件缺失：展示不可用状态，不阻塞非文件参数填充。
- 示例文件过大：只预览前一段内容。
- 路径越界：后端返回校验错误。

## 原则应用

- KISS：不新增示例表，先复用工具版本配置。
- YAGNI：只实现默认示例，不做复杂示例管理后台。
- DRY：示例参数与文件路径跟随工具配置，不在前端重复维护。
- SOLID：后端新增独立示例解析/文件服务函数，避免污染任务执行逻辑。
