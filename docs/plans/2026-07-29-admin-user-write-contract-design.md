# 管理员用户写接口统一响应设计

## 问题

管理员用户列表和统计接口返回平台标准响应，但创建、更新、重置密码和删除返回裸对象。前端 API 将这些写接口声明为 `ApiResponse<T>`，因此 TypeScript 契约与运行时值不一致；当前页面只因未读取响应实体而暂未暴露错误。

## 决策

- 四类管理员写接口统一返回 `success_response(data=...)`。
- 创建接口保留 HTTP 201；更新接口返回序列化后的用户实体；重置和删除返回消息对象。
- 路由 `response_model` 改为 `dict`，与其他平台 API 的标准包装一致。
- 不在 Axios 层猜测或自动包装裸响应，避免掩盖其他后端契约错误。
- 前端 API 类型保持不变，因为其声明本来就是目标契约。

## 验证

- API 测试覆盖四类写操作均包含 `code`、`message` 和 `data`。
- 既有权限、邮箱唯一性、自删除保护和级联删除测试继续通过。
- 前端用户管理源契约与生产构建继续通过。
