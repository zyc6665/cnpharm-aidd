# 工作台内联结果展示设计

## 目标

把任务结果从独立详情页回收进工具工作台，让用户在 `/workflow` 内完成完整闭环：

- 选工具
- 填参数
- 运行任务
- 直接在当前页查看结果

本次目标不是复制任务详情页，而是在工作台中栏表单下方新增一个 `轻量结果面板`，让结果可视化、输出数据、输出文件和关键日志都能在原地查看，同时保留“查看完整任务详情”的次入口。

## 背景

当前工作台已经具备：

- 分组驱动的工具工作台
- 中栏运行工具与任务状态摘要
- 右栏“我的产物”四级层级浏览
- 任务详情页成熟的结果展示能力

但用户从工作台运行任务后，仍然需要额外点击进入 [frontend/src/views/tasks/Detail.vue](/data/zhouyc/cpumodel_sciminer/frontend/src/views/tasks/Detail.vue) 才能看到：

- 结果可视化
- 输出数据
- 输出文件
- 关键日志

这会让“工作台”只负责提交任务，却不负责消费结果，流程体验明显割裂。

## 核心设计决策

### 1. 结果区放在中栏表单下方

结果区放在 [frontend/src/components/workflow/WorkflowRunPanel.vue](/data/zhouyc/cpumodel_sciminer/frontend/src/components/workflow/WorkflowRunPanel.vue) 的运行按钮下方，而不是顶部或右栏。

原因：

- 与“当前所选工具”的上下文最连贯
- 运行完成后，结果自然出现在提交区域之后
- 不会把右栏“我的产物”变成第二个结果详情页

这使中栏从“实验参数台”自然延伸成“参数台 + 结果台”。

### 2. 采用轻量结果面板，而不是整页复刻任务详情

工作台内联结果区不复刻整页详情，而是展示最常用结果能力：

- 状态
- 进度
- 结果可视化
- 输出数据
- 输出文件
- 最近日志

保留 `查看完整任务详情` 按钮，作为需要完整排障、时间轴、删除/重试等行为时的次入口。

这样既能消除跳页割裂，又不把工作台中栏撑成另一个完整详情页。

### 3. 复用任务详情页已有结果能力

本次不重新发明结果展示系统，优先复用已有能力：

- 继续复用 [ResultVisualizationPanel.vue](/data/zhouyc/cpumodel_sciminer/frontend/src/components/tasks/ResultVisualizationPanel.vue)
- 将任务详情页中成熟的“输出摘要”和“日志预览”抽成共享块

这符合：

- `DRY`：结果可视化和输出展示不维护两份
- `KISS`：只组合已有能力，不重写任务详情页逻辑
- `YAGNI`：不在工作台复制所有时间轴、面包屑、删除/重试等详情页行为

### 4. 结果上下文默认跟随当前工具，但允许右栏切换

工作台结果区默认显示：

- 当前中栏所选工具的最近任务结果

当用户在右栏“我的产物”里点击某个任务或某个产物时：

- 如果属于当前工具：直接切换结果区到该任务
- 如果属于其他工具：先同步切换分组与工具，再切换结果区到对应任务

这样右栏不只是浏览来源，还能充当“历史结果切换器”。

## 结果区内容设计

### 1. 运行中

显示：

- 状态标签
- 进度条
- 运行时长
- 最近几条日志

目的：

- 用户不需要跳页也能判断任务是否卡住、是否仍在推进

### 2. 成功

显示：

- 结果可视化（复用 `ResultVisualizationPanel`）
- 输出数据摘要
- 输出文件列表与下载
- 最近日志

目的：

- 满足工作台内完成“运行并消费结果”的主路径

### 3. 失败

显示：

- 错误信息
- 最近错误日志
- `查看完整任务详情`

目的：

- 在工作台内给出足够的第一层排障信息

### 4. 空状态

当当前工具还没有任务或当前结果任务为空时，显示：

- 结果会在运行后出现在这里的说明
- 若有需要，可附加最近一次历史任务入口

## 组件拆分

建议新增以下共享组件：

### 1. WorkflowTaskResultPanel

工作台专用结果容器，负责：

- 根据 `taskId` 或 `task` 加载完整详情
- 管理 loading / error / empty 状态
- 组合可视化、输出摘要、日志预览

### 2. TaskOutputSummary

从任务详情页抽离：

- 输出数据展示
- 输出文件列表
- 下载操作

### 3. TaskLogPreview

从任务详情页抽离：

- 最近日志预览
- 日志级别标记
- 可选“查看更多日志”入口

### 4. ResultVisualizationPanel

保持现有组件不变，直接复用。

## 状态流转

### 页面级协调

在 [frontend/src/views/workflow/index.vue](/data/zhouyc/cpumodel_sciminer/frontend/src/views/workflow/index.vue) 增加一个轻量结果上下文，例如：

- `activeResultTaskId`

默认来源：

- 当前工具最近任务

变更来源：

- 中栏运行成功后切到新任务
- 右栏点击任务或产物时切到对应任务
- 切换工具时，如果当前结果任务不属于该工具，则回退到该工具最近任务

### 数据获取

结果面板不依赖工作台摘要任务数据直接渲染，而是：

1. 先读取 `workflowStore.taskByTool`
2. 若信息不完整，调用 `getTaskDetail(taskId)`
3. 内部自行处理日志拉取与刷新

这样可以避免把详情加载逻辑混进运行表单本体。

## 与现有任务详情页的关系

工作台结果区与任务详情页关系如下：

- 工作台：轻量消费视图
- 任务详情页：完整诊断视图

任务详情页仍保留：

- 时间轴
- 工具信息
- 相关任务
- 完整日志视图
- 删除 / 重试 / 取消等完整操作

工作台只负责最常用的“运行后看结果”主路径。

## 测试策略

### 1. 前端表面测试

新增或扩展断言覆盖：

- 工作台中栏出现 `WorkflowTaskResultPanel`
- 工作台保留“查看完整任务详情”入口
- 成功状态下继续引用 `ResultVisualizationPanel`

### 2. 组件行为测试

覆盖结果面板在以下状态下的渲染行为：

- `pending`
- `running`
- `success`
- `failure`

以及：

- 右栏点击任务后，中栏结果上下文会切换

### 3. 回归验证

至少验证：

- 工作台产物层级联动测试继续通过
- 任务详情页现有结果展示不回归
- 前端构建通过

## 非目标

本次不做：

- 后端任务接口结构改造
- 工作台完整复刻任务详情页
- 新的任务对比、批量结果浏览、结果固定标签页
- 日志实时流的全量重构
- 全站 UI 大改版
