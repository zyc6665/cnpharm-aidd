## 1. 使用说明

### 1.1 按角色读

| 角色 | 建议顺序 | 可跳过 |
|---|---|---|
| 药物研发科学家 RES | §2 → §5 → §6 → §7 → §11 → §12 | §13、§14 |
| 计算化学家 CADD | §2 → §5.3 → §8 → §10 → §11 → §13 | §14 |
| 项目负责人 PL | §2 → §3 → §12 → §11.3 → §13.3（配额） | §8、§14 |
| 系统管理员 ADMIN | §3.2 → §14 → §13 → §15 | §5~§8 |

### 1.2 排版约定

| 记号 | 含义 |
|---|---|
| **★** | 对应技术规范书关键条款，验收必演示。操作路径不要改 |
| `代码字体` | 页面上的按钮名、字段名、文件名、状态值 |
| ⚠ | 有后果的操作，做之前先读 |
| 🔴 | 不可逆或影响他人，需二次确认 |
| `S/M/L/XL/T` | 任务规模层，平台自动判定，用户不需要选（`03` §5.2.2） |
| 路径 `/xxx` | 页面路由，可直接粘到地址栏 |

### 1.3 四个必须先知道的规则

1. **所有计算都是异步的。** 点「提交」只代表**进入队列**，不代表开始跑。离开页面不影响任务（`06` §6.2）。
2. **规模层是平台判定的，不是用户选的。** 你提交 10 万条配体，系统自动判为 `XL` 并弹出预估单——这是设计，不是故障。
3. **阶段（S0~S6）是自动推导的，不是待办清单。** 它只告诉你「走到哪了」，不阻止你做任何事，也允许回退（`03` §3.6.1）。
4. **决策记录一旦写入不可修改、不可删除。** 写错了只能再写一条新的说明（`04` §9.5）。

## 2. 十五分钟快速上手（最小闭环）

> 目的：用最短路径跑通「靶点 → 结构 → 口袋 → 生成 → 预测 → 决策」六个动作，建立全局印象。真实项目请按 §5 起逐章操作。

### 2.1 前置条件

- 已有账号，且被加入某个项目（没有项目找负责人 PL 或管理员）
- 手上有 1 条蛋白序列（FASTA 或纯序列文本，长度 ≤ 1500 aa）

### 2.2 六个动作

| 步 | 动作 | 页面 | 大约耗时 |
|---|---|---|---|
| 1 | 新建项目 | P-03 项目列表 → `新建` | 30 秒 |
| 2 | 建靶点、贴序列 | P-06 靶点列表 → `新建靶点` | 1 分钟 |
| 3 | 跑结构预测 ★ | P-08 → 选 `Boltz-2` → 提交 | 2~3 分钟（S 层，走交互卡） |
| 4 | 看结构、选口袋 ★ | P-09 结构详情 → P-10 口袋列表 → `选定` | 2 分钟 |
| 5 | 生成分子 ★ | P-15 分子生成 → 选口袋 → 生成 200 个 | 1~2 分钟 |
| 6 | 存集合 + 写决策 | P-17 生成结果 → `保存至候选集合` → P-39 决策记录 | 2 分钟 |

### 2.3 走完之后你应该看到

- 项目总览（P-04）顶部研发主线从 `●S0` 推进到 **`●S3 候选生成`**
- 「下一步」提示变成「已有候选集合，尚未做性质评估」
- 决策记录页（P-39）出现 1 条 `DP3` 记录

> 如果第 3 步卡在「排队中」超过 5 分钟，看 §13.2；如果结构预测失败，看 §15.2。

## 3. 项目与成员（M1）

### 3.1 新建项目（P-03）

**目标**：建立独立研发空间，后续所有数据、任务、结果都归属该项目。

**前置**：已登录。

**步骤**：

1. 顶部导航 `工作台` → 左侧 `项目` → 右上 `新建项目`
2. 填写：

| 字段 | 必填 | 说明 |
|---|---|---|
| 项目名称 | ✅ | 建议「靶点名 + 方向」，如 `KRAS G12C 抑制剂研发`；同项目内可重名，但不利于检索 |
| 描述 | — | 一句话写清目标，会显示在项目卡片上 |
| 关联靶点 | — | 可留空，后续在 P-06 补 |
| 可见范围 | ✅ | 默认「仅成员可见」；不要随便选「全员可见」 |

3. `创建` → 自动跳转项目总览（P-04）

**结果**：项目状态 `ACTIVE`，你成为**负责人**（PL），研发阶段为 `S0 立项与数据归集`。

**注意**：
- ⚠ 项目**归档后全员只读**，取消归档需要负责人操作。归档前先导出需要的数据。
- 一个项目建议只对应一个靶点方向。多靶点混在一个项目里，后面的决策记录会很难读。

### 3.2 成员与角色（P-05）

| 角色 | 能做什么 | 不能做什么 |
|---|---|---|
| **负责人 PL** | 全部操作 + 改成员 + 归档 + 分配配额 | — |
| **成员 MEMBER** | 提交任务、写决策、导入导出 | 改成员、归档、改配额 |
| **只读 VIEWER** | 查看、下载已有结果 | **所有写操作按钮直接隐藏**（`06` §8），写决策返回 `40302` |

**步骤**：P-04 → `成员` → `添加成员` → 选用户 + 选角色 → 确定。

**注意**：
- 只读成员看不到「新建」「提交」按钮，**不是权限 bug**，是设计（隐藏优于点击后报错）。
- 移除成员后，他提交的历史任务与决策记录**仍然保留**（审计需要），只是不能再访问。

### 3.3 项目总览（P-04）

一屏看四件事：

| 区块 | 看什么 |
|---|---|
| **研发主线**（顶部） | `●S0─●S1─●S2─○S3…` 实心=已到达，空心=未到达。可点击跳转，未到达的置灰可悬停看条件 |
| 统计卡 | 靶点 / 候选物 / 任务 / 结果 / 当前算力占用 |
| 进行中任务 | 进度条 + 剩余时间；点进去是 P-32 |
| 最近决策 | 最近 1 条，点 `查看全部` 进 P-39 |

> 阶段**回退是正常现象**。新增一个靶点后可能从 `S3` 退回 `S2`，顶部提示「已回到 S2，因为新增了靶点」，这是提示不是报错（`03` §3.6.1）。

## 4. 数据导入与资产（M1）

### 4.1 支持的文件格式

| 类型 | 格式 | 单文件上限 | 说明 |
|---|---|---|---|
| 分子结构 | `.sdf` / `.smi` / `.mol2` / `.mol` | 500 MB | `.sdf` 支持多分子；`.smi` 需 `SMILES [name]` 两列 |
| 蛋白序列 | `.fasta` / `.fa` / 纯文本 | 10 MB | 单条或多条 |
| 蛋白结构 | `.pdb` / `.cif` / `.mmcif` | 500 MB | `.cif` 优先，`.pdb` 兼容性最好 |
| 表格 | `.csv` / `.xlsx` | 100 MB | 需含 `smiles` 或 `compound_id` 列 |
| 压缩包 | `.zip` | 2 GB | 仅支持上述格式打包，不接受嵌套压缩 |

> ⚠ 不支持 `.docx`、`.pdf`、`.rar`、`.7z`。格式错误会直接拒绝，不会静默丢弃。

### 4.2 批量导入（P-14）

**步骤**：

1. P-12 数据资产 → `批量导入`（或直接 `/projects/:id/import`）
2. 拖入文件 → 平台自动识别类型
3. **字段映射**（表格文件才有）：把源列名映射到平台字段

| 平台字段 | 必填 | 说明 |
|---|---|---|
| `smiles` | ✅（二选一） | 分子结构 |
| `compound_id` | ✅（二选一） | 已有化合物的外部编号 |
| `name` | — | 显示名 |
| `mw` / `logp` / `tpsa` | — | 不填则由 RDKit 计算 |

4. `保存映射为模板`（同名模板下次自动套用）
5. `开始导入` → 转异步，返回任务卡片

**结果**：导入任务进 P-31 任务中心；完成后站内通知。

**失败处理**：导入**不会因为部分行失败而整体回滚**。完成后弹出报告：

```
导入完成：成功 1,842 条 / 失败 4 条
失败明细（可下载 errors.csv）：
  第 128 行  SMILES 无法解析：C1CC1(C
  第 431 行  分子量为 0，疑似空结构
```

> ⚠ 若失败率 > 50%，平台判定为「导入数据全部失败」（`42203`），整个批次作废，需修正文件后重传。

### 4.3 数据版本（P-13）

同一化合物被重新导入时**不覆盖**，而是生成新版本：

- 化合物详情页 → `版本历史` → 可看每版的来源、时间、字段差异
- 计算任务永远引用**提交时刻**的版本（快照在 `task_input_snapshot`），后续改数据不影响已跑结果

> 这是追溯的基础：半年后复算某个结果，用的是当时的输入，不是现在的。

## 5. 靶点与结构分析（M2）★★

### 5.1 建靶点（P-06 / P-07）

**步骤**：P-06 → `新建靶点` → 填名称（如 `KRAS G12C`）、基因名、物种、序列 → 保存。

**结果**：靶点详情页（P-07）出现「结构列表」（此时为空）与「操作入口」。

### 5.2 结构预测 ★（P-08）

> 对应 `DRP-M2-FR-02`，验收必演示。

**前置**：靶点下有序列，长度 ≤ 1500 aa。

**步骤**：

1. P-07 → `预测结构`（或 `/proteins/:id/predict`）
2. 选择模型：**`Boltz-2`**（当前唯一已验证的结构预测模型）

| 参数 | 默认 | 说明 |
|---|---|---|
| `useMsa` | `false` | **默认关闭**。开启需本地 MSA 服务，未启用时会自动回落 empty MSA（`03` §7.4.3） |
| `numRecycles` | `3` | 越大越慢，一般 3 足够 |

3. `提交`

**结果**：任务进队列（`S` 交互层，走预留交互卡，通常 2~3 分钟）；完成后结构自动挂到靶点下，状态 `PREDICTED`。

**注意**：
- ⚠ **结构预测结果受 MSA 策略影响**。用 empty MSA 跑出来的结构和带 MSA 的不完全一致，这是已知且已记录在案的（`03` §7.4.3）。同一个项目内请保持同一策略，否则结果不可比。
- 序列超长会返回 `42201`，提示「序列长度 2140 aa，超出当前模型上限 1500 aa」，建议分段。

### 5.3 结构准备（P-09）

**为什么必须做**：对接（Vina）和 MD（GROMACS）要求去水、加氢、加电荷、补缺失残基。**没做结构准备的受体不能提交对接**，会返回 `422xx` 并给一键跳转。

**步骤**：P-09 → `结构准备` → 选参数（pH、是否保留辅因子、是否补残基）→ 提交 → 生成 `PDB` 与 `PDBQT` 两个产物。

**结果**：结构状态从 `PREDICTED` / `IMPORTED` 变为 `PREPARED`，文件列表新增 `*_prepared.pdb` 与 `*_prepared.pdbqt`。

### 5.4 口袋预测与选定 ★★（P-10 / P-11）

> 对应 `DRP-M2-FR-06` / `FR-07`，验收必演示。

**步骤**：

1. P-09 → 右侧「口袋」区 → `预测口袋`（模型 **`LVpocket`**，约 25 秒）
2. P-10 口袋列表：按 `score` 降序，每行有 `score`、体积、残基数、`3D 叠加` 开关
3. 点击某口袋 → 右侧 3D 视图高亮；点 `关键残基` 进 P-11 看残基表与空间定位
4. 选定：点行尾 `★ 选定`

**结果**：该口袋标记 `selected`；结构状态推进为 `POCKET_SELECTED`；项目研发阶段进入 **`S2 结构与口袋就绪`**。

**注意**：
- ⚠ **一个结构同时只能有 1 个选定口袋**。切换会覆盖旧选择，但**不删除**旧口袋数据。
- 口袋选定是 `DP2` 决策点的核心动作，建议顺手在 P-39 记一条决策（§12.3），写明为什么选这个（score？残基组成？文献支持？）。

### 5.5 三维可视化（P-09）

| 操作 | 说明 |
|---|---|
| 显示模式 | `卡通`（默认）/ `表面` / `棒状` |
| 着色 | `链` / `pLDDT`（蓝高→红低）/ `疏水性` |
| 叠加 | 可勾选多个口袋或配体同时显示 |
| 逐残基置信度条 | 底部色条，点击定位到该残基 |
| 截图 | 导出 PNG，可直接贴进报告 |

> 性能：>5000 残基自动降级为卡通简化；轨迹播放按帧抽稀（`06` §5.2）。

### 5.6 导出（P-09）

`导出` → 可选：结构文件（PDB/CIF）、口袋定义（含残基列表）、结构准备产物（PDBQT）、分析报告（PDF）。

## 6. 分子与多肽设计（M3）★

### 6.1 小分子生成 ★（P-15）

> 对应 `DRP-M3-FR-01`，验收必演示。

**前置**：已有 `POCKET_SELECTED` 状态的结构。

**步骤**：

1. P-15（`/design/molecules`）
2. 选择靶点 → 结构 → **口袋**（必选，未选会提示「请先选定口袋」）
3. 选择模型：**`STD-Diff`**（扩散，主力）或 **`Pocket2Mol`**（口袋条件）
4. 参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| 生成数量 | 200 | 建议 200~1000；>1000 自动升为 `M` 层，耗时明显增加 |
| 步数 steps | 1000 | 越小越快、质量越差 |
| 随机种子 seed | 自动 | **填固定值可复现**（见 §6.4） |

5. `提交` → 生成任务

**结果**：P-17 生成结果页；顶部显示 `生成 200 / 重复 9 / 非法 13 / 有效 187`。

**注意**：
- ⚠ **「生成数量」≠「有效分子数」**。去重与合法性过滤后通常剩 80~95%，这是正常损耗。
- 大批量（>1000）会被判为 `M` 或 `L` 层，可能要等到夜间（`03` §5.2.2）。

### 6.2 多肽设计 ★（P-16）

**前置**：靶点有序列。

**步骤**：P-16 → 选靶点 → 设长度范围（如 8~15 aa）→ 设设计条件（结合位点、电荷、疏水性）→ 选模型 **`TheraPainter`** → 提交。

**结果**：候选序列列表，每条带序列、长度、模型评分、PEARL 预测的性质。

> ⚠ **`TheraPainter` 当前为「部分通过」**（`03` §6.2.1）：环境与依赖已验证，但**完整 evolve smoke 产物待补测**（AR-03）。上线初期建议先用小批量（≤20 条）验证，再放量。

### 6.3 生成结果筛选与保存（P-17）

| 操作 | 说明 |
|---|---|
| 筛选 | 评分 ≥、分子量区间、logP 区间、QED ≥、子结构（SMARTS） |
| 排序 | 点列头；默认按模型评分降序 |
| 多选 | 卡片左上勾选框；支持 `全选本页`、跨页保持已选 |
| `保存至候选集合` | 必选目标集合（可新建）；保存的是**当前快照**（含评分） |
| `比较选中` | ≤6 个，跳 P-20 |
| `导出` | SDF + 属性表（CSV） |

**结果**：候选物落库为 `candidate`，加入 `candidate_set`；项目阶段推进到 **`S3 候选生成`**。

### 6.4 复现一次生成（重要）

扩散模型**不保证**同种子完全一致（GPU 浮点非确定性，`03` §7.4.3）。复现口径：

| 判据 | 要求 |
|---|---|
| 产物 SHA-256 完全一致 | **不要求**（D3 统计等价） |
| 数量、有效分子率 | 偏差 ≤ 5% |
| MW / logP 均值 | 偏差 ≤ 10% |

> 所以「复现」的意思是**统计等价**，不是「逐字节相同」。要跑复现请用 P-32 的 `重试`（沿用原参数与原种子），别手动重新填参数。

### 6.5 候选物详情与比较（P-19 / P-20）

- **P-19**：2D 结构 + 属性表 + 已有预测/计算结果（按时间倒序）+ 版本历史
- **P-20**：≤6 个并排，差异行高亮，可导出对比表

## 7. 亲和力与 ADMET 性质预测（M4）★

### 7.1 单个 vs 批量（P-21）

| 模式 | 入口 | 适用 | 规模层 |
|---|---|---|---|
| 单个 | P-19 候选物详情 → `预测` | 试算、看单条指标 | `S` |
| 批量 | P-21（`/predict`）→ 选候选集合 | 常规评估 | `M`/`L` |

**步骤（批量）**：

1. P-21 → `批量` → 选候选集合（显示「共 N 个候选物」）
2. 勾选指标组：

| 指标组 | 模型 | 输出 |
|---|---|---|
| ADMET | **`MolP-PC`** | 56 列（吸收/分布/代谢/毒性） |
| 亲和力 | **`MSIGN`** | `predicted_affinity`（如 -11.0999） |
| 多肽性质 | **`PEARL (GAT)`** | 多肽专用性质 |

3. `提交`

**结果**：P-22 预测结果页，指标矩阵（行=候选物，列=指标），支持筛选、排序、分布图。

**注意**：
- ⚠ **亲和力预测（MSIGN）需要候选物 + 受体结构配对**。只选候选集合不选受体，会提示「缺少目标蛋白」。
- 批量预测规范书上限为 **500 条**（`L` 层）。超过 500 会提示分批或升为 `XL`。

### 7.2 结果解读纪律

- 不同模型输出的指标**量纲不同**，不要跨模型直接比大小。
- 亲和力预测值（MSIGN）与对接评分（Vina）**不是一回事**：前者是学习式预测，后者是物理打分。二者只能各自纵向比，不能横向换算。
- 任何指标都必须连同「模型名 + 版本」一起看（P-22 列头有悬浮提示，P-34 有完整记录）。

## 8. 虚拟筛选与计算评估（M5）★

### 8.1 虚拟筛选漏斗 ★（P-23）

> 对应 `DRP-M5-FR-04`，验收必演示。

**前置**：受体已 `PREPARED`（有 PDBQT），候选集合非空。

**步骤**：

1. P-23（`/screen`）
2. 选受体 + 候选集合（顶部显示「共 N 个配体」）
3. 配置漏斗（自上而下逐级收窄）：

| 级 | 可选 | 说明 |
|---|---|---|
| 1 构象生成 | RDKit ETKDG | 0.5~2 秒/分子 |
| 2 药效团筛选 | 可选 | 按口袋残基自动推荐药效团 |
| 3 对接 | **AutoDock Vina** | `exhaustiveness` 默认 8；10~60 秒/配体 |
| 4 重打分 | 可选 | 对 Top-N 用更贵的打分 |

4. `提交` → 若规模 ≥ 1 万，弹出 **XL 算力预估单**（§8.2）

**结果**：P-24 筛选结果页，按对接评分升序（越负越好），可下钻姿势、导出。

**注意**：
- ⚠ **Vina 是 CPU 任务，不吃 DCU**。10 万条 = 278~1667 CPU·h，按平台实际 **128 核**算约 **3.1~18.5 小时（典型 9.3 小时）**，是**天级**不是小时级（`03` §5.6.2）。
- ⚠ **一定要开漏斗前置**。不加药效团/ADMET 粗筛直接跑 10 万条，等于把算力全烧在注定被淘汰的分子上。

### 8.2 XL 层算力预估单

提交 ≥ 1 万条时**必然弹出**，必须显式确认才入队（`03` §5.2.2 硬性规则）：

```
┌───────────────────────────────────────────────────────────┐
│ 算力预估单 · 大批量虚拟筛选                      [取消]    │
├───────────────────────────────────────────────────────────┤
│ 本次提交 100,000 个配体，已自动归入 XL 层（超大批量）。    │
│ 预估耗时：约 3.1~18.5 小时，典型 9.3 小时（按 90 有效核）  │
│ 预估完成：最快 2026-10-24 03:00，最晚 2026-10-24 18:30     │
│ 资源占用：CPU 计算池 112/128 核，期间 S/M 层预留 16 核     │
│ ⚠ 建议先启用漏斗前置（药效团 + ADMET 粗筛），可减少约 90%  │
│   [✓] 先跑漏斗粗筛（推荐，勾选后约 35~110 分钟）           │
│ 本任务将核销约 833 算力·小时（项目剩余 2,400 算力·小时）   │
│                                    [我再想想] [确认提交]   │
└───────────────────────────────────────────────────────────┘
```

**三条必须理解的事**：
1. 预估值是**区间不是单值**。给单值就是给承诺，而模型冷启、卡位争抢、分片重跑都会拉长。
2. 「先跑漏斗粗筛」**默认勾选**。取消勾选后预估会显著变大，请确认你真的需要全量。
3. 这个数会**事后核对**。实际耗时与预估偏差 > 3 倍会触发运维告警（`14` AL-22），用来持续修正估算模型。

### 8.3 MD 模拟（P-26）

**前置**：已有蛋白-配体复合物（对接结果可直接用）。

**参数**：

| 参数 | 默认 | 说明 |
|---|---|---|
| 力场 | AMBER99SB-ILDN | 水模型 TIP3P |
| 时长 | 10 ns | ≥50 ns 判为 `T` 长时层 |
| 温压 | 300 K / 1 bar | |
| 步数 | 500000 ≈ 1 ns | 引擎 **GROMACS 2026.3 (OpenCL)** |

**结果**：P-27 轨迹播放器 + RMSD/RMSF 曲线；轨迹文件 `XTC` 可下载。

**注意**：
- ⚠ MD 是 `T` 长时层，**不占普通并发配额，但可能等更久**（专用队列）。
- ⚠ **MD 支持断点续算**。机器重启后会自动从最近检查点续跑，不需要你重新提交。
- ⚠ MD 结果属 **D3 统计等价**：同一输入重复跑，RMSD 均值/方差接近，但轨迹**不会逐帧相同**。比较时看统计量，别比单个坐标。

### 8.4 自由能评估（P-28）

**前置**：已有 MD 结果。

**结果**：ΔG 值 + 能量分解（范德华/静电/溶剂化/熵）。

> ⚠ 当前自由能走 **CPU 路径**（`gmx_MMPBSA`）。OpenMM 的 DCU 插件不可用（`03` §6.2.2），因此 GPU 加速路径不提供。

### 8.5 对接结果与复合物可视化（P-25）

- 3D 复合物视图（蛋白 + 配体姿势）
- 相互作用列表（氢键、疏水、盐桥，按距离判定）
- 评分：`affinity`（kcal/mol，越负越好）、`rmsd_lb` / `rmsd_ub`

### 9.1 预置模板（P-29）

平台内置 5 个模板（`03` §5.4）：

| 模板 | 节点 | 用途 |
|---|---|---|
| `wf-target-to-candidate` | 7 | 靶点 → 结构 → 口袋 → 生成 → 存集合（**最常用**） |

| `wf-md-evaluation` | — | 对接 → MD → 自由能 |

**步骤**：P-29 → 点模板卡 → 右侧 DAG 预览 → `启动` → 填参数（缺什么填什么，平台会校验前置）→ 提交。

### 9.2 工作流实例（P-30）

- DAG 状态图：每节点颜色 = 状态（灰未开始 / 蓝运行 / 绿成功 / 红失败）
- 节点列表：点节点跳到对应任务详情（P-32）
- `取消`：终止整个实例（正在跑的节点会被优雅终止，保留部分产物）
- `重试失败节点`：只重跑失败的那几个，已成功的不会重跑

**注意**：
- ⚠ 节点失败策略是 `ABORT`（默认，后续节点全部中止）或 `CONTINUE`（继续跑不依赖它的节点）。模板里已经定好，**不要为了"让它跑完"去改成 CONTINUE**，那只会产出一堆半成品。
- 工作流**不会自动重试**。失败了看日志、修参数、再手动重试。

### 9.3 自定义编排（P-40，P1）

**一期能做**（P-40 编排画布的受限形态）：
`工作流模板`（P-29）→ 选一个预置模板 → 点「**基于此模板新建**」→ 在 P-40 画布中**查看 DAG 结构与每个节点的参数** → 改节点参数（如让 `STRUCTURE_PREDICTION` 节点换用 `numRecycles=5`）→ `另存为项目模板`（`is_preset=false`）→ 回到 P-29 用新模板启动。

**一期不能做**：新增/删除节点、自由连线、条件分支。

**二期**（`D-16-01` 待产品确认）：完整画布，支持节点增删、依赖连线、并行分支与失败策略逐节点配置。

> 自定义编排为 P1 优先级。文档侧结论已写入 `06` §3 的 P-40 说明：**一期开放「复制模板 → 调参数 → 另存」，二期开放完整画布**。这样 `01` M6-FR-02 的诉求有明确落点，一期排期不被画布开发阻塞。若产品决定一期即上完整画布，本节的「一期不能做」需删除。

**注意**：自定义模板同样受 `03` §3.2.2 事务边界约束——节点拆分出来的任务仍走同一套调度与配额核销，**不会因为「自定义」而绕过规模层判定**。

### 11.3 追溯包（重点）

一个 `.zip`，解开是：

```
traceability.json      # 六要素：输入 / 模型 / 工具 / 参数 / 环境 / 产物
inputs/                # 全部输入文件的副本
outputs/               # 产物与 SHA-256 清单
env.json               # 镜像 tag、DTK 版本、权重 SHA-256、execution_flags
```

**`traceability.json` 六要素**（`03` §7.1）：

| 要素 | 示例 |
|---|---|
| 输入 | 受体 `complex_prepared.pdbqt` SHA-256、配体集合 `cset_01J...` v3 |
| 模型 | `boltz-2` v2.0.1，权重 SHA-256 `9f3a...` |
| 工具 | `AutoDock Vina` 1.2.5 |
| 参数 | `exhaustiveness=8, seed=42` |
| 环境 | 镜像 `harbor.drp.local/drp/compute-vina:1.2.5-py3.10`，DTK 26.04 |
| 产物 | `out/poses.sdf` SHA-256 `ab12...` |

> **这就是「可追溯」的全部含义**：拿到这个包，换一台机器能原样重跑并比对。没有这个包的结果，不能作为验收证据。

### 11.4 复算与比对（验收关注点）

复算判据分**四级，按模型定**（`03` §7.4.1）。**注意：不是所有模型都能复现，平台不承诺「每个模型跑出来都一样」**：

| 级 | 适用（按模型） | 判据 | 平台承诺 |
|---|---|---|---|
| **D1 比特级** | 结构准备、ETKDG 构象生成、药效团、格式转换、ECFP4 指纹 | 产物 **SHA-256 完全一致** | ✅ 保证；不一致就是缺陷 |
| **D2 数值容差** | Boltz-2 结构预测、LVpocket 口袋、AutoDock Vina、MSIGN 亲和力、MolP-PC ADMET | 按**该模型已标定**的容差表（如结构主链 RMSD ≤ 0.5 Å、对接评分偏差 ≤ 0.5 kcal/mol） | ⚠ 承诺「在这个带宽内」，未标定的模型标 `PENDING` |
| **D3 统计等价** | GROMACS MD、gmx_MMPBSA 自由能 | 重复 ≥3 次比统计量（RMSD/RMSF 均值方差、能量均值标准差） | ⚠ 只承诺分布等价 |
| **D4 不可复现** | **STD-Diff 扩散生成、Pocket2Mol（VAE 采样）、TheraPainter 多肽设计** | **不比结果**，只核对参数与种子是否被完整记录、manifest 是否如实标注 | ❌ **不做复现承诺**；只保证「同种子同镜像能重跑起来」 |

**操作**：P-32 → `追溯` Tab → `复算` → 平台用同镜像同权重同参数重跑 → 生成**七列**对比报告（模型 / 复现等级 / 原结果 / 复算结果 / 偏差 / 判据 / 结论）。

> ⚠ **生成类模型（STD-Diff / Pocket2Mol / TheraPainter）不要指望复算出同样的分子**。它们每次采样都不同，固定种子只在同一环境下可重放；换卡数、换批大小结果都会完全变。验收时对这类模型查的是「声明是否诚实」，不是「分子是否一样」。
>
> ⚠ 复算前平台会校验镜像与权重 SHA-256 是否还在。**若权重被替换过，复算会拒绝执行并提示换样重抽**——这是保护，不是故障。另外**换卡位跑同一任务可能落到不同驱动实例**，复算会优先在原卡位执行。

## 13. 算力、排队与配额（用户视角）

> 技术细节见 `03` §5.3 / §5.6，这里只讲「你遇到时会怎样、该怎么办」。

### 13.1 五种规模层

| 层 | 规模 | 你提交时看到什么 | 大概多久 |
|---|---|---|---|
| **S 交互** | 1~10 件 | 无提示，直接提交 | 秒~分钟（走预留交互卡） |
| **M 常规** | 10~500 件 | 返回排队位置 + 预估完成时间 | 分钟~小时 |
| **L 大批量** | 500~10000 件 | 同上，可能被安排到夜间 | 小时级 |
| **XL 超大批量** | 10000~100000 件 | **阻断式预估单**，必须确认 | **天级** |
| **T 长时单体** | 1 件但 >1h | 提示「长时任务，可能等更久」 | 小时~天级 |

> **层是自动判定的**，按你提交的 `itemCount` 算。想快就跑小批量——这是唯一有效的手段。

### 13.2 为什么我的任务在排队

按可能性排序：

1. **你的层被排在别人后面**。`BULK`（L/XL）永远排在 `HIGH`（S）和 `NORMAL`（M）之后。
2. **交互卡被占满**。预留 4 卡只给 S/M 用；如果 S 任务也在等，说明 4 卡都被占着——这是异常，请报运维（`14` AL-21）。
3. **批量卡在跑别人的大任务**。批量 10 卡跑一个 10 万条筛选时，其他 L/XL 全部排队。
4. **你的项目配额用完了**。看 P-36 或项目设置里的「剩余算力分钟」。

### 13.3 配额怎么算

**按算力分钟，按实际消耗核销**（`03` §5.3）：

| 资源 | 折算 |
|---|---|
| 1 张 DCU 跑 1 分钟 | **1.0 算力分钟** |
| 1 个 CPU 核跑 1 分钟 | **1/64 算力分钟** |
| 内存 | 不计 |

- **终态一律核销**：失败、取消、超时**都算**（因为资源确实被占用了）。
- **被拒绝的不算**：提交时就被配额挡下的，不核销。
- **超额只告警 + 阻塞新提交**，不会杀掉你已经在排队的任务。

> ⚠ 这条规则的实际含义：**反复提交又取消，也会消耗配额**。调参数请用 `S` 层小样本试，别拿全量试错。

### 13.4 算力指示灯

顶部常驻，显示当前 DCU 使用率：

| 颜色 | 含义 | 建议 |
|---|---|---|
| 绿 | < 60% | 随便提交 |
| 黄 | 60~90% | 大批量会等，考虑夜间 |
| 红 | > 90% | 只有 S 层能立刻跑，其他都会排长队 |

## 15. 故障处理与 FAQ

### 15.1 先看这张表

| 现象 | 最可能的原因 | 你自己能做什么 |
|---|---|---|
| 提交按钮灰的 | 你只是 `VIEWER`；或前置未满足 | 找 PL 要权限；看页面提示的缺失项 |
| 点了提交没反应 | 转异步了，任务在队列里 | 去 P-31 任务中心看 |
| 一直「排队中」 | 见 §13.2 | 等，或改小批量 |
| 进度卡在 99% | 产物正在上传对象存储 | 再等 2 分钟；超过 10 分钟报运维 |
| 任务 `FAILED` 但日志没内容 | 容器启动失败（镜像/权重/挂载） | 点 `重试` 一次；仍失败报运维 |
| 结果页空白 | 任务成功了但产物没回填 | 刷新；仍空白报运维（可能是 MQ 回填丢失） |
| 下载 403 | 预签名链接过期（默认 15 分钟） | 重新发起导出 |
| 3D 视图不加载 | 浏览器 WebGL 被禁用 / 结构过大 | 换 Chrome；>5000 残基自动降级 |

### 15.3 必须找人、不要自己试的六种情况

1. 节点状态显示 `DOWN` 或两台机器同时 `UNREACHABLE`
2. 同一个任务**重试 3 次**仍然同样失败
3. 结果与预期**数量级**不符（如对接分数 -60 kcal/mol）
4. 决策记录写错了想改（**不能改**，只能补一条）
5. 需要恢复 **超过 90 天**前删除的数据（90 天内走回收站，超过走备份恢复，`15` §4）
6. 怀疑数据越权（看到了不该看的项目）

### 15.4 FAQ

**Q：能不能一次提交 50 万条？**
不能。上限 10 万条（`XL`）。超过请拆分或先做漏斗粗筛。

**Q：为什么我的分子生成结果和上次不一样？**
扩散模型 + GPU 浮点非确定性，**不保证逐字节一致**。判据是统计等价（§6.4）。要严格复现请用 `重试` 沿用原种子。

**Q：任务能跑多久？**
每类任务有 `maxMinutes`，超时置 `TIMEOUT` 并释放资源。MD 默认上限按配置（通常 24 小时），超时前会提示。

**Q：删掉的数据能恢复吗？**
删除是**软删除**（标记 `deleted_at`），延迟物理清理。**保留期为 90 天**（`01` BR-3 / `03` §9 / `15` §8 口径一致）：90 天内由管理员在回收站恢复（RTO ≤ 15 分钟）；超过 90 天需从逻辑备份定向恢复（RTO ≤ 4 小时）。

**Q：为什么我看不到「新建」按钮？**
两种可能：你是 `VIEWER`（§3.2），或者当前页面在你的角色下不开放。按钮是**隐藏**而非置灰，这是设计。

**Q：`traceability.json` 里的 `execution_flags` 是什么？**
模型运行时实际走的代码路径标记（如 `cuEquivariance=fallback`）。**它影响结果可比性**，比对两个结果前先看这个字段是否一致。

**Q：能不能把结果直接发给同事？**
导出文件或分享项目内链接。**不要直接转发下载链接**（预签名会过期，且绕过权限）。
