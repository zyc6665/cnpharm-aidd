# 核心领域设计

## 1. 领域模型总览

平台核心领域对象如下：

```text
User ── ProjectMember ── Project
                         │
                         ├─ Artifact ── ArtifactVersion ── FileRole ── File
                         ├─ Task ── TaskInput / TaskOutput / TaskLog
                         ├─ WorkflowDefinition ── WorkflowRun ── NodeState
                         ├─ Conversation / AgentRun
                         └─ ResearchBoard

Tool ── ToolVersion ── ToolContract
  │
  └─ ExecutorConfig / ResourceProfile / Examples / Tags / Groups
```

## 2. Project

### 2.1 定义

Project 是研发上下文和权限边界。项目聚合任务、Artifact、工作流、白板和智能体会话。

### 2.2 不变量

- 项目内 Artifact 不能被其他项目直接绑定。
- 项目成员权限决定能否查看、运行、编辑和管理。
- 项目归档后不应继续创建新的运行记录。

### 2.3 设计边界

- Project 不描述工具能力。
- Project 不保存工具参数 schema。
- Project 只提供上下文、权限和资产归属。

## 3. Standard Artifact

### 3.1 定义

Standard Artifact 是平台理解的科研数据对象。它由平台 registry 定义类型、版本、文件角色和元数据要求。

### 3.2 对象关系

```text
Artifact
 ├─ standard_type
 ├─ standard_version
 ├─ latest_version_id
 ├─ source_task_id
 └─ project_id

ArtifactVersion
 ├─ manifest_json
 ├─ summary_json
 ├─ metrics_json
 ├─ validation_status
 └─ files[]

ArtifactVersionFile
 ├─ role
 ├─ file_id
 └─ is_primary
```

### 3.3 不变量

- Artifact 必须归属某个项目或默认工作空间项目。
- ArtifactVersion 不可变。
- 标准类型和版本不可随意修改。
- 文件角色必须满足 registry 要求。
- 谱系关系不能跨项目建立。

### 3.4 设计边界

- File 是存储对象，Artifact 是科研语义对象。
- TaskOutput 可以包含普通文件，但只有标准结果会沉淀为 Artifact。
- 可视化应按 Artifact 类型渲染，而不是按工具名称渲染。

## 4. Tool

### 4.1 定义

Tool 是可执行能力的声明。ToolVersion 是某个版本的具体契约和执行配置。

### 4.2 Tool Contract

Tool Contract 是工具对平台的稳定接口：

```text
ToolContract
 ├─ identity
 ├─ executor
 ├─ parameters_schema
 ├─ artifacts.inputs
 ├─ artifacts.outputs
 ├─ resource_profile
 ├─ validation
 └─ examples
```

### 4.3 不变量

- 新工具必须声明确定的 Artifact 输入输出。
- 标准输出类型由平台 registry 限定。
- 参数 schema 不应承载标准 Artifact 文件输入。
- 工具不保存项目上下文。

### 4.4 设计边界

- Tool 是能力定义，Task 是运行实例。
- Tool 不直接知道工作流节点。
- Tool 不直接知道 Agent 计划。
- Tool 不直接存储集群凭据。

## 5. Task

### 5.1 定义

Task 是一次工具运行实例。所有运行入口最终都创建 Task。

### 5.2 输入模型

```text
TaskInput
 ├─ params
 ├─ file_ids
 ├─ input_bindings
 └─ standard_input_uploads
```

解释：

- `params`：普通参数。
- `file_ids`：legacy 文件输入和直接上传文件。
- `input_bindings`：已有 ArtifactVersion 绑定。
- `standard_input_uploads`：标准 Artifact slot 的直接上传文件绑定。

### 5.3 输出模型

```text
TaskOutput
 ├─ result
 ├─ file_ids
 └─ standard_artifacts
```

### 5.4 不变量

- 有已有 ArtifactVersion 绑定时必须有项目上下文。
- 有标准 Artifact 输出时必须解析出输出归属项目。
- 任务执行器不应自行决定项目归属。
- 任务日志应能解释失败原因。

## 6. Run Context

### 6.1 定义

Run Context 是一次运行的上下文，不属于 Tool Contract。

### 6.2 类型

| 类型 | 场景 | 输出归属 |
| --- | --- | --- |
| Project Context | 从项目进入工具或工作流 | 当前项目 |
| Default Workspace Context | 独立工具运行但产出标准 Artifact | 用户默认工作空间项目 |
| File-only Context | 普通文件/JSON 输出工具 | 无需 Artifact 归属 |

### 6.3 不变量

- Run Context 由调用入口和后端权限共同决定。
- Tool Contract 不包含 Run Context。
- 输出归属必须在任务派发前确定。

## 7. Artifact Binding

### 7.1 定义

Artifact Binding 是满足工具 Artifact Slot 的决策。

### 7.2 输入来源

- Existing ArtifactVersion。
- Direct Upload。
- Workflow Input。
- Upstream Node Output。

### 7.3 输出

Binding Resolver 应输出：

- `params`。
- `file_ids`。
- `input_bindings`。
- `standard_input_uploads`。
- `binding_decisions`。
- `missing_inputs`。
- `preparation_suggestions`。

### 7.4 不变量

- Resolver 是绑定决策唯一权威入口。
- 前端可以预测和展示，后端必须最终校验。
- 角色不满足时不应静默降级。

## 8. Workflow

### 8.1 定义

WorkflowDefinition 是流程模板，WorkflowRun 是一次运行。

### 8.2 节点模型

```text
WorkflowNode
 ├─ id
 ├─ kind
 ├─ tool_slug
 ├─ params
 ├─ artifact_input_slots
 ├─ artifact_outputs
 ├─ artifact_inputs
 └─ semantic_inputs / semantic_outputs legacy
```

### 8.3 边模型

```text
WorkflowEdge
 ├─ source
 ├─ target
 ├─ source_output
 └─ target_input
```

### 8.4 不变量

- 边连接的是标准 Artifact 类型或 slot，不是文件路径。
- 下游输入优先从上游 ArtifactVersion 自动绑定。
- 工作流外部输入只出现在流程边界。
- 保存的工作流加载时需要用当前 Tool Contract 补齐旧节点槽位。

## 9. Agent

### 9.1 定义

Agent 是辅助规划模块。它可以生成建议和草稿，但不能绕过平台领域规则。

### 9.2 输入

- 用户自然语言。
- 项目上下文。
- 工具契约。
- Artifact 列表。
- 工作流运行状态。

### 9.3 输出

- 解释。
- 工具推荐。
- 工作流草稿。
- 缺失输入提示。
- 结果总结。

### 9.4 不变量

- Agent 输出必须经过工具契约和权限校验。
- Agent 不直接写入不可审计执行状态。
- Agent 生成的流程必须落入 WorkflowDefinition 或 Task。

## 10. 外部数据库

### 10.1 定义

外部数据库模块负责从公共数据库查询并导入数据。

### 10.2 不变量

- 外部记录导入后必须转成标准 Artifact。
- 必须保留来源和时间。
- 导入动作应记录到项目或默认工作空间。

## 11. 需要统一的领域语言

| 当前混乱表达 | 推荐表达 |
| --- | --- |
| 文件输入、Artifact 输入、标准输入混用 | Artifact Slot |
| 工具需要项目 | 运行需要 Run Context |
| 工作流自动处理参数 | Artifact Binding Resolver 处理绑定 |
| 节点结果 | Task Output + Standard Artifact |
| 模型工具部署方式 | Executor Adapter |
| 工作流任务内容 | Node Task Binding |

## 12. 领域治理规则

1. 新功能必须说明它归属哪个领域对象。
2. 新工具必须先声明 Tool Contract。
3. 新数据资产必须先判断是否应成为 Standard Artifact。
4. 新工作流能力必须依赖 Artifact Slot，不依赖工具私有字段。
5. 新执行方式必须作为 Executor Adapter，不进入业务页面逻辑。
