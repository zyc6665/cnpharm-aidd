# 平台总体架构

> 执行环境重构基线：生产执行只使用 `k8s_job` 和 `ssh_job`。`docker_image`、`python_script` 是运行时描述，`remote_api` 仅作为旧工具兼容连接器。完整方案见 [执行环境与资源调度重构方案](./19-执行环境与资源调度重构方案.md)。

## 1. 架构目标

平台架构要支撑药物研发中的多工具、多数据、多资源、多入口协作。架构重点不是把所有功能堆在页面上，而是形成稳定的数据和执行主线。

目标：

- 以 Project 组织研发上下文。
- 以 Standard Artifact 组织科研数据。
- 以 Tool Contract 组织算法能力。
- 以 Task 组织执行实例。
- 以 Workflow 组织流程编排。
- 以 Agent 提供辅助规划和解释。
- 以 Executor / Scheduler 屏蔽底层计算资源差异。

## 3. 架构主线

### 3.1 数据主线：Standard Artifact

所有可复用科研数据都应沉淀为 Standard Artifact。普通文件只是存储对象，Standard Artifact 才是平台能理解的科研资产。

数据流：

```text
上传 / 外部数据库 / 工具输出
        │
        ▼
File 存储对象
        │
        ▼
ArtifactVersion 文件角色与元数据
        │
        ▼
Artifact 最新版本和谱系
        │
        ▼
工作流自动绑定 / 可视化 / 下载 / 后续任务复用
```

### 3.2 能力主线：Tool Contract

工具只声明能力，不承载项目状态。工具契约应回答：这个工具需要哪些参数、哪些标准输入、会产出哪些标准输出、需要什么资源、通过什么执行器运行。

```text
Tool
 ├─ parameters_schema
 ├─ artifacts.inputs
 ├─ artifacts.outputs
 ├─ executor
 ├─ resource_profile
 └─ examples / docs
```

### 3.3 执行主线：Task

所有工具运行最终都应落成 Task。无论来自工具详情页、节点独立运行、工作流、智能体，最终都走同一个任务创建和调度入口。

```text
Run Request
  │
  ├─ Run Preparation
  ├─ Artifact Binding 决策
  ├─ 参数、上传文件和 legacy 投影
  ├─ 资源画像生成
  ▼
Task
  ▼
Executor
  ▼
TaskOutput + File + Standard Artifact
```

### 3.4 编排主线：Workflow

工作流不应理解每个工具的私有字段。工作流只处理节点、边、状态和标准 Artifact 类型。工具特异性由 Tool Contract 和 Run Preparation Module 处理，Artifact Binding 只是其中的 slot/source/role 决策。

```text
WorkflowDefinition
  ├─ nodes: tool_slug + params + artifact slots
  ├─ edges: source_output -> target_input
  └─ workflow inputs

WorkflowRun
  ├─ materialized definition
  ├─ node states
  ├─ task bindings
  └─ artifact lineage
```

## 4. 前端架构

### 4.1 页面层

页面层负责组合业务体验：

- `views/projects`：项目入口。
- `views/tools`：工具浏览和独立运行。
- `views/workflow`：工作流画布。
- `views/tasks`：任务中心。
- `views/research-boards`：科研白板。
- `views/admin`：管理后台。

页面层不应包含复杂领域决策。

### 4.2 组件层

组件层负责 UI 复用：

- Artifact 渲染器。
- 工具参数表单。
- 工作流节点面板。
- 结果可视化面板。
- 文件选择器。

### 4.3 Domain 层

`frontend/src/domain` 和 `frontend/src/workflow` 应承载前端领域逻辑：

- 工具契约解析。
- 标准 Artifact 输入策略。
- 工作流预检。
- 结果展示策略。
- 项目导航和权限展示。

### 4.4 Store 层

Pinia store 保存状态，不承载复杂领域判断：

- 用户认证状态。
- 当前工具。
- Artifact 列表。
- 工作流会话。
- 任务绑定。
- 工作流运行。

## 5. 后端架构

### 5.1 API 层

API 层负责请求校验、权限校验和响应序列化。API 不应包含工具执行细节。

主要 API：

- `projects`
- `artifacts`
- `tools_public` / `tools_admin`
- `tasks`
- `workflows`
- `external_databases`
- `research_boards`
- `conversations` / `agents`

### 5.2 领域服务层

领域服务层封装稳定行为：

- Artifact 持久化。
- Tool Contract 构建和校验。
- Run Preparation 和 Artifact Binding 决策。
- Workflow 调度。
- Task 创建和调度。
- 外部数据库导入。

### 5.3 执行层

执行层屏蔽受控执行环境差异：

- K8s Job Adapter：生产主路径。
- SSH Job Adapter：无集群和过渡路径。
- 轻量 builtin：仅用于平台内置兼容能力。
- Docker/Python：作为 K8s/SSH Job 内的 runtime。
- Remote API：仅用于旧工具兼容。

执行层只消费准备好的任务输入，不做业务规划。

### 5.4 数据模型层

核心表：

- User / Project / ProjectMember。
- Tool / ToolVersion / ToolCategory / ToolWorkbenchGroup。
- Task / TaskInput / TaskOutput / TaskLog。
- File。
- Artifact / ArtifactVersion / ArtifactVersionFile / ArtifactLineage。
- WorkflowDefinition / WorkflowRun。
- AgentRun / Conversation / ResearchBoard。

## 6. 关键深模块

### 6.1 Tool Contract Builder

小接口：输入 Tool，输出标准契约。内部兼容 legacy config、agent_capability、artifacts 和 Tool Package。

价值：新工具只要契约正确，前端、工作流、智能体都能理解。

### 6.2 Run Preparation Module

小接口：输入 Tool Contract、Run Context 和用户/工作流输入来源，输出 PreparedRun 和 ReadinessReport。内部包含 Artifact Binding、上传文件 staging、权限校验、role 选择和 legacy 参数投影。

价值：工具详情页、节点独立运行、工作流调度不再各自实现绑定逻辑。

### 6.3 Task Command Module

小接口：输入 PreparedRun，创建、启动、取消或重试 Task。

价值：所有 Run Surface 不再自己拼 TaskCreate payload。

### 6.4 Workflow Orchestration Module

小接口：输入 WorkflowRun，启动可运行节点并同步状态。

价值：画布只表达流程，不直接管理任务执行细节。

### 6.5 Standard Artifact Persistence

小接口：输入 TaskOutput 和标准结果，输出 ArtifactVersion 和谱系。

价值：所有工具输出统一沉淀为可复用数据资产。

## 7. 当前架构问题

1. 工具独立运行、节点独立运行、工作流运行的输入绑定逻辑重复。
2. 前端部分规则比后端能力更保守，例如标准 Artifact 输入无项目直接被阻断。
3. 工作流节点 UI 和工具契约之间存在历史快照不一致问题。
4. Agent、Workflow、Tool、Task 都在表达“运行计划”，边界需要收敛。
5. 重计算部署方式还没有统一资源抽象。
6. 新药研工具继续增加时，缺少平台级模块归属标准。

## 8. 架构治理方向

第一阶段不追求重写，而是收敛主线：

- 工具契约统一。
- Run Preparation Module 统一。
- 工作流只依赖标准 Artifact 类型。
- 工具独立运行和工作流运行共享任务创建模型。
- 重计算工具统一资源画像和执行器接口。
