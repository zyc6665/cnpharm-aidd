# 模块边界与迁移计划

## 1. 目标

本计划把现有原型式堆积逐步迁移到工程化架构。迁移策略是不做大爆炸重写，而是先定义目标边界，再沿用户可见链路替换重复逻辑。

第一条验收链路：

```text
Fetch PDB
  -> Protein Preparation
  -> LVpocket
```

第二条验收链路：

```text
Fetch PubChem Ligand
  -> Ligand Preparation
  -> RDKit Properties
  -> ADMET
```

## 2. 当前问题映射

| 问题 | 现象 | 目标模块 |
| --- | --- | --- |
| 多入口输入模型不一致 | 工具详情页、节点独立运行、工作流运行表现不同 | Run Preparation Module |
| 工作流承担工具适配 | scheduler/preflight/persistence 都在补契约和猜绑定 | Workflow Orchestration Module |
| Tool Contract 兼容逻辑分散 | legacy artifacts、agent_capability、Tool Package、Remote API 混用 | Tool Contract Module |
| 标准输出归属不稳定 | 缺 project_id 时输出持久化失败 | Run Context + Standard Artifact Module |
| 执行器差异暴露 | SSH、Docker、Remote API、K8s、Slurm 状态/日志/取消不统一 | Executor Gateway Module |
| 可视化按工具修补 | 节点预览、任务详情、结果中心策略不一致 | Artifact Presentation Module |

## 3. 目标模块边界

### 3.1 Tool Contract Module

现有相关文件：

- `backend/app/services/tool_contracts.py`
- `backend/app/tool_packages/`
- `backend/app/remote_tools/`
- `frontend/src/workflow/contract-bindings.ts`
- `frontend/src/domain/tools/*`

目标：

- 后端成为 Tool Contract 权威。
- 前端只消费归一化 contract，不再修补 legacy contract。
- legacy 转换集中在 builder 内。

迁移动作：

1. 给 Tool Contract Builder 增加稳定 DTO 和 validation result。
2. 把 workflow contract hydration 依赖的字段全部纳入 contract 输出。
3. 前端 `contract-bindings.ts` 只做展示型转换，不再承担 legacy 修复。

### 3.2 Run Preparation Module

现有相关文件：

- `backend/app/services/artifact_binding_resolver.py`
- `backend/app/tasks/service.py`
- `frontend/src/domain/tools/standard-artifact-run-context.ts`
- `frontend/src/composables/useStandaloneNodeRun.ts`
- `frontend/src/workflow/preflight.ts`

目标：

- 建立 `prepare_run()` 作为工具运行前唯一权威入口。
- 同时服务工具详情页、节点独立运行、工作流运行和 Agent。
- 统一输出 `PreparedRun`、`ReadinessReport`、`BindingDecision`。

迁移动作：

1. 后端新增 `RunPreparationInput` / `PreparedRun` schema。
2. 将 `_validate_standard_input_bindings`、`_project_standard_input_bindings`、标准上传 staged 逻辑迁入模块。
3. 工具详情页和节点独立运行只发送用户输入来源，不拼内部字段。
4. 工作流调度只调用 prepare_run，不再自己投影 file_ids。

### 3.3 Task Command Module

现有相关文件：

- `backend/app/tasks/service.py`
- `backend/app/tasks/executors/`
- `backend/app/worker/tools/`

目标：

- Task 创建、启动、取消、重试统一。
- `TaskCreate` 从外部请求 DTO 逐步变成内部命令 DTO。
- 所有 Run Surface 最终落到同一个 create/start 流程。

迁移动作：

1. 保留现有 API DTO，新增内部 `CreatePreparedTaskCommand`。
2. 让 API 和 Workflow 都先得到 `PreparedRun`，再创建 Task。
3. 移除散落的默认项目推断和标准输出归属补丁。

### 3.4 Workflow Orchestration Module

现有相关文件：

- `backend/app/services/workflow_scheduler.py`
- `backend/app/services/workflow_validation.py`
- `backend/app/services/workflow_reconciliation.py`
- `backend/app/services/workflow_runs.py`
- `frontend/src/workflow/*`
- `frontend/src/composables/useWorkflow*.ts`

目标：

- 工作流只表达节点、边、Workflow Input、Node Task Binding。
- 节点 readiness 由 Run Preparation 判断。
- 保存和加载不丢任务、产物和 contract hydration。

迁移动作：

1. 把 workflow_scheduler 拆成 plan materialization、node readiness、node dispatch、state sync 四个内部模块。
2. 对外保留一个小 Interface：`preflight()`、`start()`、`sync_task_event()`。
3. 前端 composables 只管理交互状态，领域判断迁入 `frontend/src/workflow` 纯函数。
4. 保存格式增加明确版本号和 contract snapshot policy。

### 3.5 Executor Gateway Module

现有相关文件：

- `backend/app/execution/`
- `backend/app/tasks/executors/`
- `backend/app/remote_tools/`

目标：

- K8s Job 和 SSH Job 共享 submit/inspect/cancel/logs/collect Interface；旧 Remote API/Docker/Python 由隔离的兼容适配器承接。
- Task 不关心底层 execution handle 结构。

迁移动作：

1. 定义 `TaskExecutionRequest` 和 `ExecutionHandle`。
2. 建立 K8s Job 与 SSH Job 受控执行 Adapter；旧 Remote API 仅维持迁移兼容。
3. 再让 Docker、K8s、Slurm 复用同一输出 manifest。

### 3.6 Artifact Presentation Module

现有相关文件：

- `frontend/src/components/artifacts/`
- `frontend/src/domain/tasks/result-visualization.ts`
- `frontend/src/workflow/artifact-resolver.ts`
- 任务详情和工作流节点渲染逻辑。

目标：

- 按 Standard Artifact type 选择 renderer。
- 节点内预览、放大查看、任务详情和 Artifact 详情共享 renderer registry。

迁移动作：

1. 建立前端 `ArtifactRendererRegistry`。
2. 将 protein、ligand、pocket、molecule table、run report 都注册到 registry。
3. 删除按工具 slug 判断可视化的逻辑。

## 4. 迁移阶段

### 阶段 1：接口冻结

目标：冻结 Architecture Kernel 的 Interface，允许内部继续沿用旧实现。

交付：

- `ToolContract` DTO。
- `RunPreparationInput` / `PreparedRun` / `ReadinessReport`。
- `TaskExecutionRequest` / `ExecutionHandle`。
- `WorkflowPlan` / `NodeTaskBinding`。
- `ArtifactRendererDescriptor`。

验收：

- 新代码只能依赖这些 Interface。
- 旧代码允许存在，但不能继续扩大。

### 阶段 2：Run Preparation 权威化

目标：解决工具详情页、节点独立运行、工作流运行不一致。

工作项：

- 后端将 input_bindings、standard_input_uploads、Run Context、role policy 收敛到 prepare_run。
- 前端将表单预检改为调用或镜像同一模型。
- 移除工具详情页“标准 Artifact 输入必须项目”的硬阻断。

验收：

- 无项目 + 上传标准输入可运行。
- 有项目 + 选择 ArtifactVersion 可运行。
- 工作流上游 Artifact 自动绑定。
- 所有失败都返回 BindingDecision。

### 阶段 3：Workflow Orchestration 瘦身

目标：让工作流不再承担工具适配。

工作项：

- `workflow_scheduler.py` 内部拆分，外部 Interface 不变。
- preflight 使用 Run Preparation 的 ReadinessReport。
- 保存恢复 Node Task Binding。
- 前端 `useWorkflowPersistence.ts` 仅做持久化状态映射，不做契约推断。

验收：

- 保存的 test 工作流加载后能恢复节点任务。
- Fetch PDB -> Protein Preparation -> LVpocket 不需要手动绑定。
- 上游未完成、类型不匹配、缺角色三类错误能区分。

### 阶段 4：Executor Gateway 统一

目标：重计算工具接入不再侵入 Task/Workflow。

工作项：

- 统一 submit/inspect/cancel/logs/collect。
- SSH Job 先对齐 Interface。
- 旧 Remote API 兼容工具使用统一状态和取消接口，但不作为新工具路径。
- K8s Job 是生产主 Adapter，SSH Job 是无 K8s 环境的过渡 Adapter；Slurm 专用 Adapter 后续按需评审。

验收：

- 长任务可取消。
- 日志可增量读取。
- 输出 manifest 可回收并持久化 Artifact。

### 阶段 5：前端工作台收敛

目标：傻瓜化用户体验和工程结构同时成立。

工作项：

- 工作台页面拆成 shell、canvas、tool library、node inspector、result center。
- 业务判断迁入 domain/workflow 纯函数。
- Artifact Renderer Registry 统一可视化。

验收：

- 节点独立运行体验一致。
- 画布大小不受节点位置影响。
- 工具库筛选来自后台标签和 contract，不硬编码。

## 5. 代码治理规则

### 5.1 文件大小信号

超过以下规模需要审查是否拆模块：

- 后端单文件超过 500 行。
- 前端 composable 超过 300 行。
- Vue 页面超过 800 行。
- 单个函数超过 80 行且包含多个业务分支。

这不是硬性禁止，但必须解释为什么仍然合理。

### 5.2 依赖规则

- `api` 可以依赖 application facade，不能依赖 executor adapter 细节。
- `workflow` 可以依赖 Tool Contract 和 Run Preparation Interface，不能依赖工具私有 config。
- `execution` 可以依赖 TaskExecutionRequest，不能依赖 WorkflowDefinition。
- `artifacts` 可以依赖 File storage，不能依赖 UI renderer。
- `agent` 可以读取 Tool Contract 摘要，不能直接拼 TaskCreate。

### 5.3 新功能落位规则

| 新功能 | 应放位置 |
| --- | --- |
| 新模型接入 | Tool Contract / Tool Package / Remote API |
| 新标准输入输出 | Artifact schema + Tool Contract |
| 新执行环境 | Executor Adapter |
| 新工作流节点能力 | Workflow Orchestration + Tool Contract |
| 新可视化 | Artifact Presentation Module |
| 新页面交互 | View + Component，领域判断进 domain/workflow |

## 6. 重构优先级

### P0

- Run Preparation Module 权威化。
- 工具详情页、节点独立运行、工作流运行共享输入模型。
- Workflow 保存恢复 Node Task Binding。
- Tool Contract Builder 输出稳定化。

### P1

- Workflow Scheduler 内部瘦身。
- Executor Gateway Interface。
- Artifact Renderer Registry。
- 工具库动态标签和 contract 筛选。

### P2

- Slurm 专用 Adapter（按客户环境评审）；K8s/SSH Job 属于当前执行基线。
- Agent 基于 Tool Contract 和 Artifact registry 生成可执行草稿。
- 旧 docs/design/guides 的迁移和归档索引。

## 7. 禁止事项

- 禁止继续把跨入口规则写进单个页面或 composable。
- 禁止新增工具时修改工作流专属适配表。
- 禁止 executor adapter 直接处理 ArtifactVersion 权限。
- 禁止为了某个模型临时扩展 TaskCreate 私有字段而不进入 Tool Contract。
- 禁止绕过标准 Artifact 输出持久化直接给前端文件 URL。
