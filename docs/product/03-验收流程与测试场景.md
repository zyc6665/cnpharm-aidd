# 验收流程与测试场景

> 文档状态：基线草案；修订日期：2026-09-05；维护角色：测试负责人、科学负责人。本文件定义待执行场景，本次文档修订不表示测试、模型或硬件已验证。

## 1. 目标

本文件定义平台功能从“能跑”到“研发人员能顺手使用”的验收方式。验收不只看接口是否返回成功，还要验证工具注册、标准 Artifact、任务运行、工作流自动绑定、可视化、下载、取消和错误提示是否贯通。

版本与 AT 编号以 [企业交付需求](../delivery/01-企业交付需求规格说明书.md) 第 8 节为准。V1 验基础计算链路和科学说明附件，V1.1 验候选决策/人工实验反馈，V2 验对接/MD/集群及多轮复盘；只执行本次交付范围，提前试点需单独列出。

## 2. 验收分层

| 层级 | 验收对象 | 主要问题 |
| --- | --- | --- |
| Contract | Tool Contract / Remote Manifest / Tool Package | 工具是否能被平台理解 |
| Binding | Artifact Slot / Run Context / Resolver | 输入输出是否能自动绑定 |
| Execution | Task / Executor / ResourceProfile | 任务是否能提交、运行、取消、回收 |
| Artifact | Standard Artifact / FileRole / Metadata | 输出是否可复用、可追踪、可下载 |
| Workflow | 节点、边、预检、保存恢复 | 用户是否只需拖节点、连线、补必要输入 |
| UX | 表单、节点面板、结果中心、错误文案 | 研发人员是否能理解和操作 |
| Scientific Semantics | 分子状态、endpoint、单位、模型版本、证据范围 | 预测、实测和评分是否可区分，是否误用结果 |
| Scientific Validation | 基准、拆分、指标、容差、适用域 | 声明的质量能否被独立复核，是否覆盖当前用途 |
| Decision/Feedback | 候选快照、实验回写、配对、报告 | 科研人员能否解释选择依据并追溯实验反馈 |

前六层通过不意味着科学验证通过。证据等级与工程/科学双维度记录按 [科学结果规范](../architecture/16-药研数据与科学结果规范.md) 第 2 节执行；科学基准为 V1.1 要求或特定科学声明的前提，不是所有 V1 平台交付必须达到 E3/E4。

## 3. P0 核心验收链路

### 3.1 外部数据库到口袋预测

流程：

```text
Fetch PDB
  -> Protein Preparation
  -> LVpocket Pocket Prediction
```

验收点：

- Fetch PDB 输入 PDB ID 后产出 `protein_structure@1`。
- Protein Preparation 自动接收上游 protein，产出 prepared roles。
- LVpocket 自动使用 prepared protein。
- 用户不手动填写文件路径、file_id 或 ArtifactVersion ID。
- 节点可独立运行。
- 保存工作流后重新加载，节点任务和 Artifact 绑定仍可见。
- 口袋结果可在节点内预览、放大查看和下载。

### 3.2 小分子查询、属性和基础 ADMET（AT-003）

流程：

```text
Fetch PubChem Ligand
  -> Ligand Preparation
  -> RDKit Properties
  -> Basic ADMET Prediction
```

验收点：

- PubChem 查询支持 CID、名称或 SMILES。
- ligand 输出同时支持 2D 和 3D；无 3D 时 RDKit 生成并记录来源。
- RDKit Properties 作为平台内置节点运行。
- 输出 `molecule_table@1` 可表格查看和下载。
- 基础 ADMET 使用验收前登记的真实 endpoint 和固定模型版本，独立运行与串联运行均验证；RDKit 描述符不替代该步骤。
- 结果关联 molecule/state、endpoint、单位/标签、模型与输入版本，未估计适用域标 unknown；失败值不填零。
- 输出采用已支持的 molecule_table/run_report 与交付附件，不要求 admet_report 候选类型提前实现。

### 3.3 工具独立运行

场景：用户不进入项目，直接打开工具详情页运行 Fetch PDB 或 RDKit Properties。

验收点：

- 无 project 时允许上传或填写参数运行。
- 产出标准 Artifact 时自动进入用户默认工作空间。
- 不再出现“标准 Artifact 输入需要项目上下文”的硬阻断。
- 工具详情页保留“一键填入示例”。

### 3.4 节点独立运行

场景：用户在工作流画布中拖入一个节点，不连线，直接运行。

验收点：

- 节点面板有独立运行入口。
- 缺少标准输入时可上传文件或选择项目 Artifact。
- 普通参数从 schema 自动生成表单。
- 运行结果展示在节点和结果中心。

## 4. 后续药研连续流程验收

### 4.1 生成到扩展 ADMET（V1.1，AT-023）

流程：

```text
Fetch PDB
  -> Protein Preparation
  -> LVpocket
  -> Molecule Generation
  -> Candidate Molecules
       -> ADMET Prediction --------+
       -> Toxicity Prediction -----+-> Scoring Rerank
       -> Synthetic Accessibility -+
```

验收点：

- 分子生成自动使用 pocket。
- ADMET、毒性和合成可及性自动使用 molecule table。
- 各评价分支接收同一候选集合，按 molecule/state、endpoint 和模型版本合并，不能假定前一步输出仍含下一步所需结构。
- 打分重排保留原始值、候选分母、缺失策略和权重；不可比分数不能隐式加权，零方差归一化、重复键和缺失行必须测试。
- 结果中心按 Artifact 类型聚合。
- Agent 可以解释每一步输入输出，但不能绕过 Tool Contract。

### 4.2 对接链路（V2，FR-CADD-008）

流程：

```text
Fetch PDB
  -> Protein Preparation
Fetch PubChem Ligand
  -> Ligand Preparation
Protein Preparation + Ligand Preparation + LVpocket
  -> Molecular Docking
  -> Scoring Rerank
```

验收点：

- Docking 缺 `receptor_pdbqt` 时提示先运行 Protein Preparation。
- Docking 可使用 pocket metadata 作为盒子中心。
- Docking 输出 pose 和 score table。
- 对接结果可查看、下载并进入重排。
- 固定受体/配体准备策略、盒子、工具版本和 scoring function，运行前登记共晶重对接或筛选基准及通过标准；pose 可下载与科学基准分别验收。

### 4.3 MD 长任务链路（V2，FR-CADD-009）

流程：

```text
Molecular Docking
  -> MD Simulation
  -> Run Report
```

验收点：

- MD 预检展示 GPU、预计时长和超时。
- 任务提交到 SSH、K8s 或 Slurm Adapter。
- 用户可查看日志、取消任务、恢复状态。
- 输出 trajectory 和 report 可下载。
- 实际验收一个已交付执行器即可，不把 SSH 可用解释为 K8s/Slurm 全部可用；拓扑、力场、平衡与采样要求及科学复核独立记录。

## 5. 新工具接入验收

### 5.1 Remote API 自注册

步骤：

1. 管理员输入远端服务 URL。
2. 平台拉取 `/manifest`。
3. 平台校验 Tool Contract。
4. 平台拉取 `/examples`。
5. 平台执行 smoke run。
6. 工具进入工具库、工作流和智能体摘要。

验收点：

- 不需要管理员手写 schema。
- manifest 声明 Artifact 输入输出后自动生成节点槽位。
- async status、logs、cancel、artifacts 端点可用。
- smoke run 失败时工具保持未发布状态并展示原因。
- 含预测或评分的工具另附模型卡及环境/endpoint 证据；远端 manifest 自称科学已验证不作为可信证据。

### 5.2 Docker / SSH 工具注册

验收点：

- 注册时必须声明 Tool Contract。
- Docker 工具使用标准输入输出目录和 result manifest。
- SSH 工具支持上传、运行、日志、取消、输出回收。
- Resource Profile 能在任务预检中展示。

### 5.3 Tool Package 交付

验收点：

- Tool Package manifest 可转换为 Tool Contract。
- 权重、镜像、样例、资源画像可被平台读取。
- 不需要新增工作流适配代码。

## 6. 失败场景验收

| 场景 | 期望 |
| --- | --- |
| 上游未运行 | 下游显示等待上游，不误报语义错误 |
| 上游 Artifact type 不匹配 | 禁止连线或显示明确类型不匹配 |
| 缺少 required role | 提示需要准备工具或格式转换 |
| 工具契约 invalid | 节点不可运行，展示管理员修复入口 |
| 远端任务超时 | Task failed，日志可见，用户可重试 |
| 用户取消长任务 | 远端 cancel 生效，状态变 cancelled |
| 输出 manifest 缺文件 | 任务完成但 Artifact 校验失败，错误可诊断 |
| 登录过期导致渲染失败 | 提示重新登录，不显示空白或无限 loading |
| 历史 Artifact 缺少新科学 profile | 原契约读取/下载仍可用，科学比较显示 unknown 或缺失原因 |
| 预测值为空或部分分子失败 | 保留 source_row_id、error_code 和分母，不填零或静默过滤 |
| 评分协议不同或实验单位无法对齐 | 显示不可比较，不生成无依据综合分或误差 |

## 7. 前端 E2E 场景

必须覆盖：

- 工具详情页一键填入示例并运行。
- 工作流拖入 Fetch PDB、Protein Preparation、LVpocket 并自动连线。
- 节点独立运行上传文件。
- 保存 workflow，刷新后加载并恢复节点任务。
- 节点内预览和放大查看。
- 工具库动态标签筛选。
- 预检错误展示和修复动作。

## 8. 后端测试场景

必须覆盖：

- Tool Contract Builder 从 legacy artifacts 派生 capability。
- Binding Resolver 处理 ArtifactVersion、上传文件、上游节点和 workflow input。
- 无 project 标准输出进入默认工作空间。
- 有 input_bindings 时校验项目权限。
- 标准 Artifact required roles 校验。
- Remote API manifest、examples、invoke、status、cancel、artifacts 校验。
- V1：Docker/SSH/Remote API 状态映射和取消幂等；V2：已交付 K8s/Slurm Adapter 同类测试。

## 9. 发布前检查清单

1. 文档基线已更新。
2. 新工具有 Tool Contract 和 smoke example。
3. 新 Artifact 类型有 schema、roles、metadata 和 renderer 策略。
4. 工具详情页、节点独立运行、工作流运行使用同一输入模型。
5. 任务结果可持久化为标准 Artifact。
6. 保存工作流可恢复节点任务和 Artifact 绑定。
7. 关键链路通过前端 E2E。
8. 重计算工具支持日志、取消、超时和输出回收。
9. V1 交付模型卡、科学语义和真实环境证据，未验证内容如实登记；不把本规范里的示例当科学证据。
10. 已启用的科学 profile/new Artifact 具备兼容测试，不向旧 @1 数据追加无条件必填字段。

## 10. 科学与决策场景

| 场景 | 版本 | 数据与验收动作 |
| --- | --- | --- |
| AT-015 科学语义 | V1 | 样例同时含合法零值、失败 null、未知适用域和未定义手性；检查报告及导出，不混淆预测/实测/评分 |
| AT-016 模型证据 | V1 | 逐模型/endpoint/环境核对卡片和附件；Fake 只作契约证据，CPU smoke 不支持 DCU 声明，缺真实运行材料标未完成 |
| AT-017 科学基准 | V1.1 | 先固定数据版本、拆分、阈值、基线和容差，再运行并记录样本数、失败分母和审查结论；不能事后挑指标 |
| AT-018 候选决策 | V1.1 | 100 个固定候选、至少 3 类结果，含缺失/重复/不可比项；验证阈值、待复核、快照重开、导出一致性和越权；至少 3 名代表用户完成流程并记录耗时 |
| AT-019 实验回写 | V1.1 | CSV/JSON 含无效结构关联、重复测量、重复上传、不同批次；预览后确认有效子集，全无效只产报告，更正新建版本 |
| AT-020 预测实测 | V1.1 | 覆盖 nM/uM、IC50/Ki、不同 protocol、删失和重复；仅可比精确值算普通误差，原始值和排除原因可追踪 |
| AT-021 相似/聚类 | V2 | 固定指纹、标准化、算法、阈值与种子；验证可复核检索/聚类结果与版本 |
| AT-022 DMTA 复盘 | V2 | 候选决策 -> CompoundBatch -> assay -> 配对报告 -> 下一轮，验证关闭/重开与历史保存，无自动实验调用 |

实验回写的接受数、拒绝数、重复数与原始行数必须相符；多状态枚举另计生成状态数。科学门禁关注的是声明与证据是否匹配，不承诺通用命中率。

## 11. 证据归档格式

每次执行按场景记录产品版本、commit/构建摘要、目标环境、数据与参数版本、执行时间、执行人、结果（pass/fail/not_run）、证据链接、失败原因和复核人。科学场景另存模型卡、数据划分、输入输出摘要、指标、阈值/容差及适用范围。

需求-场景映射存在不代表验收通过。历史报告保留原日期和范围，在 [文档索引](../README.md) 的证据入口查阅；本次仅文档静态检查，不替代发布实测。
