# 验收流程与测试场景

## 1. 目标

本文件定义平台功能从“能跑”到“研发人员能顺手使用”的验收方式。验收不只看接口是否返回成功，还要验证工具注册、标准 Artifact、任务运行、工作流自动绑定、可视化、下载、取消和错误提示是否贯通。

## 2. 验收分层

| 层级 | 验收对象 | 主要问题 |
| --- | --- | --- |
| Contract | Tool Contract / Remote Manifest / Tool Package | 工具是否能被平台理解 |
| Binding | Artifact Slot / Run Context / Resolver | 输入输出是否能自动绑定 |
| Execution | Task / Executor / ResourceProfile | 任务是否能提交、运行、取消、回收 |
| Artifact | Standard Artifact / FileRole / Metadata | 输出是否可复用、可追踪、可下载 |
| Workflow | 节点、边、预检、保存恢复 | 用户是否只需拖节点、连线、补必要输入 |
| UX | 表单、节点面板、结果中心、错误文案 | 研发人员是否能理解和操作 |

## 3. P0 核心验收链路

### 3.1 外部数据库到口袋预测

流程：

```text
Fetch PDB
  -> Protein Preparation
  -> LVpocket Pocket Prediction
```

验收点：

- Fetch PDB 输入 PDB ID 后产出 `protein_structure@1`。
- Protein Preparation 自动接收上游 protein，产出 prepared roles。
- LVpocket 自动使用 prepared protein。
- 用户不手动填写文件路径、file_id 或 ArtifactVersion ID。
- 节点可独立运行。
- 保存工作流后重新加载，节点任务和 Artifact 绑定仍可见。
- 口袋结果可在节点内预览、放大查看和下载。

### 3.2 小分子查询和属性计算

流程：

```text
Fetch PubChem Ligand
  -> Ligand Preparation
  -> RDKit Properties
```

验收点：

- PubChem 查询支持 CID、名称或 SMILES。
- ligand 输出同时支持 2D 和 3D；无 3D 时 RDKit 生成并记录来源。
- RDKit Properties 作为平台内置节点运行。
- 输出 `molecule_table@1` 可表格查看和下载。

### 3.3 工具独立运行

场景：用户不进入项目，直接打开工具详情页运行 Fetch PDB 或 RDKit Properties。

验收点：

- 无 project 时允许上传或填写参数运行。
- 产出标准 Artifact 时自动进入用户默认工作空间。
- 不再出现“标准 Artifact 输入需要项目上下文”的硬阻断。
- 工具详情页保留“一键填入示例”。

### 3.4 节点独立运行

场景：用户在工作流画布中拖入一个节点，不连线，直接运行。

验收点：

- 节点面板有独立运行入口。
- 缺少标准输入时可上传文件或选择项目 Artifact。
- 普通参数从 schema 自动生成表单。
- 运行结果展示在节点和结果中心。

## 4. P1 药研连续流程验收

### 4.1 生成到 ADMET

流程：

```text
Fetch PDB
  -> Protein Preparation
  -> LVpocket
  -> Molecule Generation
  -> ADMET Prediction
  -> Toxicity Prediction
  -> Synthetic Accessibility
  -> Scoring Rerank
```

验收点：

- 分子生成自动使用 pocket。
- ADMET、毒性和合成可及性自动使用 molecule table。
- 打分重排可合并多个上游评分表。
- 结果中心按 Artifact 类型聚合。
- Agent 可以解释每一步输入输出，但不能绕过 Tool Contract。

### 4.2 对接链路

流程：

```text
Fetch PDB
  -> Protein Preparation
Fetch PubChem Ligand
  -> Ligand Preparation
Protein Preparation + Ligand Preparation + LVpocket
  -> Molecular Docking
  -> Scoring Rerank
```

验收点：

- Docking 缺 `receptor_pdbqt` 时提示先运行 Protein Preparation。
- Docking 可使用 pocket metadata 作为盒子中心。
- Docking 输出 pose 和 score table。
- 对接结果可查看、下载并进入重排。

### 4.3 MD 长任务链路

流程：

```text
Molecular Docking
  -> MD Simulation
  -> Run Report
```

验收点：

- MD 预检展示 GPU、预计时长和超时。
- 任务提交到 SSH、K8s 或 Slurm Adapter。
- 用户可查看日志、取消任务、恢复状态。
- 输出 trajectory 和 report 可下载。

## 5. 新工具接入验收

### 5.1 Remote API 自注册

步骤：

1. 管理员输入远端服务 URL。
2. 平台拉取 `/manifest`。
3. 平台校验 Tool Contract。
4. 平台拉取 `/examples`。
5. 平台执行 smoke run。
6. 工具进入工具库、工作流和智能体摘要。

验收点：

- 不需要管理员手写 schema。
- manifest 声明 Artifact 输入输出后自动生成节点槽位。
- async status、logs、cancel、artifacts 端点可用。
- smoke run 失败时工具保持未发布状态并展示原因。

### 5.2 Docker / SSH 工具注册

验收点：

- 注册时必须声明 Tool Contract。
- Docker 工具使用标准输入输出目录和 result manifest。
- SSH 工具支持上传、运行、日志、取消、输出回收。
- Resource Profile 能在任务预检中展示。

### 5.3 Tool Package 交付

验收点：

- Tool Package manifest 可转换为 Tool Contract。
- 权重、镜像、样例、资源画像可被平台读取。
- 不需要新增工作流适配代码。

## 6. 失败场景验收

| 场景 | 期望 |
| --- | --- |
| 上游未运行 | 下游显示等待上游，不误报语义错误 |
| 上游 Artifact type 不匹配 | 禁止连线或显示明确类型不匹配 |
| 缺少 required role | 提示需要准备工具或格式转换 |
| 工具契约 invalid | 节点不可运行，展示管理员修复入口 |
| 远端任务超时 | Task failed，日志可见，用户可重试 |
| 用户取消长任务 | 远端 cancel 生效，状态变 cancelled |
| 输出 manifest 缺文件 | 任务完成但 Artifact 校验失败，错误可诊断 |
| 登录过期导致渲染失败 | 提示重新登录，不显示空白或无限 loading |

## 7. 前端 E2E 场景

必须覆盖：

- 工具详情页一键填入示例并运行。
- 工作流拖入 Fetch PDB、Protein Preparation、LVpocket 并自动连线。
- 节点独立运行上传文件。
- 保存 workflow，刷新后加载并恢复节点任务。
- 节点内预览和放大查看。
- 工具库动态标签筛选。
- 预检错误展示和修复动作。

## 8. 后端测试场景

必须覆盖：

- Tool Contract Builder 从 legacy artifacts 派生 capability。
- Binding Resolver 处理 ArtifactVersion、上传文件、上游节点和 workflow input。
- 无 project 标准输出进入默认工作空间。
- 有 input_bindings 时校验项目权限。
- 标准 Artifact required roles 校验。
- Remote API manifest、examples、invoke、status、cancel、artifacts 校验。
- SSH/K8s/Slurm Adapter 状态映射和取消幂等。

## 9. 发布前检查清单

1. 文档基线已更新。
2. 新工具有 Tool Contract 和 smoke example。
3. 新 Artifact 类型有 schema、roles、metadata 和 renderer 策略。
4. 工具详情页、节点独立运行、工作流运行使用同一输入模型。
5. 任务结果可持久化为标准 Artifact。
6. 保存工作流可恢复节点任务和 Artifact 绑定。
7. 关键链路通过前端 E2E。
8. 重计算工具支持日志、取消、超时和输出回收。
