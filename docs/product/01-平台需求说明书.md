# AI 制药研发平台需求说明书

> 文档状态：基线草案；修订日期：2026-09-05；维护角色：产品负责人。本文件描述目标能力，产品版本、需求编号和交付范围以 [企业交付需求](../delivery/01-企业交付需求规格说明书.md) 为准，新增条款尚待实现和验收。

## 1. 产品定位

本平台定位为面向药物研发场景的 AI + CADD 科研工作台。平台不是单一模型演示系统，也不是简单任务队列，而是用于统一管理项目数据、标准 Artifact、算法工具、分布式计算任务、可视化结果、工作流编排、候选决策与智能体辅助研发的研发操作平台。

平台的核心价值是降低研发人员使用模型与开源计算工具的门槛，让蛋白结构、配体结构、口袋预测、分子生成、ADMET、毒性、合成可及性、分子对接、MD、打分重排等步骤可以在同一项目空间中沉淀数据、复用结果并追踪谱系。预测、评分和实验实测值必须保持不同科学语义，支持后续候选复核和实验反馈，而不替代 LIMS/ELN。

## 2. 目标用户

| 用户类型 | 主要目标 | 典型诉求 |
| --- | --- | --- |
| 药物研发科研人员 | 完成结构获取、口袋分析、虚拟筛选、性质评估等研发任务 | 不关心部署细节，能拖节点、传文件、看结果 |
| CADD / 计算化学人员 | 调用对接、MD、构象生成、分子处理等专业工具 | 能控制参数、复用已有 Artifact、导出下游格式 |
| AI 模型开发者 | 将新模型注册到平台并提供标准输入输出 | 不想为每个工作流单独做平台适配 |
| 平台管理员 | 管理工具、运行资源、项目权限和部署环境 | 工具可审核、资源可调度、任务可追踪 |
| 运维 / 集群管理员 | 管理 Docker、SSH、K8s、Slurm、对象存储和队列 | 计算资源可水平扩展、任务隔离可靠 |

## 3. 核心业务目标

1. **项目化研发**：所有重要数据、任务、工作流、白板和谱系应归属项目，支持后续复盘和协作。
2. **标准 Artifact 驱动**：平台定义标准 Artifact 类型、文件角色、元数据和校验规则，工具围绕标准 Artifact 输入输出对接。
3. **工具统一接入**：内置工具、Python、Docker、SSH、Remote API、自注册 API、Tool Package 都通过统一工具契约进入平台。
4. **工作流傻瓜化**：用户主要通过拖节点和连线表达流程，平台自动绑定上下游输入输出和必要数据格式。
5. **重计算资源可调度**：对接、MD、深度学习模型等重任务应支持 Docker、SSH、K8s、Slurm 等部署方式。
6. **结果可视化和可下载**：蛋白、配体、口袋、表格、报告、轨迹等结果应能在节点、任务和项目资产中查看。
7. **智能体辅助但不绑架流程**：智能体用于规划、推荐、解释和自动化草稿，但手动工作流仍是一等入口。
8. **科学证据可辨识**：平台区分契约验证、运行验证、科学基准验证和项目外部验证；预测、评分与实验数据均应保留证据等级、适用域和版本信息。

## 4. 核心使用场景

### 4.1 快速查询结构

用户在项目或工作台中查询 PDB、PubChem 等外部数据库，平台将下载结果保存为标准 Artifact。蛋白以 `protein_structure@1` 记录，配体以 `ligand_structure@1` 记录，并提供 2D/3D 可视化和下载入口。

### 4.2 工具独立运行

用户直接打开某个工具，填写参数、上传文件或选择项目 Artifact 后运行。工具可以无项目运行；若产生标准 Artifact，平台应自动给输出确定归属空间，优先使用显式项目，否则使用用户默认工作空间。

### 4.3 项目内工具运行

用户从项目进入工具，平台自动加载当前项目可兼容的 Artifact。用户可以选择已有 Artifact，也可以上传新文件作为输入。输出沉淀到当前项目，任务、文件和 Artifact 谱系可追踪。

### 4.4 工作流连续编排

用户拖入 Fetch PDB、蛋白处理、口袋预测、分子生成、ADMET、对接、MD、重排等节点。连线后平台依据标准 Artifact 类型自动绑定输入输出。只有流程边界缺少外部输入时才要求用户选择或上传。

### 4.5 新模型接入

模型开发者按平台标准编写 Tool Package 或 Remote API manifest，声明参数 schema、Artifact 输入输出、资源需求和样例。平台注册后，工具能自动出现在工具库和工作流节点库中，并自动参与上下游匹配。

### 4.6 候选复核与实验反馈

用户从候选分子表中查看结构、预测、评分、适用域和证据等级，保留入选或排除理由并导出候选清单。V1.1 起可导入受控的实验结果摘要，将预测与实测按分子身份、endpoint 和单位规则关联，形成下一轮设计的可复核输入。平台不管理实验仪器、样品库存或完整 ELN/LIMS 流程。

## 5. 功能性需求

### 5.1 项目空间

- 支持创建、归档、删除项目。
- 支持项目成员和角色权限。
- 聚合项目内任务、Artifact、工作流、白板、智能体会话和谱系。
- 所有项目内运行必须校验成员权限。

### 5.2 Artifact 管理

- 平台维护标准 Artifact registry。
- Artifact 必须记录类型、版本、文件角色、来源任务、创建人、项目和最新版本。
- 分子、预测、评分和实验结果必须保留稳定身份、单位、科学语义、工具或模型版本及证据等级。
- 支持多文件 Artifact，例如蛋白结构同时包含原始结构、处理后 PDB、PDBQT、元数据。
- 支持 ArtifactVersion、文件角色、谱系关系和可视化渲染。

### 5.3 工具中心

- 支持平台内置工具、用户工具和外部自注册工具。
- 支持 Python、Docker、SSH、Remote API、Tool Package 等执行方式。
- 支持工具版本、审核、分组、标签、示例、文档和契约校验。
- 含预测、生成、打分或筛选语义的工具必须提供模型卡或算法说明、适用范围和验证证据等级。
- 新工具必须声明参数输入和标准 Artifact 输入输出。

### 5.4 任务执行

- 支持创建、排队、运行、取消、重试和查看任务。
- 任务应记录运行参数、输入文件、Artifact 输入绑定、输出文件、标准 Artifact 输出和日志。
- 任务调度应屏蔽底层执行方式差异。
- 重任务应支持资源画像和远端执行。

### 5.5 工作流画布

- 支持自由拖拽工具节点。
- 支持节点独立运行和全流程运行。
- 支持保存、加载、恢复节点任务和历史运行。
- 支持根据标准 Artifact 自动绑定上下游输入输出。
- 支持预检、错误解释、自动修复建议和结果中心。

### 5.6 智能体

- 支持基于项目上下文理解用户意图。
- 支持生成工作流草稿、推荐工具、解释结果和提示缺失输入。
- 智能体输出必须可审查，不应绕过工具契约、权限和任务执行规则。

### 5.7 外部数据库

- 支持查询和导入 PDB、PubChem 等外部数据库记录。
- 外部数据库导入结果必须转化为平台标准 Artifact。
- 外部记录需要保留来源、ID、URL、下载时间和许可证/来源说明。

### 5.8 可视化和下载

- 支持蛋白、配体、口袋、分子表、报告等标准 Artifact 的差异化渲染。
- 工作流节点面板、任务详情、Artifact 详情和项目资产均可查看结果。
- 下载必须走权限校验和受保护文件接口。
- 候选表支持查看预测、评分、实验实测、适用域和证据等级，且不得混淆其科学含义。

### 5.9 候选决策与实验结果回写

- 支持以不可变 `molecule_id` 管理候选分子及其标准化状态。
- 支持记录筛选、保留、排除和导出候选的理由、操作者和时间。
- V1.1 支持受控 CSV/JSON 实验结果导入，记录 endpoint、单位、assay 语义、来源摘要和测量时间。
- 仅当分子身份、endpoint 与单位规则可对齐时，允许展示预测-实测比较；无法对齐时必须标记原因。

## 6. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 易用性 | 研发人员不需要理解底层部署、文件路径和队列细节 |
| 可扩展性 | 新工具通过标准契约接入，不应频繁修改工作流前端 |
| 可追踪性 | 任务、Artifact、工作流和智能体操作必须可追踪 |
| 安全性 | 项目数据隔离，下载和 Artifact 访问必须校验权限 |
| 可部署性 | 支持开发单机、Docker Compose、SSH 远端、K8s/Slurm 集群 |
| 可靠性 | 长时任务可恢复状态，失败原因可读，支持重试和取消 |
| 性能 | 大文件和重任务不阻塞 Web 服务，前端画布保持流畅 |
| 科学可信度 | 预测、评分、实验结果、适用域和证据等级分开存储、展示与导出，不能由运行成功替代科学验证 |

## 7. 当前优先级

### P0：平台主线重整

- 明确 Project、Tool、Task、Artifact、Workflow、Agent 的边界。
- 统一标准 Artifact 输入输出和运行上下文。
- 修复工具独立运行、项目运行、工作流运行三种入口的不一致。
- 交付两条基础链路：Fetch PDB -> 蛋白准备 -> LVpocket；Fetch PubChem -> 配体准备 -> RDKit -> 基础 ADMET。
- 基础 ADMET 固定真实 endpoint 和模型版本，支持单工具/工作流运行；科学语义、模型卡和验证范围可先以交付附件提供。

### P1：候选决策与人工反馈（V1.1）

- 分子生成。
- 扩展 ADMET / 毒性 / 合成可及性、多模型结果复核。
- 批量构象生成、评分重排、工作流模板。
- 候选多目标筛选、决策记录、模型质量看板和实验结果回写。

### P2：生产计算与多轮复盘（V2）

- Docker / SSH / API 基础统一属于 V1；V2 扩展 K8s / Slurm 和生产对接、MD。
- 结构相似搜索、聚类、DesignCycle 多轮复盘、外部实验系统引用和可执行 Agent 计划。

## 8. 验收标准

1. 用户可以在无项目情况下独立运行普通工具。
2. 用户可以在项目内选择已有 Artifact 或上传文件运行标准工具。
3. Fetch PDB -> Protein Preparation -> LVpocket 无需手动绑定字段，PubChem -> Ligand Preparation -> RDKit -> 基础 ADMET 同样贯通。
4. 新工具只要声明标准 Artifact 输入输出，即可被工作流发现并匹配。
5. 所有标准 Artifact 输出都能在项目或默认工作空间中找到归属。
6. 工作流加载后能恢复节点任务、结果和上下游绑定状态。
7. 管理员能理解工具、标签、分组、执行方式和部署资源的配置边界。
8. 含预测或评分的结果可追踪到输入、工具或模型版本、证据等级和适用域状态。
9. 对接、预测和实验实测结果不会被隐式合并或误标为同类科学证据。
