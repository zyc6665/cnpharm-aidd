# 平台功能模块说明书

## 1. 模块分层原则

平台功能按“科研业务入口 -> 平台能力中台 -> 执行与基础设施”分层。前端页面可以组合多个模块，但领域能力不应互相穿透。

核心原则：

- Project 是研发上下文。
- Artifact 是数据主线。
- Tool 是能力声明。
- Task 是执行实例。
- Workflow 是编排定义和运行记录。
- Agent 是辅助规划与解释入口，不直接替代任务系统。

## 2. 功能模块总览

| 模块 | 定位 | 主要用户 | 核心对象 |
| --- | --- | --- | --- |
| 项目空间 | 研发资产和协作上下文 | 科研人员、管理员 | Project、Member |
| Artifact 资产 | 标准科研数据管理 | 科研人员、工作流、工具 | Artifact、ArtifactVersion、FileRole |
| 工具中心 | 算法能力注册和使用 | 科研人员、模型开发者、管理员 | Tool、ToolVersion、ToolContract |
| 任务中心 | 单次执行实例管理 | 科研人员、运维 | Task、TaskInput、TaskOutput、Log |
| 工作流画布 | 多工具流程编排 | 科研人员、CADD 人员 | WorkflowDefinition、WorkflowRun、Node |
| 智能体 | 规划、解释和推荐 | 科研人员 | Conversation、AgentRun、Plan |
| 外部数据库 | 外部数据查询与导入 | 科研人员 | ExternalRecord、Imported Artifact |
| 可视化中心 | 标准结果查看和下载 | 科研人员 | Artifact Renderer、Task Result |
| 管理后台 | 平台运营和治理 | 管理员 | User、ToolGroup、Tag、Review |
| 资源调度 | 计算资源抽象 | 运维、平台 | Executor、Queue、ResourceProfile |

## 3. 功能设计总原则

平台功能不能只按数据库对象拆页面，而应按用户任务组织体验，按治理对象组织管理后台。

### 3.1 用户好用

- 常用入口优先：项目驾驶舱、需要关注任务、最近结果、常用工作流模板应优先出现。
- 输入自动化：从项目、工作流和上游 Artifact 自动带入上下文，只有缺少必要信息时才让用户选择。
- 预检可理解：缺输入、缺 role、需处理、需转换、权限不足、上游未完成应给出明确原因和下一步动作。
- 结果可复用：每个成功任务都应产生可查看、可下载、可进入下游的 Artifact 或报告。
- 大量数据可筛选：任务、Artifact、工具、工作流都必须支持搜索、筛选、分组、保存视图和批量操作。

### 3.2 管理好管

- 分类和标签可配置：工具分类、研发阶段、工作台分组、标签不得硬编码在前端。
- 发布有门禁：工具、Artifact type、role、renderer、executor 配置发布前必须校验。
- 质量可观察：管理员能看到工具成功率、失败原因、队列等待、存储增长和下载审计。
- 风险可控制：管理员能禁用工具、禁用 executor、限制资源、归档数据和追踪越权访问。
- 扩展有标准：新模型和新工具只通过 Tool Contract、Result Manifest、Artifact Registry、Renderer Registry 和 Executor 配置接入。

## 4. 项目空间模块

### 3.1 职责

项目空间负责组织研发资产、权限和上下文。项目不负责执行逻辑，不直接理解工具内部参数。

### 3.2 功能

- 创建、编辑、归档、删除项目。
- 项目成员管理和角色权限。
- 项目概览：任务、Artifact、工作流、白板、智能体会话。
- 项目驾驶舱：运行中任务、失败任务、最近结果、推荐下一步、项目统计。
- 项目级 Artifact 谱系。
- 从项目进入工具、工作流和智能体。
- 项目模板：靶点发现、结构处理、虚拟筛选、分子优化等模板。
- 项目活动流：任务运行、Artifact 生成、工作流变更、成员操作、Agent 审批。
- 项目归档和只读：归档后保留查看和下载，禁止新任务提交。

### 3.3 边界

- 项目只提供上下文和权限。
- 工具契约不应依赖固定项目。
- Artifact 输出必须有项目或默认工作空间归属。

## 5. Artifact 资产模块

### 4.1 职责

Artifact 模块是平台数据主线，负责将文件转化为可理解、可验证、可复用的科研资产。

### 4.2 标准 Artifact 类型

第一阶段保留现有类型：

- `protein_structure@1`
- `ligand_structure@1`
- `binding_pocket@1`
- `molecule_table@1`
- `run_report@1`

后续可扩展：

- `docking_pose@1`
- `docking_score_table@1`
- `md_trajectory@1`
- `admet_report@1`
- `toxicity_report@1`
- `protein_preparation_report@1`

### 4.3 功能

- 标准类型 registry。
- 多文件角色管理。
- ArtifactVersion 管理。
- 文件校验、摘要、元数据、指标。
- Artifact 谱系关系。
- 可视化渲染和下载。
- 上传和导入向导：识别类型、补 metadata、校验 role、生成 Artifact。
- 搜索和筛选：项目、类型、role、标签、来源、创建人、时间、任务、外部 ID。
- 版本对比：原始结构、处理后结构、转换格式和报告差异。
- 批量管理：打标签、归档、导出、移动/导入到项目。
- 生命周期治理：保留、过期、归档、清理策略。

### 4.4 边界

- Artifact 不负责调度任务。
- Artifact 不保存工具运行参数，参数属于 Task。
- Artifact 可以由外部数据库、上传、任务输出或工作流生成。

## 6. 工具中心模块

### 5.1 职责

工具中心负责描述和注册能力。工具不等于任务，工具只是可执行能力的声明。

### 5.2 工具接入方式

- 平台内置工具：如 RDKit 分子属性、Fetch PDB、蛋白处理。
- Python 工具：平台运行 Python 脚本或包。
- Docker 工具：通过容器镜像运行。
- SSH 工具：提交到远端服务器或集群登录节点。
- Remote API 工具：远端服务提供标准 manifest 和异步任务接口。
- Tool Package：推荐的新模型交付方式，声明标准 Artifact、参数和运行资源。

### 5.3 工具契约

工具契约包含：

- 身份：slug、name、version、description。
- 参数：`parameters_schema` 或 legacy `input_schema`。
- 标准输入：`artifacts.inputs`。
- 标准输出：`artifacts.outputs`。
- 资源画像：CPU、内存、GPU、预估时长、超时。
- 执行器：builtin、python、docker、ssh、remote_api、k8s、slurm。
- 交付格式：Tool Package 可转换为 Tool Contract，但不是执行器。
- 示例：参数、样例文件、样例 Artifact。

### 6.4 用户功能

- 工具库浏览：按研发阶段、能力、Artifact 输入输出、执行器、资源、标签筛选。
- 工具详情：展示用途、输入、输出、参数、资源、示例、最近任务和结果预览。
- 智能输入表单：展示必填项、默认值、单位、说明、错误、高级参数折叠。
- 一键填入示例：参数、样例文件、样例 Artifact 能直接填入并预检。
- 工具推荐：基于当前项目 Artifact 和用户目标推荐兼容工具。

### 6.5 管理功能

- 工具版本治理：草稿、验证、发布、禁用、废弃、回滚。
- 工具审核：Tool Contract、Artifact slots、Result Manifest、resource profile、smoke test。
- 分类标签治理：阶段、能力标签、工作台分组、显示顺序。
- 质量看板：运行次数、成功率、平均耗时、失败原因、用户反馈。
- Remote API 自注册：管理员填写 URL，平台拉取 manifest 并校验。

### 6.6 边界

- 工具不存放项目状态。
- 工具不直接生成工作流适配代码。
- 新工具应靠标准 Artifact 契约自动进入工作流。
- 工具中心不处理项目内 Artifact 选择，选择和预检由 Run Preparation 负责。

## 7. 任务中心模块

### 6.1 职责

任务是一次工具运行实例。任务负责保存运行输入、输出、日志、状态和资源调度信息。

### 6.2 功能

- 创建任务。
- 调度任务。
- 运行、取消、重试。
- 日志和进度。
- 输入输出记录。
- 标准 Artifact 输出持久化。
- 任务详情和结果查看。
- 任务总览看板：运行中、需要关注、今日完成、失败率、队列等待、重计算占用。
- 系统任务视图：我的任务、项目任务、工作流任务、运行中、需要关注、重计算队列、最近结果。
- 多维筛选：项目、工具、工作流、节点、状态、创建人、执行器、Artifact 类型、时间范围、标签。
- 分组和保存视图：按项目、工作流运行、工具、状态、执行器、日期分组，并保存常用视图。
- 任务详情侧栏：在列表中直接查看输入、输出、日志、Artifact、工作流节点和操作按钮。
- 批量操作和关注通知：批量取消、重试、归档、标记已处理，并对关注任务进行状态提醒。

### 6.3 查看模型

任务中心应按用户问题组织信息，而不是只按任务创建时间堆叠。

| 用户问题 | 推荐视图 | 关键字段 |
| --- | --- | --- |
| 我现在需要处理什么？ | 需要关注 | failed、preflight_failed、缺输入、输出校验失败、可重试 |
| 我的任务跑完了吗？ | 我的任务 | 创建人、参与项目、状态、最近更新时间 |
| 这个项目发生了什么？ | 项目任务 | 项目、工具、Artifact 输出、失败原因 |
| 这条工作流跑到哪一步了？ | 工作流任务 | WorkflowRun、节点、Node Task Binding、上游/下游状态 |
| 哪些任务占用资源？ | 重计算队列 | executor、queue、resource_profile、等待时长、运行时长 |
| 最近有什么可用结果？ | 最近结果 | 成功任务、输出 Artifact、报告、下载入口 |

### 6.4 输入来源

- 表单参数。
- 上传文件。
- 选择已有 ArtifactVersion。
- 工作流上游节点输出。
- 工作流外部输入。

### 6.5 边界

- 任务不决定工具可见性。
- 任务不负责长期业务分组，长期归属由 Project 和 Artifact 管理。
- 任务执行器只消费已准备好的运行请求。
- 任务中心的筛选和分组不应改变 Task、Artifact 或 Workflow 的真实归属。
- 工作流任务视图只展示 Node Task Binding，不应复制工作流调度规则。

## 8. 工作流画布模块

### 7.1 职责

工作流负责把多个工具节点组织成可保存、可运行、可恢复的研发流程。

### 7.2 功能

- 工具节点库。
- 画布拖拽和连线。
- 节点配置和独立运行。
- 全流程运行。
- 预检和错误解释。
- 运行状态同步。
- 节点任务恢复。
- 结果中心和节点内可视化。
- 工作流模板：常用药研流程模板、项目模板引用、另存和复制。
- 节点面板工作台：配置、预检、运行、结果、日志和 Artifact 预览。
- 调试运行：从失败节点继续、只运行下游、跳过已成功节点。
- 工作流版本：保存 contract snapshot、Node Task Binding、运行历史和版本说明。

### 7.3 自动绑定规则

- 节点输出 Artifact 类型匹配下游输入 slot 时自动绑定。
- 上游节点输出优先于工作流外部输入。
- 必填 slot 无上游来源时提升为工作流输入。
- 角色不满足时提示准备工具或转换工具。

### 7.4 边界

- 工作流不手写每个工具的适配逻辑。
- 工作流不直接处理文件格式转换，转换应由工具或 Binding Resolver 触发。
- 工作流只表达编排关系，执行仍由 Task 系统负责。

## 9. 智能体模块

### 8.1 职责

智能体是平台辅助层，负责理解意图、生成计划、推荐工具和解释结果。

### 8.2 功能

- 项目上下文问答。
- 工作流草稿生成。
- 工具推荐。
- 缺失输入提示。
- 结果解释。
- 计划审批。
- 缺失输入解释：基于 Run Preparation 的 Binding Decision 解释问题。
- 可执行计划校验：未通过预检的计划不能直接执行。
- 管理员可配置 Agent 可见工具、模板和禁用策略。

### 8.3 边界

- 智能体不能绕过工具契约。
- 智能体不能绕过权限。
- 智能体生成的工作流需要进入平台工作流定义和任务执行系统。

## 10. 外部数据库模块

### 9.1 职责

外部数据库模块负责查询外部科学数据库并将结果导入平台 Artifact。

### 9.2 第一阶段数据库

- RCSB PDB：蛋白结构。
- PubChem：小分子结构和基础属性。

### 9.3 输出

- 查询结果记录。
- 标准 Artifact。
- 元数据和来源信息。
- 可视化预览。
- 导入前预览：名称、结构摘要、来源、license/source 信息。
- 批量导入：批量 PDB ID、CID、SMILES 或 CSV，并生成导入报告。
- 缓存和刷新：复用已有外部记录，刷新时生成新版本或新导入记录。

## 11. 可视化中心模块

### 10.1 职责

可视化中心负责按 Artifact 类型渲染结果，而不是按工具硬编码结果。

### 10.2 渲染器

- Protein Renderer。
- Ligand Renderer。
- Binding Pocket Renderer。
- Molecule Table Renderer。
- Run Report Renderer。

### 10.3 使用位置

- Artifact 详情。
- 任务详情。
- 工作流节点面板。
- 工作流结果中心。
- 项目白板。

### 11.4 管理功能

- Renderer Registry：按 Artifact type/role 绑定渲染器。
- Preview 策略：大文件抽样、分页、异步生成预览。
- 下载策略：按 role 提供下载、批量打包、敏感文件控制。
- 缺 renderer 检查：新 Artifact type 发布前检查是否有可用展示策略。

## 12. 管理后台模块

### 11.1 职责

管理后台负责平台配置、用户、工具、标签、分组和审核。

### 11.2 功能

- 用户管理。
- 工具分类和分组。
- 标签管理。
- 工具审核。
- Tool Package 管理。
- 系统健康检查。
- 资源配置查看。
- Artifact 标准治理：type、role、metadata、validation、compatibility。
- Renderer 注册治理：Artifact type/role 到 renderer 的映射。
- 执行资源管理：executor、队列、并发、超时、资源 tier。
- 质量和使用统计：工具成功率、失败原因、任务耗时、队列等待、存储增长。
- 审计日志：工具发布、权限变更、Artifact 下载、任务取消、Agent 审批、配置变更。
- 数据治理：归档、保留、清理、配额和导出策略。

## 13. 资源调度模块

### 12.1 职责

资源调度模块负责把任务交给合适的执行环境。

### 12.2 执行环境

- 本地 direct：开发调试。
- Celery：生产任务队列。
- Docker：容器化工具。
- SSH：远程机器或集群登录节点。
- Remote API：模型服务自托管。
- K8s / Slurm：重计算集群调度，可先由 SSH Job 过渡，最终作为标准 Executor Adapter。

### 13.3 功能

- Executor Gateway：统一 submit、inspect、cancel、logs、collect。
- 队列和并发控制：按 executor、工具、资源 tier、用户、项目控制。
- 资源预检：展示资源画像、预估耗时、队列和超时。
- 长任务取消：Docker stop、SSH kill、Remote API cancel、K8s Job delete、Slurm scancel。
- 输出回收：按 Result Manifest 回收输出并持久化。
- 执行器健康：连接、队列、失败率、日志同步、输出回收状态。
- Remote API 安全注册：allowlist、超时、大小、重定向、checksum 控制。

### 13.4 边界

- 资源调度不理解业务流程。
- 工作流只提交任务，不直接调集群。
- 工具声明资源需求，调度器选择执行环境。
