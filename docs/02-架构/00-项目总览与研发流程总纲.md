## 1. 项目目标（引用并展开甲方确认版需求规格 V3.0）

> 规范书原文：本期建设中国医药 AI 药物研发平台，为药物研发团队提供统一工作环境，围绕研发项目和靶点，支持研发数据管理、蛋白结构分析、分子与多肽设计、性质预测、虚拟筛选、计算评估及结果管理，形成可复用、可追溯的研发流程，提升研发协同和计算分析效率。

拆解为四条可执行目标：

| 编号 | 目标 | 可度量口径 |
|---|---|---|
| G-1 | **统一工作环境**：研发人员在同一平台完成从靶点到候选物的全流程 | 7 大功能域在同一门户内可达，跨模块无需人工搬运文件 |
| G-2 | **可复用**：模型、工作流、数据集、候选物作为研发资产沉淀 | 工作流模板可保存并复用；候选集合可跨项目引用 |
| G-3 | **可追溯**：任一计算结果可回溯到输入数据、模型版本、工具版本、运行参数 | 结果详情页可一键还原「输入 + 参数 + 环境」三元组 |
| G-4 | **提效**：长时计算异步化，不阻塞人工操作 | 常规页面操作平均响应 ≤ 3 秒；计算任务提交后异步执行 |

## 3. 软件开发流程总览（SDLC）

本项目采用 **迭代式 + 阶段门禁（Stage Gate）** 的混合流程：整体按瀑布式阶段推进以保证合规与可追溯，模块内部按 2 周迭代交付。

```
立项启动 ──▶ 需求分析 ──▶ 系统设计 ──▶ 迭代开发 ──▶ 系统测试 ──▶ 部署上线 ──▶ 验收交付 ──▶ 运维与迭代
   │            │            │            │            │            │            │            │
   ▼            ▼            ▼            ▼            ▼            ▼            ▼            ▼
 立项书       PRD/需求矩阵  架构/DB/API  代码+单测    测试计划    部署方案    验收报告    运维手册
 项目计划     需求评审      设计评审     代码评审     测试报告    上线演练    用户培训    版本迭代
```

### 3.1 阶段门禁定义

| 阶段 | 入口条件 | 出口交付物 | 门禁评审方 |
|---|---|---|---|
| 立项启动 | 合同/任务书 | 项目计划书、里程碑表、团队与角色 | 甲方 PM + 我方 PM |
| 需求分析 | V3.0 需求规格说明书（`AIYF-SRS-001`） | PRD、需求追踪矩阵、需求评审记录 | 甲方业务专家 + 我方产品 |
| 系统设计 | PRD 基线化 | 架构设计、数据模型、API 规格、UI 原型 | 架构评审委员会 |
| 迭代开发 | 设计基线化 | 源码、单元测试、接口文档、迭代演示 | 技术负责人 |
| 系统测试 | 功能冻结 | 测试计划、测试用例、测试报告、缺陷清单 | 测试负责人 + 甲方 |
| 部署上线 | 测试通过 | 部署方案、上线演练记录、回滚预案 | 运维 + 甲方 IT |
| 验收交付 | 上线稳定运行 | 验收报告、用户手册、培训记录 | 甲方验收组 |
| 运维迭代 | 验收通过 | 运维手册、监控告警、迭代 backlog | 运维团队 |

## 7. 需求变更与基线管理

1. **基线规则**：PRD 经甲方评审通过后即为需求基线，纳入《需求追踪矩阵》管理。
2. **变更流程**：变更申请 → 影响分析（范围/工期/算力/成本）→ 变更评审 → 基线更新 → 矩阵同步。
3. **矩阵纪律**：任何新增需求必须先分配编号并写入矩阵，未入矩阵的需求不得进入开发排期。
4. **★ 专项不可裁剪**：V3.0 §5.1~§5.4 四个 ★ 关键指标专项（见《02-需求追踪矩阵》§3）属不可裁剪项，任何偏离需甲方书面确认。

## 8. 关键技术约束（需在设计阶段持续校验）

| 约束 | 说明 | 影响 |
|---|---|---|
| 国产算力 | 海光 K100-AI DCU；**实测基线 DTK 26.04 + PyTorch 2.7.1（HIP 6.3.26045）** | 已完成一轮兼容性验证，但**测试机已回收、成果未资产化** → 见 `08-DCU适配复现与验证计划` |
| 已知不可用路径 | AlphaFold-DCU（输出 NaN）、OpenFE/OpenMM-GPU（NVRTC/HIPRTC 失败） | 结构预测改用 Boltz-2；自由能改用 GROMACS + gmx_MMPBSA |
| 离线内网 | 无外网访问 | 镜像、依赖包、模型权重需离线交付；Harbor + 内网 PyPI 镜像为必备件 |
| 版本锁定 | DTK 与 PyTorch 版本强绑定；**禁止 pip 覆盖 torch/dgl/tensorflow** | 计算镜像版本矩阵需固化，禁止随意升级 |
| 许可合规 | 商业交付 | 需做开源许可证审查（GPL/AGPL 组件隔离），见架构文档第 9 章 |
| 数据安全 | 研发数据不出内网 | 禁止任何形式的外部 API 调用；所有模型本地化部署 |
| 资源上限 | 16 张 DCU、总显存 1024GB | 任务并发与显存分配策略需显式设计，见架构文档第 5 章 |
