## 🔧 技术实施细节

### 1. Docker Compose服务架构

#### 服务1: Redis消息队列
```yaml
服务名: scitool-redis
镜像: redis:7-alpine
端口: 6379
密码: scitool123（生产环境需修改）
持久化: AOF + RDB双重保护
内存限制: 2GB（可调整）
内存策略: allkeys-lru（LRU淘汰）
健康检查: 10秒间隔，3次重试
```

**关键配置**:
- `--appendonly yes`: 启用AOF持久化
- `--appendfsync everysec`: 每秒同步一次到磁盘
- `--maxmemory 2gb`: 内存上限2GB
- `--requirepass scitool123`: Redis认证密码

#### 服务2: Celery Worker（默认队列）
```yaml
服务名: scitool-celery-worker
基础镜像: scitool-backend:latest
并发数: 4（prefork进程池）
队列: default
任务限制: 每个worker最多执行50个任务后重启
```

**挂载卷**:
- `./backend/storage:/app/storage` - 共享数据库
- `./backend/storage/uploads:/app/storage/uploads` - 共享上传文件
- `/var/run/docker.sock:/var/run/docker.sock` - Docker执行器需要

#### 服务3: Celery Worker（GPU队列）
```yaml
服务名: scitool-celery-worker-gpu
并发数: 1（GPU任务串行执行）
队列: gpu_queue
GPU配置: NVIDIA Container Toolkit
```

**GPU资源分配**:
```yaml
deploy:
  resources:
    reservations:
      devices:
        - driver: nvidia
          count: 1
          capabilities: [gpu]
```

#### 服务4: Flower监控面板
```yaml
服务名: scitool-flower
镜像: mher/flower:2.0
端口: 5555
认证: Basic Auth (admin/scitool123)
```

**方式一：使用启动脚本**（推荐）

**方式二：手动启动**
```bash
# 1. 检查网络
docker network inspect cpumodel

# 2. 启动服务
docker-compose -f docker-compose.celery.yml up -d

# 3. 查看状态
docker-compose -f docker-compose.celery.yml ps

# 4. 查看日志
docker-compose -f docker-compose.celery.yml logs -f
```

### 常用管理命令

```bash
# 停止服务
docker-compose -f docker-compose.celery.yml down

# 重启服务
docker-compose -f docker-compose.celery.yml restart

# 查看活跃任务
docker-compose -f docker-compose.celery.yml exec celery-worker \
  celery -A app.celery_app.celery_app inspect active

# 查看Worker统计
docker-compose -f docker-compose.celery.yml exec celery-worker \
  celery -A app.celery_app.celery_app inspect stats
```

## 🐛 已知问题和解决方案

### 问题1: cpumodel网络不存在
**症状**: 启动时报错 `network cpumodel declared as external, but could not be found`

**解决方案**:
```bash
docker network create cpumodel
```

### 问题2: 端口冲突
**症状**: `Error starting userland proxy: listen tcp4 0.0.0.0:6379: bind: address already in use`

**解决方案**:
- 检查端口占用: `netstat -nltp | grep 6379`
- 修改端口映射或停止冲突服务

### 问题3: GPU Worker启动失败
**症状**: `could not select device driver "" with capabilities: [[gpu]]`

**解决方案**:
- 检查NVIDIA驱动: `nvidia-smi`
- 安装NVIDIA Container Toolkit
- 如无GPU，注释掉docker-compose.celery.yml中的`celery-worker-gpu`服务
