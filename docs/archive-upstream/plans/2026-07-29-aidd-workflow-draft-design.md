# AIDD 工作流草稿生成设计

## 背景

平台已经具备 AIDD 规划、工具契约、工作流模板和工作流执行能力，但 AIDD 当前只能在规划后立即创建运行并调度任务。用户无法先把智能体建议转换为可编辑工作流，再审查、调整、保存或执行。

## 目标

- 根据用户目标和已上传的科学文件生成可执行的工作流草稿。
- 生成阶段不创建 `AgentRun`、`AgentRunStep`、`WorkflowTemplate`、`WorkflowRun` 或 `Task`。
- 草稿进入现有手动工作流画布，用户保留最终编辑、保存和执行决定。
- 工具节点引用真实的已发布工具及版本快照，不输出无法执行的占位节点。

## 方案比较

### 方案一：复用智能体运行创建接口

改动最少，但 `create_agent_run` 会持久化运行并立即调度首批任务。生成草稿本应是可撤销的规划操作，该方案会产生任务和产物副作用，因此不采用。

### 方案二：前端根据智能体计划拼装工作流

后端接口较少，但前端需要复制语义输入解析、工具版本解析、DAG 校验和兼容规则。两套契约会随工具扩展而漂移，因此不采用。

### 方案三：后端提供只规划的工作流草稿接口

新增 `POST /api/v1/agents/aidd/workflow-drafts`，复用 AIDD 的输入分类和计划构建，在后端把计划转换为经过校验的工作流定义。前端只负责展示和编辑。该方案职责清晰、可测试并保持单一契约，因此采用。

## 后端设计

### 规划准备

从 `create_agent_run` 提取共享的计划准备函数，统一完成：

- 输入文件所有权检查与语义分类；
- 请求输出语义归一化；
- LangGraph 规划调用；
- 可用工具契约加载；
- 计划及工具契约追踪信息构建。

现有运行创建继续消费该结果并持久化、调度；草稿创建只消费该结果并转换定义。

### 草稿定义

响应包含：

- `name`、`description` 和 `intent`；
- `definition.nodes`、`definition.edges`；
- `input_files`，用于在手动运行面板中预填已上传文件；
- `requested_outputs`、`reasoning_summary` 和 `analysis_trace`，用于解释草稿来源。

转换规则：

- 每种实际使用的工作流输入生成一个 `kind=input` 节点；
- 每个 AIDD 步骤生成一个 `kind=tool` 节点；
- `agent_input[:semantic_type]` 转为 `workflow_input:semantic_type`；
- `step:step_key:semantic_output` 转为 `node:step_key:semantic_output`；
- 依赖关系生成稳定 ID 的边；
- 节点按拓扑层级确定性布局，重复请求不会产生随机漂移；
- 工具节点保存真实 `tool_id`、`tool_slug`、当前版本快照和输出契约；
- 返回前调用 `validate_workflow_definition`，拒绝循环、未知引用和缺失工具。

### 内置工具边界

AIDD 的虚拟能力在草稿中必须解析为已持久化的平台 `builtin` 工具。必要时沿用 `ensure_aidd_builtin_tool` 创建幂等的平台工具记录；该操作不会创建用户运行或任务。

平台内置工具保持 `is_public=false`，避免出现在公共工具目录。工作流调度器只额外接受满足以下全部条件的私有工具：

- `provider_type=platform`；
- 当前版本执行器 `type=builtin`；
- 工具已发布且当前版本处于活动、未弃用状态。

普通私有工具仍不可通过工作流绕过可见性限制。

## 前端设计

`AiddAgentPanel` 保留现有“立即运行”主操作，新增“生成工作流草稿”次操作。两个操作复用文件上传逻辑，但状态独立，避免生成草稿时触发运行加载态。

草稿成功后组件向工作流页面发送事件。页面清除当前持久化模板选择，应用返回定义，设置草稿名称，预填工作流输入文件，并切换到手动模式。草稿不会自动保存或执行。

## 错误与安全

- 未认证、越权文件、无有效输入、规划失败、工具不可用和定义校验失败均返回现有结构化错误。
- 不以占位成功掩盖缺失执行器；无法解析为真实工具时整次草稿生成失败。
- 不返回隐藏推理链，只返回现有面向用户的 `reasoning_summary` 与 `analysis_trace`。

## 验证

- 纯转换测试覆盖多输入、串行/分支依赖、稳定布局和非法来源。
- 服务/API 测试证明草稿可执行引用真实工具，且不创建运行、模板或任务。
- 调度测试证明平台 builtin 可执行、普通私有工具仍被拒绝。
- 前端测试覆盖 API、独立加载态、事件、模式切换、画布应用和输入预填。
- 运行后端全量测试、前端全量测试和生产构建。
