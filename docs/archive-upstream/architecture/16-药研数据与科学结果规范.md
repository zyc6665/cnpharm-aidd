## 1. 目标与边界

本规范定义药物研发结果在平台内的最小科学语义，保证候选分子、预测结果、对接评分和实验结果可比较、可复核、可追踪。

本规范不定义实验室原始记录、样品库存或仪器控制流程，不替代 LIMS/ELN。平台只管理进入研发决策链路的数据副本、来源和关联。

## 2. 科学证据分级

平台必须将工程可用性与科学可信度分开表达。任何页面、报告或 Agent 输出均不得把低等级证据表述为已验证的科学结论。

| 等级 | 名称 | 证明内容 | 不证明内容 |
| --- | --- | --- | --- |
| E0 | 未验证 | 仅有工具或模型说明 | 无可复现运行证据 |
| E1 | 契约验证 | Contract、Result Manifest、Artifact 校验通过 | 模型可在真实环境运行或结果准确 |
| E2 | 运行验证 | 受控输入可完成运行并产出可追踪结果 | 模型预测有效或跨硬件数值一致 |
| E3 | 科学基准验证 | 固定基准或黄金样例达到预定义指标或容差 | 对新靶点、新化学空间一定有效 |
| E4 | 项目外部验证 | 项目独立数据或实验结果与预测形成可审查对比 | 临床有效性或最终成药结论 |

E0-E4 为本平台拟定的证据展示规则，不是行业认证。发布状态与证据等级独立；每项证据必须限定工具/模型版本、endpoint、输入准备策略、数据集、硬件环境、运行日期和审查人。`engineering_status`（contract/runtime）和 `scientific_status`（benchmark/external）分别记录。一个版本可有论文基准而目标 DCU 运行失败，不能用单一最高等级隐藏失败；E3/E4 标签须同时满足其声明运行环境的 G1/G2。

E4 仅指独立、可审查且达到预登记要求的外部验证；导入实验、完成配对或观察到相关性都不自动升级证据。`unknown`、`failed`、`not_tested` 必须保留，不得按等级排序取最大值替代。

## 3. 分子身份与候选集合

候选集合的每个输入行使用稳定 `source_row_id`，有效结构关联项目内 `molecule_id`、`structure_state_id`，构象另用 `conformer_id`。`molecule_id` 标识候选身份，不能仅由文件行号或名称生成；状态、构象、pose 一对多时保留父子关系。同一状态在不同任务中不得反复分配无关联的新身份。

最低字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `source_row_id` | 是 | 原始导入/生成行标识；无法解析结构时仍保留 |
| `molecule_id` | 有效结构必填 | 平台稳定分子标识；候选表中按 molecule/state 唯一，评分明细允许同分子多 endpoint/pose |
| `canonical_smiles` | 有效结构必填 | 保留原始输入，记录所用化学工具及版本；解析失败不能编造 SMILES |
| `isomeric_smiles` | 建议 | 保留立体化学的结构表达 |
| `structure_state_id` | 有效结构必填 | 盐型、质子化、互变异构体和立体化学状态；构象用独立 conformer_id |
| `source_molecule_id` | 否 | 上游生成或导入批次中的原始标识 |
| `compound_name` | 否 | 人类可读名称，不作为唯一键 |
| `standardization_profile` | 是 | 标准化、去盐、加氢、质子化和互变异构体策略版本 |
| `deduplication_key` | 有效结构必填 | 明确按结构状态、工具和策略版本生成；跨策略不自动合并 |
| `generation_status` | 是 | `valid`、`invalid`、`filtered` 或 `failed` |
| `failure_reason` | 条件必填 | 失败或过滤时记录机器可读原因 |

批量处理必须保留失败分子和过滤原因，不能因只导出成功项而丢失分母。可用独立拒绝表保存无结构行，通过 source_row_id 关联；必须满足输入数等于有效输出、重复排除、规则过滤和失败数之和。枚举多个状态时分别报告输入行数与生成状态数，不能混算分母。

## 4. 预测结果语义

预测、规则计算或模型推理的每个 endpoint 都必须带有下列字段。表格可以宽表呈现，但导出和 API 必须能恢复这些语义。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `endpoint_id` | 是 | 稳定 endpoint 标识，例如 `herg_inhibition` |
| `endpoint_name` | 是 | 展示名称 |
| `prediction_kind` | 是 | `classification`、`regression`、`ranking` 或 `rule` |
| `prediction_status` | 是 | `succeeded`、`failed`、`not_evaluated`；失败时保存 error_code |
| `predicted_value` | 成功时必填 | 原始预测值；失败/未预测为 null，绝不能填 0 |
| `value_unit` | 条件必填 | 回归或物理量必须声明单位；分类可为 `probability` 或 `label` |
| `decision_direction` | 是 | `higher_is_better`、`lower_is_better`、`within_range` 或 `informational` |
| `threshold` | 条件必填 | 有阈值决策时声明阈值和比较符 |
| `uncertainty` | 是 | status 为 available/unavailable；可用时给 method、区间/标准差、coverage 与校准数据引用，概率值本身不等于置信区间 |
| `applicability_domain` | 是 | `in_domain`、`out_of_domain`、`unknown` 或具体距离/规则 |
| `model_version` | 是 | 模型或规则版本 |
| `model_weights_digest` | 条件必填 | 有权重的模型必须提供权重摘要 |
| `input_artifact_version_id` | 是 | 预测输入的不可变 ArtifactVersion 引用 |
| `task_id` | 是 | 产生该结果的 Task 引用 |

endpoint 定义还需 `target_id`、`species_or_system`、`assay_family`、分类阳性标签、量纲及变换约定；不适用明确标注，未知不能臆造。例如 log 浓度必须说明对数底数、原始浓度单位和变换公式。模型不提供适用域估计时填 unknown 并给出原因，不伪造 in_domain。适用域状态、预测置信区间和模型性能指标分别存储。

预测值用于研发优先级排序，不得在没有相应科学证据时展示为实验实测值、结合常数或临床结论。

## 5. 评分与重排

`docking_score_table@1`、`molecule_table@1` 中的评分列，以及重排输出，必须同时提供 `score_definition`。评分名称相同不表示数值可直接比较。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `score_id` | 是 | 稳定评分标识 |
| `score_name` | 是 | 展示名称 |
| `source_tool` | 是 | 产生分数的工具及版本 |
| `raw_value` | 是 | 原始值，禁止先覆盖为归一化值 |
| `unit` | 是 | 量纲或 `dimensionless` |
| `direction` | 是 | `ascending`、`descending` 或 `informational` |
| `normalization_method` | 是 | `none`、min-max、z-score、rank 或已登记方法 |
| `normalization_scope` | 条件必填 | 使用归一化时说明作用的候选集合和版本 |
| `weight` | 条件必填 | 综合重排时声明权重与版本 |
| `comparability_scope` | 是 | `same_tool_same_setup`、`same_project_protocol` 或 `not_comparable` |

跨工具或不同 preparation profile 的对接能量默认 `not_comparable`。平台可以并列展示和进行人工审查，但不得隐式合并成统一物理能量。

重排协议必须固定候选集合版本、参与列、工具/模型和受体版本、硬约束、分数方向、变换、缺失策略、权重、并列规则及审批人。V1.1 可先用可解释的阈值筛选和单列排序；综合分数必须标记为项目决策分数，不解释为实验亲和力。

- 归一化仅对声明兼容的数值执行；无量纲化不会消除科学不可比性。
- min-max 或 z-score 的样本范围、最值/均值/标准差要冻结；范围为零或样本不足时拒绝该归一化并解释。
- 权重须有限、非负且至少一个大于零；输出实际使用的归一化权重。
- 缺失数据默认转待复核，不填零、不静默重分配权重。显式排除时保留原因和分母。
- 硬约束先于排序；并列时按稳定 molecule/state 标识排序，保留原始分数与排名依据。
- 重排以 molecule/state、endpoint、模型和 pose 等复合键联结；不能按 CSV 行号拼接，不能让一对多连接重复放大候选。

## 6. 实验结果回写

实验结果使用 `assay_result@1` 表示。首期仅要求从受控 CSV/JSON 导入，不要求连接仪器或替代 ELN/LIMS。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `measurement_id` | 是 | 不可变测量记录标识 |
| `molecule_id` | 是 | 与候选分子稳定关联 |
| `structure_state_id` | 是 | 实测结构状态；未知时不自动配对预测 |
| `compound_batch_id` | 是 | 外部或项目批次标识；无法获知时标 unknown 并要求复核 |
| `assay_endpoint_id` | 是 | 受控 endpoint 标识 |
| `measured_value` | 条件必填 | 精确值或单侧界限；range 使用 lower/upper，not_detected 可为 null 并记录检出限 |
| `value_unit` | 是 | 单位 |
| `qualifier` | 是 | `=`、`<`、`>`、`range` 或 `not_detected` |
| `assay_type` | 是 | 结合、细胞、酶、ADME、毒性等 |
| `species_or_system` | 是 | 物种、细胞系或实验体系；unknown 数据保留但禁止自动误差比较 |
| `protocol_reference` | 是 | 协议及版本或外部 ELN/LIMS 引用；缺失转待复核 |
| `replicate_id` | 是 | 技术/生物重复及重复组；汇总值需指向原始重复记录和聚合方法 |
| `measured_at` | 是 | 实测日期或时间 |
| `source_record_digest` | 是 | 导入文件或外部记录摘要 |

预测与实测只有在 `molecule_id`、endpoint、单位转换规则和 assay 语义可对齐时才能形成比较记录；无法对齐时必须标记原因。

实测不要求 task_id；由导入事件、原始文件版本和操作者追溯。更正数据生成新 ArtifactVersion，并注明 supersedes，不覆盖原始测量。候选结构身份不等同实物样品身份，不得跨批次静默合并实验值。

### 6.1 配对与误差规则

配对键包含 molecule/state、目标、endpoint 定义版本、protocol/assay family、物种或体系、单位/变换规则，以及实际预测版本。IC50、EC50、Ki、Kd 即使单位相同也不得直接替换；协议兼容性由科学负责人确认。蛋白状态或盐型差异要可见。

`<`、`>`、range、not_detected 是删失或区间观测，保留原始 qualifier；V1.1 仅精确且可比的数值参与普通 MAE/RMSE，其他值可展示但计入排除统计。重复实验逐条保留，未经固定聚合协议不得取均值。标准化后预测和实测均保留原值、原单位、转换公式和新值。

### 6.2 导入事务与权限

导入流程为上传暂存 -> 列映射/类型校验 -> 行级预览 -> 用户确认有效子集 -> 创建不可变版本及拒绝报告。幂等键为项目、源文件摘要、映射/协议版本；相同请求返回原记录，不重复计数。改变映射必须创建新导入版本并保留关系。无效行不能让有效行无声消失；全无效时只保存导入报告，不发布可用实测表。

项目成员可按角色上传，科学负责人审核用于比较的记录；读取、下载、导出和关联校验同一项目权限。未获授权的外部来源不得由 Agent 自动导入或传给第三方模型。

## 7. 可复现性与谱系

每一份可用于项目决策的预测、评分或实验结果都必须能够定位到：

1. 输入 ArtifactVersion、分子标准化策略和候选集合版本。
2. Tool Contract、工具版本、模型版本和权重摘要。
3. 计算结果的 Task 参数、随机种子或显式不适用原因；实测走导入事件和协议，不伪造 Task 或 seed。
4. 执行环境摘要，包括镜像、依赖、硬件和驱动版本。
5. 结果 ArtifactVersion、生成时间、操作者和科学证据等级。

## 8. 版本治理

- 字段新增且可选时，保持 Artifact major version 不变。
- 改变字段语义、单位、去重规则或 endpoint 定义时，必须新增 schema version 或 Artifact major version。
- 模型权重、训练数据、阈值或标准化配置变化必须产生新的 ToolVersion 或 model version，不得覆盖历史结果。

### 8.1 与当前标准的兼容

本文定义拟议 `scientific-result.v1` 语义 profile，不直接改变当前 `molecule_table@1` 和 Tool Contract v2 的必填 schema。V1 允许通过 `metadata_json`、`run_report@1` 或交付附件承载，V1.1 再实施 profile 校验器、registry 和页面。未声明该 profile 的历史产物可继续读取、下载和按原契约使用；科学信息不足时标 unknown，阻止需要该信息的比较或排序，而非删除旧资产。

新发布版本声明 profile 后必须满足本规范。存量数据补齐需显式映射、生成新版本和验证记录；不能直接为旧数据推定证据或单位。新增 assay_result、docking_score_table、admet_report 等类型须先发布 schema、roles、校验器、样例和 renderer，再进入可运行契约。

## 9. 科学与体验验收

| 场景 | 可复核期望 |
| --- | --- |
| 输入含坏 SMILES、重复结构、未知手性 | 原始行不丢失；重复、过滤、失败分母可还原，未知手性不静默变确定结构 |
| 分数来自不同 Vina/AD4 scoring 或不同受体 | 并列展示来源，禁止直接合并能量；项目排名需独立协议 |
| ADMET 预测失败或 OOD 未评估 | 值为 null 或原预测且带状态；不自动视作安全/有效 |
| 同分子多个 endpoint、模型或 pose | 复合键联结，不发生按行错配或重复膨胀 |
| 实验包含 nM、uM、IC50、Ki、删失值和重复 | 仅批准的可比子集参与误差统计；转换和排除原因可追踪 |
| 同文件重复导入或修正映射 | 前者幂等，后者新版本；无静默覆盖 |

上述为拟定验收要求，具体测试编号及版本见 [交付需求](../delivery/01-企业交付需求规格说明书.md) 的 AT-015 至 AT-023。

## 10. 依据与适用性

- [AutoDock Vina 官方对接教程](https://autodock-vina.readthedocs.io/en/stable/docking_basic.html) 指出不同 scoring forcefield 的能量不能直接比较；据此，本平台要求声明评分可比范围。
- [TDC ADMET Benchmark](https://tdcommons.ai/benchmark/admet_group/overview/) 提供按任务划分的数据、拆分和评价指标；本平台采用 endpoint 级评估记录，不把不同任务压成单一“准确率”。

字段名、证据等级和交付版本是本项目产品设计，以上来源不构成对平台或已接入模型的验证背书。
