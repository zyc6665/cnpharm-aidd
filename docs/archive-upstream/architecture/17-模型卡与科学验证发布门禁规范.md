## 1. 目的

本规范约束 AI 模型、规则工具和 CADD 工具的科学说明、验证证据和发布门禁。Tool Contract 回答“如何运行”，模型卡回答“适用于什么、证据到什么程度、结果应如何解释”。

## 2. 模型卡最小内容

每个含预测、生成、打分或筛选语义的 ToolVersion 必须关联不可变模型卡快照。传统确定性工具也必须声明算法版本、输入假设和已知限制。

| 内容 | 必填 | 说明 |
| --- | --- | --- |
| 工具与模型身份 | 是 | tool slug、ToolVersion、模型/算法版本、权重摘要 |
| 任务定义 | 是 | 输入、输出、endpoint、单位、预测类型和决策方向 |
| 使用范围 | 是 | 适用靶点、分子类型、化学空间、输入准备条件 |
| 训练或规则来源 | 是 | 数据/代码/权重各自来源、许可证、可用范围和数据截止日期；未知明确标 unknown；非学习工具说明算法来源 |
| 评估设计 | 是 | 已有评估数据划分、独立测试集、指标、基线、样本量和种子；未开展时写 not_tested 及计划，不能填造指标 |
| 已知限制 | 是 | OOD、缺失立体化学、质子化、构象、物种、assay 差异等限制 |
| 推理运行要求 | 是 | 运行环境、硬件、资源、预期耗时和已验证平台 |
| 证据等级 | 是 | 采用 E0-E4，并链接验证记录 |
| 责任信息 | 是 | 模型维护者、科学审查人、最近复核日期 |

学习模型还应记录预处理、训练/验证/测试数据版本摘要和可能重叠；不能公开的数据以权限受控引用保留，不能把含机密结构的样例发到未经授权的外部评估服务。生成模型记录生成有效率、唯一性、多样性、训练集新颖性和条件满足情况，指标需有明确分母。预测的校准信息、适用域方法及无法提供的不确定性均要说明。

## 3. 发布门禁

工具发布分为平台发布和科学声明发布。前者保证平台安全、可运行和可追踪；后者决定能否向用户展示性能指标、推荐阈值或决策建议。

| 门禁 | 最低要求 | 通过后允许的声明 |
| --- | --- | --- |
| G1 契约门禁 | Tool Contract、Artifact slots、Result Manifest、权限和资源画像校验通过 | 声明该版本平台契约已验；Fake 执行只能支持此范围 |
| G2 运行门禁 | 真实工具、固定 smoke input、环境摘要、日志、输入输出 hash 和失败处理记录 | 声明该具体环境可运行；CPU 通过不代表 DCU 通过 |
| G3 科学基准门禁 | 预先登记的 benchmark、指标、比较基线、容差和审查结论 | 在限定数据/endpoint/环境内声明平台已复核基准表现 |
| G4 项目验证门禁 | 独立项目数据或实验回写，且预测-实测对齐、样本量和通过标准可审查 | 在限定项目和协议内声明外部验证，记录通过与不通过结果 |

G1/G2 通过且用途/许可证经过审查的工具可供受控运行，但必须带证据范围和局限说明。没有 G3 的模型可以引用来源明确的论文指标，标签须为“作者报告，平台未复核”，不能显示为平台验证结果。默认推荐阈值需对应的任务数据、代价假设和科学审核；G3 本身不授权任意阈值。G4 不外推为临床或全局有效性。

上述门禁是验证记录，不能给当前 Tool 或 Task 擅自添加状态枚举。V1 使用交付附件和人工发布记录；V1.1 自动校验结果进入现有工具审核流程。科学验证失败可以限制用途或撤回版本，不能把一批正常完成推理的历史 Task 改成执行失败。

## 4. 基准与数值复核

- 基准数据、数据划分、指标、容差和判定规则必须在运行前登记，不能根据结果事后选择。
- 分类任务记录 AUROC、AUPRC、阈值、灵敏度和特异性；回归任务记录 MAE/RMSE、相关性、单位和误差分布。具体指标取决于任务定义。
- 化学泛化评估应优先使用能揭示结构外推风险的拆分策略，并明确写出随机、scaffold、时间或项目独立拆分。
- 有随机性的工具必须声明种子、重复次数和汇总方式；无法固定时记录原因。
- 硬件迁移验证必须区分“流程可运行”和“数值可接受”。数值比较应使用预定义容差，不得以单次 smoke run 替代。

### 4.1 按任务定义指标

| 任务 | 必须说明的验证设计 |
| --- | --- |
| ADMET 分类 | endpoint/阳性定义、类别比例、AUROC/AUPRC 及阈值指标，单类别集不得虚报可计算 AUC |
| 性质/亲和力回归 | 单位和变换、MAE/RMSE、相关性、测试量、误差分布；不能混合不同 assay endpoint |
| 口袋预测 | 结构集、真实口袋定义、top-k、距离或重叠判定、未检出数；0 口袋可通过特定 smoke，但不据此通过科学基准 |
| 分子生成 | 有效/唯一/新颖/多样性与条件满足指标及各自分母；小步模型加载不证明完整生成可用 |
| 对接/重排 | 固定准备与盒子、共晶重对接方案/pose 度量或筛选基准；预先指定 RMSD、富集或排序判据，不从最低能量推断实测活性 |
| MD | 拓扑/力场/溶剂/时间步长、平衡与采样策略、重复、检查点；轨迹可下载不能替代收敛/稳定性复核 |

独立测试集不能参与阈值或超参数选择；结构标准化和近似重复处理需在拆分协议中说明。模型版本间比较必须使用同一冻结集及纳入/排除规则；不确定性区间注明方法、采样单位、样本量与种子，样本不足时明确不支持的结论。平台不设置适用于所有模型的统一“准确率达标线”。

### 4.2 验证记录最小字段

每份记录保存 verification_id、工具/模型/权重/代码摘要、数据与拆分摘要、endpoint、preparation profile、环境摘要、命令/参数、输入输出版本、指标/容差、通过标准、observed result、pass/fail/not_tested、执行时间、执行人、科学复核人及证据链接。摘要不能替代受保护的原始日志和结果，复核权限遵循项目边界。

## 4.3 复核触发与职责

- 模型维护者提供身份、来源和复现材料；科学负责人审查任务定义、基准及用途；管理员负责发布可见性；运维只确认环境和运行证据。
- 权重、预处理、endpoint、阈值、依赖或硬件发生影响结果的变化时，重新执行受影响的 G2/G3；G4 不自动继承至新版本。
- 历史证据过期或范围不覆盖当前任务时，显示 unknown/not_tested，允许按策略受控评估，不虚构信心值。

## 5. 产品呈现要求

工具详情、节点结果、候选表和项目报告至少展示：工具版本、模型版本、证据等级、适用域状态、主要限制和结果产生时间。预测、对接分数和实验测量必须使用不同标签与视觉分组，避免混淆。

Agent 解释结果时必须引用模型卡和真实 Artifact，不得把 E1/E2 输出描述为已实验验证的药效或安全性结论。

## 6. 废弃与回滚

当发现权重、数据、阈值、实现或科学结论存在问题时，管理员应将对应 ToolVersion 标为 `deprecated` 或 `withdrawn`，阻止新任务创建，保留历史任务和 Artifact 的可追踪访问，并在结果页显示影响提示。修复后发布新版本，不修改历史结果。

`withdrawn` 表示拟定的科学撤回标记；代码尚无此字段时用现有禁用/废弃机制及审计附件表达，不能声称 API 已支持。撤回记录列明受影响 endpoint、任务/Artifact、理由和替代版本，历史科学说明追加更正而不覆盖。

## 7. 首期交付清单与验收

V1 每个交付模型须有模型卡、G1/G2 证据或明确未完成状态、已批准用途及复核人；E3/E4 未验证不阻断受控平台验收，但阻止对应科学声明。AT-016 检查不得将 Fake、CPU、NVIDIA、DCU 混为同一证据；AT-017 检查新增科学基准及质量看板。

历史记录 [四模型 K100/DCU 报告](../verification/k100/2026-08-06-four-model-dcu-test-report.md) 只证明 2026-08-06 报告所述范围；[首月验收](../verification/aidd-first-month-acceptance.md) 区分 Fake、自动化和实机待验。新规范不追溯改写它们，也不把本次文档检查当作新模型验收。
