## 1. 引言

### 1.1 编写目的

本文档用于定义 AI 制药研发平台的业务目标、用户角色、功能范围、非功能要求、约束条件和验收标准，作为后续系统设计、开发实施、测试验收和企业交付的需求基线。

### 1.2 项目背景

药物研发流程涉及蛋白结构获取、配体处理、口袋预测、分子生成、ADMET、毒性、合成可及性、分子对接、MD 模拟和打分重排等多类工具。现阶段大量能力以单工具、单脚本、单模型方式存在，研发人员需要手动处理文件格式、运行环境、任务结果和上下游关联。

本平台面向药物研发场景，建设统一的 AI + CADD 科研工作台，通过标准 Artifact、工具契约、任务执行、工作流编排、可视化和智能体辅助，实现工具可注册、数据可复用、流程可追踪、计算可调度。

### 1.3 术语定义

| 术语 | 定义 |
| --- | --- |
| Project | 研发项目空间，承载项目成员、任务、Artifact、工作流、白板和智能体会话。 |
| Standard Artifact | 平台标准科研数据对象，具备类型、版本、文件角色、元数据、校验规则和谱系。 |
| ArtifactVersion | Standard Artifact 的不可变版本，记录一次具体产物状态。 |
| Tool Contract | 平台归一化后的工具能力契约，描述参数、Artifact 输入输出、资源画像和运行入口。 |
| Run Preparation | 运行准备过程，将运行上下文、工具契约、用户输入和上游 Artifact 转换为可执行任务输入。 |
| Task | 一次工具运行实例，记录参数、输入、输出、日志、状态和执行环境。 |
| Workflow | 由工具节点、连线、工作流输入和节点任务绑定组成的可保存研发流程。 |
| Executor | 执行适配方式，包括 builtin、python、docker、ssh、remote_api、k8s、slurm。 |
| Result Manifest | 工具输出结果声明，用于把文件、角色、元数据、checksum 和谱系持久化为 Standard Artifact。 |

## 2. 项目概述

### 2.1 产品定位

AI 制药研发平台定位为面向药物研发人员、CADD 人员、AI 模型开发者、平台管理员和运维人员的科研操作平台。平台不是单一模型展示系统，而是以项目、Artifact、工具、任务、工作流和智能体为主线的研发基础设施。

### 2.2 建设目标

| 编号 | 目标 | 说明 |
| --- | --- | --- |
| OBJ-01 | 项目化研发资产管理 | 研发任务、数据、流程、结果和智能体会话均可归属项目并可追踪。 |
| OBJ-02 | 标准 Artifact 驱动 | 通过标准类型、文件角色和元数据统一跨工具数据交换。 |
| OBJ-03 | 工具统一注册和运行 | 内置、Python、Docker、SSH、Remote API、Tool Package 工具通过 Tool Contract 接入。 |
| OBJ-04 | 工作流傻瓜化编排 | 用户拖节点、连线、补必要参数即可完成上下游自动绑定。 |
| OBJ-05 | 重计算资源可调度 | 分子对接、MD、深度学习模型等任务可通过 Docker、SSH、K8s、Slurm 执行。 |
| OBJ-06 | 结果可视化和可下载 | 蛋白、配体、口袋、表格、报告和轨迹可在统一界面查看和下载。 |
| OBJ-07 | 智能体辅助研发 | 智能体基于平台契约做计划、推荐、解释和流程草稿生成。 |

### 2.3 业务范围

本期纳入范围：

- 用户登录和项目空间。
- Standard Artifact 管理。
- 工具中心和工具注册。
- 任务中心和执行记录。
- 工作流画布和节点运行。
- 外部数据库查询导入。
- 药物研发工具模板。
- 可视化和结果下载。
- 管理后台和标签分类治理。
- Docker、SSH、Remote API、K8s、Slurm 方向的执行适配设计。

本期不纳入范围：

- 企业级计费结算。
- 多租户商业 SaaS 计费体系。
- 自动闭环优化决策系统。
- 全量 LIMS/ELN 替代能力。
- 未经平台契约校验的任意脚本自由执行。

### 2.4 版本交付范围

版本范围用于控制项目实施边界。除非合同或评审另行确认，企业交付以 V1 为首期验收范围，V1.1 和 V2 作为后续迭代范围。

| 版本 | 目标 | 必交付范围 | 不纳入该版本 |
| --- | --- | --- | --- |
| V1 首期交付 | 打通平台主链路，证明标准 Artifact 驱动可用 | 用户/项目、Artifact 基础管理、工具中心、任务中心、Fetch PDB/PubChem、蛋白处理、配体处理、LVpocket、RDKit、基础 ADMET、工作流节点独立运行、工作流自动绑定、保存加载、基础可视化、Docker/SSH/Remote API 基础执行 | K8s/Slurm 生产化、MD 完整生产链路、复杂 Agent 自动编排、多租户计费 |
| V1.1 易用性增强 | 提升科研人员使用效率和管理员治理能力 | 项目驾驶舱、任务工作台完整视图、保存视图、工作流模板、结果中心增强、工具质量看板、标签分类后台、Artifact 上传向导、更多药研工具模板 | 大规模集群调度、高级审计报表、复杂数据生命周期自动化 |
| V2 生产化扩展 | 支持重计算生产部署和更复杂研发流程 | K8s/Slurm Adapter、分子对接生产链路、MD 长任务管理、批量虚拟筛选、Agent 可执行计划审批、数据治理自动化、审计报表 | 全自动实验闭环、外部 LIMS/ELN 深度替代 |
| 暂缓项 | 控制范围膨胀 | 仅保留接口或文档设计 | 企业计费、公共 SaaS 多租户、自动采购/实验执行、任意脚本自由运行 |

### 2.5 需求优先级规则

| 优先级 | 定义 | 进入条件 | 验收要求 |
| --- | --- | --- | --- |
| P0 | 首期主链路不可缺少能力。缺失后平台无法完成核心研发闭环或无法企业验收。 | 影响项目、Artifact、工具、任务、工作流、权限、下载、核心药研链路。 | 必须在 V1 有演示路径、测试记录、失败处理说明。 |
| P1 | 显著提升易用性、管理效率或生产稳定性，但不阻断 V1 主链路。 | 影响效率、治理、质量、复用、批量管理或增强工作流体验。 | 可进入 V1.1，也可按项目资源提前实现。 |
| P2 | 高级能力、生产增强或外部环境依赖较强能力。 | 依赖 K8s/Slurm、复杂模型、长任务生产治理或 Agent 深度能力。 | 进入 V2 或专项里程碑，不作为 V1 阻断项。 |

P0 收敛原则：P0 不等于“重要”，而是“没有它就无法交付主链路”。若某需求只是让体验更顺滑，但有替代操作路径，应优先标为 P1。

### 2.6 可行性评估

可行性分为五档：

| 等级 | 含义 |
| --- | --- |
| F1 已有基础 | 当前平台已有类似能力，主要做文档化、整合或小范围优化。 |
| F2 小改可落地 | 需要局部改造 UI、API 或配置，但不改变核心架构。 |
| F3 需地基改造 | 依赖 Run Preparation、Tool Contract、Result Manifest、Artifact Registry 等核心模块定型。 |
| F4 需新增能力 | 当前需要新增较完整模块或后台治理能力。 |
| F5 外部依赖强 | 依赖集群、第三方工具、模型服务、外部数据库或企业基础设施。 |

| 能力 | 可行性 | 主要依赖 | 建议版本 | 说明 |
| --- | --- | --- | --- | --- |
| 项目空间、项目资产聚合 | F1-F2 | Project、权限、资产查询 | V1 | 可先做基础聚合，驾驶舱增强放 V1.1。 |
| Artifact 基础管理和下载 | F2-F3 | Artifact Registry、文件 role、权限 | V1 | 必须先保证标准类型、role 和下载权限。 |
| 工具中心和示例一键填入 | F2-F3 | Tool Contract、examples、Run Preparation preview | V1 | 示例能力应作为工具契约的一部分治理。 |
| 任务中心工作台 | F2-F4 | Task 查询、Saved View、队列状态、索引 | V1/V1.1 | V1 做系统视图和详情侧栏，保存视图和批量操作可 V1.1。 |
| 工作流自动绑定 | F3 | Artifact Slot、Binding Decision、Run Preparation | V1 | 是平台主链路地基，优先级高。 |
| 保存工作流恢复节点任务 | F3 | Node Task Binding、contract snapshot、ArtifactVersion binding | V1 | 必须修复“加载后空节点/任务丢失”类问题。 |
| Fetch PDB / PubChem | F1-F2 | 外部数据库 API、Artifact 持久化、Renderer | V1 | 外部 API 稳定性需做失败重试和来源记录。 |
| 蛋白/配体处理 | F3-F5 | RDKit/OpenBabel/MGLTools/PDBFixer 等工具链 | V1/V1.1 | V1 可先支持关键格式，复杂质子化策略后续增强。 |
| RDKit 分子属性 | F1-F2 | 平台内置 RDKit | V1 | 适合内置为平台工具节点。 |
| ADMET/毒性/合成可及性 | F3-F5 | 传统工具或模型工具契约 | V1.1 | V1 可保留基础 ADMET，深度模型按工具接入。 |
| 分子对接 | F4-F5 | Docker/SSH/K8s/Slurm、蛋白/配体 PDBQT 准备 | V2 | 可先设计模板，生产化依赖资源调度。 |
| MD 模拟 | F5 | HPC/Slurm、长任务、轨迹预览、检查点 | V2 | 不建议纳入 V1 验收阻断。 |
| Remote API 自注册 | F3-F5 | manifest 标准、安全 allowlist、异步接口、Result Manifest | V1/V1.1 | V1 可做内网受信 API，外部开放需更强安全治理。 |
| K8s / Slurm Adapter | F5 | 企业集群、账号、镜像、共享存储、队列策略 | V2 | 先复用 SSH Job 过渡，避免过早绑定集群细节。 |
| Agent 可执行计划 | F4 | Tool capability summary、Run Preparation、审批和审计 | V2 | V1/V1.1 可先做推荐和解释。 |

### 2.7 风险与依赖

| 风险编号 | 风险 | 影响 | 缓解措施 | 责任角色 | 前置条件 |
| --- | --- | --- | --- | --- | --- |
| RISK-001 | Standard Artifact 类型和 role 设计不稳定 | 工作流自动绑定反复返工 | 先冻结 `protein_structure@1`、`ligand_structure@1`、`binding_pocket@1`、`molecule_table@1` 的 role 和 metadata | 平台架构负责人 | Artifact Registry 评审通过 |
| RISK-002 | Run Preparation 未统一 | 工具详情、节点运行、工作流运行表现不一致 | 将运行准备作为唯一权威，禁止页面和调度器复制绑定规则 | 后端负责人 | PreparedRun、ReadinessReport 接口冻结 |
| RISK-003 | Result Manifest 不统一 | 输出能下载但不能进入下游工作流 | 发布工具前校验 Result Manifest；不合规任务不能生成标准 Artifact | 工具管理员 | Result Manifest schema 冻结 |
| RISK-004 | 外部数据库 API 不稳定 | Fetch PDB/PubChem 失败或变慢 | 增加超时、重试、缓存、来源记录和失败报告 | 后端负责人 | 外部 API 访问策略确认 |
| RISK-005 | OpenBabel/RDKit/MGLTools 等依赖复杂 | 蛋白/配体处理环境不稳定 | 优先容器化或内置轻量路径，复杂工具放 Docker/SSH | 工具负责人、运维 | 工具依赖清单和镜像策略确认 |
| RISK-006 | Remote API 无认证但可注册 URL | SSRF、非法重定向、超大文件、结果污染 | 仅管理员注册；启用 allowlist、协议限制、大小限制、checksum 复算 | 平台管理员、运维 | Remote API 安全策略启用 |
| RISK-007 | 长任务状态不同步 | 用户看到任务一直 running 或无法取消 | ExecutionRecord 记录执行 handle；Executor Gateway 定期 inspect 和超时处理 | 后端负责人、运维 | 任务状态同步机制上线 |
| RISK-008 | K8s/Slurm 环境差异大 | 生产部署延期 | V1 不阻断；先用 SSH Job 过渡；K8s/Slurm 作为专项验收 | 运维 / 集群管理员 | 集群账号、队列、存储、镜像策略确认 |
| RISK-009 | 大文件预览性能不足 | 页面卡顿或加载失败 | 大文件摘要预览、分页、异步 preview、下载优先 | 前端负责人、后端负责人 | Renderer Registry 和 preview 策略确认 |
| RISK-010 | 权限和审计缺失 | 企业验收不通过或数据泄露 | 文件下载、跨项目绑定、工具发布、任务取消、Agent 审批均记录审计 | 平台管理员 | 权限矩阵和审计事件清单确认 |

### 2.8 数据规模与部署假设

以下规模用于默认验收和估算，不代表平台上限。生产规模应结合部署环境单独压测。

| 部署形态 | 用户规模 | 任务规模 | Artifact 规模 | 文件规模 | 并发假设 | 适用范围 |
| --- | --- | --- | --- | --- | --- | --- |
| 单机演示 | 1-10 用户 | 500-1000 任务 | 1000 Artifact | 单文件 500 MB 内 | 1-3 个轻任务，1 个重任务 | 客户演示、内部评审、培训 |
| 实验室私有部署 | 10-50 用户 | 5000-20000 任务 | 10000-50000 Artifact | 单文件 1-5 GB，推荐对象存储 | 5-20 个轻任务，2-5 个重任务 | 实验室日常研发 |
| 集群生产部署 | 50+ 用户 | 50000+ 任务 | 100000+ Artifact | 大文件走对象存储/共享存储 | 按队列和资源 tier 配置 | 对接、MD、批量筛选、模型服务生产化 |

默认 V1 验收以“实验室私有部署”的低档规模为目标：不少于 10 个用户、5000 条任务、10000 个 Artifact、500 MB 单文件、20 节点工作流和 Docker/SSH/Remote API 基础执行。

## 3. 用户角色

| 角色编号 | 用户角色 | 主要职责 | 核心诉求 |
| --- | --- | --- | --- |
| U-01 | 药物研发科研人员 | 查询结构、运行工具、查看结果、组合工作流 | 操作简单，不理解底层部署也能完成研发任务。 |
| U-02 | CADD / 计算化学人员 | 配置专业参数、执行对接/MD/筛选、导出结果 | 可控参数、可追踪输入输出、可复用 Artifact。 |
| U-03 | AI 模型开发者 | 注册新模型、提供标准输入输出和样例 | 不为每个工作流写额外适配。 |
| U-04 | 平台管理员 | 管理用户、工具、标签、审核、资源配置 | 工具可审核，标签可配置，资源可治理。 |
| U-05 | 运维 / 集群管理员 | 管理服务器、容器、队列、对象存储、集群 | 任务隔离、状态可观测、失败可定位。 |
| U-06 | 项目负责人 | 管理项目成员、项目资产、工作流模板和项目交付结果 | 了解项目进展、控制成员权限、复用成功流程。 |

### 3.1 角色权限矩阵

权限设计应满足“科研人员少受阻、管理员可治理、运维不接触科研数据内容”的原则。具体权限可按企业组织策略细化，但必须覆盖以下能力域。

| 能力域 | 科研人员 | 项目负责人 | CADD / 计算化学人员 | AI 模型开发者 | 平台管理员 | 运维 / 集群管理员 |
| --- | --- | --- | --- | --- | --- | --- |
| 项目空间 | 查看和使用参与项目 | 管理成员、模板、归档和项目资产 | 查看和使用参与项目 | 查看授权项目中的模型测试结果 | 管理全部项目策略和异常处理 | 查看项目运行健康，不默认查看科研内容 |
| Artifact | 查看、上传、使用授权 Artifact | 管理项目 Artifact、标签、导入和归档 | 上传和使用专业结构/表格 Artifact | 使用样例 Artifact 验证工具 | 管理 Artifact type、role、metadata 和生命周期 | 管理存储容量和备份，不绕过权限下载文件 |
| 工具 | 浏览、运行已发布工具 | 推荐项目常用工具 | 配置高级参数和专业工具 | 提交工具版本、样例和 manifest | 审核、发布、禁用、回滚工具 | 配置执行器、镜像和资源，不修改工具语义 |
| 任务 | 查看和操作本人/授权任务 | 查看项目任务、批量归档、重试授权任务 | 查看专业任务日志和结果 | 查看工具验证任务 | 查看全部任务质量和失败统计 | 查看队列、执行器日志、取消异常长任务 |
| 工作流 | 创建、保存、运行个人或项目工作流 | 管理项目模板、复制成功流程 | 编辑专业节点参数和调试流程 | 验证新工具在工作流中的表现 | 管理模板发布和契约兼容问题 | 查看执行状态和资源占用 |
| 智能体 | 发起问答、生成草稿、审批本人计划 | 审批项目级推荐流程 | 获取专业工具建议 | 提供工具说明和样例知识 | 管理 Agent 可见工具、模板和审计 | 不直接干预 Agent 科研结论 |
| 管理后台 | 无访问或只读个人设置 | 项目级设置 | 无默认访问 | 工具提交入口 | 全局配置、审核、审计、治理 | 执行资源、健康、告警、备份恢复 |
| 审计 | 查看本人操作记录 | 查看项目审计摘要 | 查看本人专业任务记录 | 查看工具提交流程记录 | 查看全局审计 | 查看运维操作和系统事件审计 |

## 4. 业务流程需求

### 4.1 外部结构查询流程

1. 用户进入项目或工作台。
2. 选择 PDB 或 PubChem 查询工具。
3. 输入 PDB ID、CID、SMILES、名称等查询参数。
4. 平台调用外部数据库接口并下载结果。
5. 平台生成 Standard Artifact，记录来源、外部 ID、下载时间、文件角色和 metadata。
6. 用户在节点面板、任务详情或 Artifact 详情中查看 2D/3D 可视化并下载。

验收要求：查询得到的蛋白或配体可以直接进入后续工作流预检；若 role 或准备状态不足，平台应提示插入准备或转换节点。

### 4.2 工具独立运行流程

1. 用户从工具详情页或单个工作流节点启动运行。
2. 平台展示工具参数、Artifact 输入槽位、示例和资源需求。
3. 用户填写必要参数、上传文件或选择已有 Artifact。
4. Run Preparation 进行权限、role、metadata、版本和 cardinality 校验。
5. 校验通过后创建 Task 并提交 Executor。
6. 任务完成后持久化输出文件、Standard Artifact 和谱系。

验收要求：工具可无项目运行；若产生标准输出，平台应归属到显式项目或用户默认工作空间。

### 4.3 项目内工具运行流程

1. 用户从项目空间进入工具。
2. 平台加载当前项目内与工具输入兼容的 Artifact。
3. 用户选择 Artifact 或上传新文件。
4. 任务输出归属当前项目。
5. 项目资产页可查看任务、Artifact、谱系和下载结果。

验收要求：跨项目 Artifact 不能静默绑定；需要复用时必须导入或复制并保留谱系。

### 4.4 工作流编排流程

1. 用户拖入工具节点。
2. 节点根据 Tool Contract 自动展示输入输出槽位。
3. 用户连接上游 output slot 与下游 input slot。
4. 平台进行语义预检，识别 ready、missing、needs_preparation、needs_conversion、invalid_type 等状态。
5. 用户补充流程边界参数或上传文件。
6. 工作流按依赖关系启动 ready 节点。
7. 每个节点运行后保存 Node Task Binding 和 ArtifactVersion 绑定。

验收要求：保存工作流重新加载后，节点任务、输出 Artifact、连线绑定和预检状态应恢复。

### 4.5 新工具接入流程

1. 模型开发者提供 Tool Package、Remote API manifest 或管理员配置工具契约。
2. 平台校验 Tool Contract、Artifact slots、参数 schema、Result Manifest 和样例。
3. 管理员审核工具分类、标签、资源画像和可见范围。
4. 工具发布后进入工具库、工作流节点库和 Agent capability summary。
5. 工作流通过标准 Artifact 自动发现上下游兼容关系。

验收要求：新工具不需要单独修改工作流调度代码即可进入编排。

### 4.6 核心用户旅程

核心用户旅程用于约束功能体验：用户应沿着自然研发路径完成任务，而不是在工具、文件、任务和工作流之间反复手工查找。

| 旅程编号 | 用户目标 | 推荐路径 | 好用要求 | 管理要求 |
| --- | --- | --- | --- | --- |
| J-01 | 从靶点结构开始做口袋分析 | 新建项目 -> Fetch PDB -> 蛋白处理 -> LVpocket -> 查看口袋 -> 保存工作流模板 | PDB ID、项目上下文和上游蛋白自动带入；role 不满足时提示处理节点 | 管理员可配置 Fetch PDB、蛋白处理、LVpocket 的默认模板和资源 |
| J-02 | 从小分子开始做性质评估 | Fetch PubChem / 上传 SDF -> 配体处理 -> RDKit 属性 -> ADMET / 毒性 -> 表格筛选导出 | 小分子 2D/3D 可视化、表格可筛选、失败分子可定位 | 管理员可配置 ADMET 工具、表格列标准和下载策略 |
| J-03 | 调试并复用一条工作流 | 从模板创建工作流 -> 单节点运行 -> 修复失败节点 -> 只运行下游 -> 保存为项目模板 | 节点内有配置、预检、运行、日志、结果和预览，不需要跳转多页 | 项目负责人可管理模板可见范围和版本说明 |
| J-04 | 注册一个新模型工具 | 模型开发者提交 manifest / Tool Package -> 平台校验 -> 管理员审核 -> smoke test -> 发布 | 开发者只关注标准输入输出和样例，不写工作流适配 | 管理员能看到契约错误、样例结果、资源画像和发布影响 |
| J-05 | 管理高负载重计算任务 | 查看重计算队列 -> 定位长任务 -> 查看资源画像和日志 -> 取消/降级/调整并发 | 科研人员看到预计等待和运行状态，不接触集群命令 | 运维可按 executor、队列、资源 tier 和工具治理资源 |
| J-06 | 复盘一个项目结果 | 项目驾驶舱 -> 查看活动流 -> 查看关键 Artifact 谱系 -> 导出报告和文件 | 负责人能看到谁在何时用什么输入产生了什么结果 | 管理员可导出审计、控制保留策略和归档项目 |

### 4.7 核心业务闭环

平台交付必须优先保证以下闭环可用：

| 闭环 | 起点 | 终点 | 必须沉淀的对象 | 验收标准 |
| --- | --- | --- | --- | --- |
| 数据闭环 | 上传或外部数据库导入 | 可复用 Artifact | Artifact、ArtifactVersion、ArtifactFile、Lineage | 下游工具能自动发现并预检该 Artifact。 |
| 工具闭环 | 工具注册或自注册 | 已发布 Tool Release | ToolVersion、Tool Contract、Example、Smoke Test | 工具无需 workflow 专属适配即可进入工具库和工作流。 |
| 任务闭环 | 用户点击运行 | Task 结果和 Artifact 输出 | Task、ExecutionRecord、TaskOutput、Result Manifest | 任务可取消、可重试、可看日志、可追踪输出。 |
| 工作流闭环 | 拖节点连线 | 可保存和复用流程 | WorkflowDefinition、WorkflowRun、Node Task Binding | 保存后加载不丢节点任务和 Artifact 绑定。 |
| 治理闭环 | 管理员发现问题 | 配置、禁用、修复或归档 | AuditLog、Governance Registry、Quality Metrics | 管理员能定位工具、资源、数据或权限问题并处理。 |

## 5. 功能需求

### 5.1 功能需求设计原则

功能需求按“科研人员好用、管理员好管、平台可扩展”重新组织。每个模块都必须同时回答两个问题：用户如何更少操作完成研发任务，管理员如何用配置和审核治理平台。

| 设计原则 | 用户侧要求 | 管理侧要求 |
| --- | --- | --- |
| 入口清晰 | 常用工作流、最近项目、最近结果、需要关注事项应一眼可见。 | 管理员能配置首页模块、工具分组、标签和推荐模板。 |
| 输入傻瓜化 | 能自动带入项目上下文、上游 Artifact、示例参数和默认值。 | 管理员能配置必填项、默认值、参数范围和校验规则。 |
| 结果可理解 | 结果需要有摘要、预览、下载、来源和下一步建议。 | 管理员能配置 renderer、下载策略、保留策略和敏感文件规则。 |
| 异常可处理 | 错误提示要给出原因和下一步动作。 | 管理员能看到失败统计、日志、执行器健康和工具质量问题。 |
| 扩展不改页面 | 新工具发布后自动进入工具库、工作流和 Agent 能力列表。 | 新标签、分类、Artifact type、role、renderer、executor 都可配置审核。 |
| 大量数据可管理 | 任务、Artifact、工作流都必须支持搜索、筛选、分组、保存视图和批量操作。 | 管理员能做归档、清理、配额、审计和质量治理。 |

### 5.2 项目空间

项目空间是科研人员的默认工作入口。它不应只是资产列表，而应提供项目驾驶舱、最近活动、待处理事项、推荐流程和项目内数据导航。

| 需求编号 | 需求名称 | 优先级 | 需求描述 | 验收标准 |
| --- | --- | --- | --- | --- |
| FR-PROJ-001 | 项目创建和维护 | P0 | 支持创建、编辑、归档、恢复和删除项目，创建时可选择项目模板。 | 用户可基于模板创建项目，并在列表、详情页查看。 |
| FR-PROJ-002 | 项目成员权限 | P0 | 支持项目成员、角色、邀请、移除和权限变更。 | 非成员不能访问项目 Artifact、任务和工作流。 |
| FR-PROJ-003 | 项目驾驶舱 | P0 | 项目首页展示最近任务、最近 Artifact、失败任务、运行中工作流、推荐下一步和项目统计。 | 用户进入项目后能定位当前最需要处理的事项。 |
| FR-PROJ-004 | 项目资产聚合 | P0 | 聚合任务、Artifact、工作流、白板、智能体会话和外部导入记录。 | 项目详情可按资产类型、标签、时间和创建人筛选。 |
| FR-PROJ-005 | 项目上下文运行 | P0 | 从项目进入工具、工作流或 Agent 时自动带入 Run Context。 | 输出 Artifact 默认归属当前项目。 |
| FR-PROJ-006 | 项目模板 | P1 | 支持管理员配置项目模板，例如靶点发现、虚拟筛选、分子优化。 | 新建项目可自动带入推荐工具、工作流模板和 Artifact 类型。 |
| FR-PROJ-007 | 项目活动流 | P1 | 记录项目内任务运行、Artifact 生成、工作流变更、成员操作和 Agent 审批。 | 项目负责人可查看项目最近活动和操作者。 |
| FR-PROJ-008 | 项目归档和清理 | P1 | 支持项目归档、只读、恢复和数据保留策略。 | 归档项目不能提交新任务，但历史结果可查看。 |

### 5.3 Artifact 资产

Artifact 资产模块要让科研人员能“找得到、看得懂、用得上、追得回”。管理员要能治理类型、角色、校验、保留和权限。

| 需求编号 | 需求名称 | 优先级 | 需求描述 | 验收标准 |
| --- | --- | --- | --- | --- |
| FR-ART-001 | Standard Artifact Registry | P0 | 平台维护 Artifact type、version、file role、metadata、validation rule 和 compatibility rule。 | 标准类型可被工具契约引用并通过校验。 |
| FR-ART-002 | ArtifactVersion 管理 | P0 | 每次处理、转换、筛选和打分产生不可变版本。 | 历史版本可查看且不会被覆盖。 |
| FR-ART-003 | 文件角色管理 | P0 | 一个 ArtifactVersion 可包含多个有语义的文件角色。 | 下游工具可按 role 自动选择输入文件。 |
| FR-ART-004 | 谱系追踪 | P0 | 记录 ArtifactVersion 与任务、参数、上游输入和派生关系。 | 结果详情可追踪来源任务、输入和处理链路。 |
| FR-ART-005 | 权限校验下载 | P0 | Artifact 文件预览和下载必须经过权限校验。 | 未授权用户无法访问下载地址。 |
| FR-ART-006 | 资产搜索和筛选 | P0 | 支持按项目、类型、role、标签、来源、创建人、时间、任务、外部 ID 搜索筛选。 | 用户能快速定位某个 PDB、配体、口袋或报告。 |
| FR-ART-007 | 上传和导入向导 | P0 | 用户上传文件时平台应识别类型、提示缺失 metadata、校验 role 并生成 Artifact。 | 上传 PDB/SDF/CSV 后能形成可复用 Artifact 或给出错误原因。 |
| FR-ART-008 | 版本对比 | P1 | 支持同一 Artifact 不同版本的 metadata、role、来源任务和文件差异对比。 | 用户能比较原始蛋白和处理后蛋白的差异。 |
| FR-ART-009 | 批量管理 | P1 | 支持批量打标签、移动/导入到项目、归档、删除申请和导出清单。 | 管理员或项目负责人可批量治理资产。 |
| FR-ART-010 | 生命周期策略 | P1 | 管理员可配置 Artifact 保留、归档、过期和清理策略。 | 过期 Artifact 不再自动绑定，但历史记录可追踪。 |

### 5.4 工具中心

工具中心要同时服务科研人员和模型开发者。科研人员需要快速找到能用的工具，模型开发者和管理员需要可审核、可测试、可发布、可回滚的工具治理链路。

| 需求编号 | 需求名称 | 优先级 | 需求描述 | 验收标准 |
| --- | --- | --- | --- | --- |
| FR-TOOL-001 | 工具注册 | P0 | 支持 builtin、python、docker、ssh、remote_api、Tool Package 工具注册。 | 管理员可创建工具版本并进入审核流程。 |
| FR-TOOL-002 | Tool Contract 校验 | P0 | 工具发布前校验参数 schema、Artifact slots、executor、resource profile、Result Manifest 和样例。 | 无效契约不能发布为可运行工具。 |
| FR-TOOL-003 | 工具库浏览 | P0 | 工具库支持按研发阶段、能力、Artifact 输入输出、执行器、资源需求、标签和热度筛选。 | 用户能在 30 秒内找到目标工具或候选工具。 |
| FR-TOOL-004 | 工具详情运行 | P0 | 工具详情页展示用途、输入、输出、参数、示例、资源、最近任务和可视化结果。 | 用户可从详情页直接运行、预检和查看结果。 |
| FR-TOOL-005 | 示例一键填入 | P0 | 工具详情页可一键填入示例参数、样例文件或样例 Artifact。 | 用户点击示例后表单可直接预检。 |
| FR-TOOL-006 | 智能输入表单 | P0 | 参数表单应根据 Tool Contract 自动展示必填项、默认值、单位、说明、校验错误和高级参数折叠。 | 用户不需要理解 schema 即可填写。 |
| FR-TOOL-007 | 标签分类可维护 | P0 | 工具标签、分类、阶段、工作台分组由管理员维护，不在前端硬编码。 | 新增标签后工具库筛选可使用。 |
| FR-TOOL-008 | 资源画像 | P0 | 工具声明 CPU、内存、GPU、超时、预估耗时、并发和调度类型。 | 运行前可展示资源需求，管理员可用于队列治理。 |
| FR-TOOL-009 | 工具版本治理 | P1 | 支持工具版本草稿、验证、发布、禁用、废弃和回滚。 | 禁用版本不再可新建任务，历史任务仍可查看。 |
| FR-TOOL-010 | 工具质量看板 | P1 | 管理员可查看工具运行次数、成功率、平均耗时、失败原因和用户反馈。 | 管理员能发现不稳定工具并下线或修复。 |
| FR-TOOL-011 | Remote API 自注册 | P0 | 管理员只填写受信 URL，平台拉取 manifest、examples、schema 和异步任务接口。 | manifest 校验通过后生成 Tool Contract 并可发布。 |
| FR-TOOL-012 | 工具推荐入口 | P1 | 工具可根据当前项目 Artifact、工作流节点和用户目标推荐。 | 用户选择蛋白 Artifact 时能看到兼容的处理、口袋预测和对接工具。 |

### 5.5 任务中心

任务中心不能只提供按创建时间倒序排列的任务流水表。随着工具、工作流和用户增多，任务应按“我需要关注什么”“这个项目发生了什么”“这条工作流跑到哪里了”“哪些重任务占用资源”四类问题组织。

任务中心第一版推荐提供以下系统视图：

| 视图 | 目标用户 | 展示重点 |
| --- | --- | --- |
| 我的任务 | 科研人员 | 当前用户创建、参与或需要处理的任务。 |
| 项目任务 | 科研人员、项目负责人 | 单个项目内的任务、输入、输出和失败原因。 |
| 工作流任务 | 科研人员、CADD 人员 | 按 WorkflowRun 和节点聚合任务，查看流程进度。 |
| 运行中 | 科研人员、运维 | queued、running、cancelling 等活跃任务。 |
| 需要关注 | 科研人员、管理员 | failed、preflight_failed、缺输入、可重试、输出校验失败任务。 |
| 重计算队列 | 运维、管理员 | Docker、SSH、Remote API、K8s、Slurm 等 executor 的队列和资源占用。 |
| 最近结果 | 科研人员 | 最近成功任务及其输出 Artifact、报告和下载入口。 |

| 需求编号 | 需求名称 | 优先级 | 需求描述 | 验收标准 |
| --- | --- | --- | --- | --- |
| FR-TASK-001 | 任务创建 | P0 | 所有运行入口统一创建 Task。 | 工具、节点、工作流、Agent 运行均产生 Task。 |
| FR-TASK-002 | 任务状态 | P0 | 支持 created、queued、running、succeeded、failed、cancelled、cancelling 等状态。 | 页面可实时或轮询查看状态。 |
| FR-TASK-003 | 取消和重试 | P0 | 支持长任务取消和失败任务重试。 | 取消后 Executor 收到取消命令，重试生成新执行记录。 |
| FR-TASK-004 | 日志查看 | P0 | 支持查看任务标准日志、错误日志、执行器日志和关键事件。 | 失败任务能查看错误原因和下一步建议。 |
| FR-TASK-005 | 结果持久化 | P0 | 根据 Result Manifest 持久化输出文件和 Standard Artifact。 | 成功任务可在结果区和项目资产中查看。 |
| FR-TASK-006 | 任务总览看板 | P0 | 任务中心首页展示运行中、需要关注、今日完成、失败率、队列等待和重计算占用。 | 用户进入任务中心即可判断当前是否有失败、排队或长任务。 |
| FR-TASK-007 | 系统任务视图 | P0 | 提供我的任务、项目任务、工作流任务、运行中、需要关注、重计算队列、最近结果等系统视图。 | 用户不需要手动筛选即可进入常用任务视角。 |
| FR-TASK-008 | 多维筛选 | P0 | 支持按项目、工具、工作流、节点、状态、创建人、执行器、Artifact 类型、时间范围、标签筛选。 | 用户可在任务数量较大时快速缩小范围。 |
| FR-TASK-009 | 搜索和排序 | P0 | 支持按任务名、工具名、Artifact 名、PDB ID、PubChem CID、错误关键字搜索，并按时间、耗时、状态、资源排序。 | 输入关键词后可定位相关任务。 |
| FR-TASK-010 | 分组查看 | P1 | 支持按项目、工作流运行、工具、状态、执行器、日期分组。 | 工作流任务可按节点和运行批次聚合展示。 |

| FR-WF-003 | 节点独立运行 | P0 | 每个节点可以单独预检、配置和运行。 | 单节点运行能产生 Task 和结果。 |

| FR-WF-007 | 工作流模板 | P1 | 提供常用模板，例如结构获取、蛋白准备、口袋预测、虚拟筛选、ADMET。 | 用户可从模板创建可编辑工作流。 |

| FR-WF-009 | 结果中心 | P0 | 工作流结果中心按节点、Artifact 类型和运行批次聚合结果。 | 用户可统一查看、下载、对比工作流产物。 |

### 5.12 资源调度和执行

资源调度要让科研人员不用理解集群命令，让管理员能管理队列、配额、失败和成本。

| 需求编号 | 需求名称 | 优先级 | 需求描述 | 验收标准 |
| --- | --- | --- | --- | --- |
| FR-EXEC-001 | Executor Gateway | P0 | builtin、python、docker、ssh、remote_api、k8s、slurm 通过统一 Interface 提交、查询、取消、日志和收集输出。 | Task 不需要知道底层执行细节。 |
| FR-EXEC-002 | 队列和并发控制 | P0 | 支持按 executor、工具、资源 tier、用户或项目控制并发和排队。 | 重任务不会挤占轻任务和 Web 服务资源。 |
| FR-EXEC-003 | 资源预检 | P0 | 运行前展示资源画像、预估耗时、队列和超时。 | 用户提交重任务前能看到资源影响。 |
| FR-EXEC-004 | 长任务取消 | P0 | 支持 Docker stop、SSH kill、Remote API cancel、K8s Job delete、Slurm scancel。 | 取消后平台状态与底层执行状态一致。 |

### 6.1 量化非功能指标

以下指标作为企业交付验收的默认目标，实际部署可按硬件、并发和数据规模调整。

| 编号 | 指标类别 | 指标要求 | 验收方式 |
| --- | --- | --- | --- |
| QNFR-001 | 页面响应 | 常规列表页首屏加载在 3 秒内完成，筛选/排序交互在 1 秒内反馈。 | 以 500 条任务、500 条 Artifact、100 个工具为样本测试。 |
| QNFR-002 | 任务中心规模 | 任务中心至少支持 5000 条任务按系统视图、筛选、搜索、分组查看。 | 构造 5000 条任务数据，验证查询和详情侧栏可用。 |
| QNFR-003 | 工作流画布规模 | 20 个节点以内保持拖拽、缩放、预检流畅；50 个节点以内可打开和保存。 | 工作流压力场景测试。 |
| QNFR-004 | 状态同步 | running 任务状态在常规场景下 5-15 秒内刷新；长任务日志支持增量查看。 | 运行 Docker/SSH/Remote API 任务验证。 |
| QNFR-005 | 文件规模 | 单文件上传默认支持至少 500 MB；更大文件走对象存储分片或后台导入策略。 | 上传 PDB/SDF/CSV 和大报告文件验证。 |
| QNFR-006 | 结果预览 | 常规结构和表格预览在 5 秒内展示；大文件应先展示摘要或异步 preview 状态。 | protein、ligand、molecule table、trajectory 摘要测试。 |
| QNFR-007 | 任务可靠性 | 任务失败必须保留错误日志、执行器状态和可读失败原因。 | 人为制造参数错误、输出缺失、执行器断连。 |
| QNFR-008 | 安全审计 | Artifact 下载、工具发布、权限变更、任务取消、Agent 审批必须有审计记录。 | 检查审计日志完整性。 |
| QNFR-009 | 数据保留 | 默认保留任务、Artifact、审计记录不少于 180 天；项目归档后仍可按策略查看。 | 配置保留策略并验证归档项目。 |
| QNFR-010 | 可扩展性 | 新工具发布后无需修改工作流前端或调度特判即可被发现。 | 发布一个新 Tool Contract 并验证工具库/工作流/Agent 可见。 |

## 7. 约束条件

| 编号 | 约束 | 说明 |
| --- | --- | --- |
| CON-001 | 后端权威 | 前端预检仅做展示，最终权限、绑定和任务输入以后端 Run Preparation 为准。 |
| CON-002 | 标准 Artifact 优先 | 工作流连线不得依赖临时文件路径和工具私有输出名。 |
| CON-003 | Tool Package 非 executor | Tool Package 是交付格式，运行仍归一到具体 executor。 |
| CON-004 | Remote API 第一版无认证 | 仅允许管理员注册受信 URL，平台侧必须做 SSRF、大小、checksum 和超时控制。 |
| CON-005 | 重计算外部化 | 对接、MD 和大规模模型推理不应长期在 Web 进程内执行。 |

| 编号 | 异常场景 | 系统行为 | 用户提示 | 管理员/运维动作 |
| --- | --- | --- | --- | --- |
| EDGE-001 | Artifact type 不匹配 | Run Preparation 返回 `invalid_type`，禁止运行。 | 当前上游产物类型不满足下游工具。 | 检查工具契约或推荐转换工具。 |
| EDGE-002 | Artifact role 缺失 | 返回 `invalid_role` 或 `needs_preparation`。 | 需要先进行蛋白/配体准备或格式转换。 | 检查 Artifact role registry 和准备工具配置。 |
| EDGE-003 | metadata 不满足 | 返回 `invalid_metadata` 或 `needs_conversion`。 | 当前产物缺少必要科学状态信息。 | 检查 metadata schema 和工具输入要求。 |
| EDGE-004 | 上游节点未完成 | 返回 `waiting_upstream`，下游节点不可运行。 | 等待上游节点完成。 | 无需处理，除非上游任务失败。 |
| EDGE-005 | 多个候选 Artifact | 返回 `needs_selection`。 | 存在多个可用输入，请选择一个。 | 可配置默认选择策略或 ranking。 |
| EDGE-006 | 工作流加载后工具契约升级 | 使用当前 contract hydrate；不兼容时保留 snapshot 并要求重新预检。 | 工具契约已更新，请重新预检该节点。 | 管理员查看 breaking change 并提供迁移说明。 |
| EDGE-007 | 保存工作流引用的 ArtifactVersion 失效 | 返回 `stale_binding`，节点不可直接运行。 | 原绑定产物已过期、删除或无权限。 | 检查生命周期策略和跨项目权限。 |
| EDGE-008 | Remote API manifest 不合规 | 拒绝注册或发布。 | 远端服务 manifest 不符合平台规范。 | 管理员查看校验报告，模型方修正 manifest。 |
| EDGE-009 | Remote API 超时或取消失败 | Task 标记 failed 或 cancelling timeout，保留日志。 | 远端服务无响应或取消失败。 | 运维检查远端服务健康和网络。 |
| EDGE-010 | Executor 断连 | Task 暂停同步并进入待检查状态，不直接覆盖为成功。 | 执行环境暂时不可达，请稍后查看。 | 运维检查 Docker/SSH/K8s/Slurm 连接。 |
| EDGE-011 | Result Manifest 缺失或输出不合规 | Task 可标记 failed 或 partial_failed，不生成标准 Artifact。 | 工具输出不符合平台标准。 | 管理员查看工具质量看板并下线或修复工具。 |
| EDGE-012 | 下载越权 | 拒绝下载并记录审计。 | 无权限访问该文件。 | 管理员可查看越权审计记录。 |
| EDGE-013 | 存储容量不足 | 新任务进入等待或失败前置校验。 | 当前存储空间不足，请联系管理员。 | 运维扩容、清理或调整保留策略。 |
| EDGE-014 | 大文件无法即时预览 | 展示摘要、排队生成 preview 或提示下载。 | 文件较大，正在生成预览。 | 管理员可调整 preview 策略和资源。 |
| EDGE-015 | Agent 计划包含禁用工具 | 计划校验失败，不能执行。 | 计划包含不可用工具，请替换。 | 管理员检查 Agent 可见工具和工具状态。 |

## 10. 交付验收口径

企业交付时，以以下条件作为需求层面完成标准：

1. P0 需求均有可演示路径、测试记录和失败处理说明。
2. 核心链路 `Fetch PDB -> Protein Preparation -> LVpocket` 可端到端完成。
3. 新工具接入不需要修改工作流专属代码即可出现在工具库和工作流节点库。
4. 任务、Artifact、工作流和下载均可做权限校验。
5. 部署文档可指导运维在目标环境完成安装、启动、停止、备份、恢复和监控。
