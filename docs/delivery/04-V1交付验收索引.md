## 1. 使用方式

本文是 V1 验收入口索引，不替代需求、设计或运维说明书。验收前按下列顺序检查：

1. 确认两条主链路具备可演示路径。
2. 确认地基模块有自动化回归覆盖。
3. 确认结果、下载、失败定位和科学附件可在页面定位。
4. 确认未完成项被标为限制，不包装成已验证能力。

## 3. 主链路巡检

### 3.1 蛋白口袋链路

```text
Fetch PDB
  -> Protein Preparation
  -> LVpocket
```

验收时重点确认：

- PDB 输入产出 `protein_structure@1`。
- Protein Preparation 产出 prepared protein roles。
- LVpocket 自动消费 prepared protein 并产出 pocket Artifact。
- 任务详情、Artifact 详情可查看、下载和定位失败原因。

### 3.2 小分子 ADMET 链路

```text
Fetch PubChem Ligand
  -> Ligand Preparation
  -> SDF to SMILES Table
  -> RDKit Properties
  -> MolP-PC Basic ADMET
```

验收时重点确认：

- RDKit Properties 只作为理化描述符步骤，不替代基础 ADMET。
- MolP-PC 必须通过平台注册工具 `molp-pc-property-prediction`、当前 `ToolVersion` 和平台任务调度入口运行。
- MolP-PC 节点消费 `molecule_table@1` 并产出 `molecule_table@1` 与 `run_report@1`。
- 任务详情展示模型卡、验证记录和证据等级引用。
- Artifact 详情展示 `manifest_json.metadata` 中的模型版本、runtime、endpoint、证据等级和附件引用。

## 5. 当前限制

- AT-003 平台工具调用 smoke 是主验收路径；`model/MolP-PC/platform_run.sh` 仅用于模型包本地调试和执行器 runtime 自检。
- AT-003 已归档一次平台真实运行证据：[2026-09-09 MolP-PC 平台运行记录](../verification/at003-platform-run-2026-09-09.md)；后续回归仍可按 [AT-003 平台工具调用真实运行记录模板](../verification/templates/at003-platform-tool-run-record.md) 新增记录。
- `engineering_smoke_only` 只表示工程冒烟证据，不等同于科学验证或外部基准。
- 完整 MD 链路、复杂 Agent 自动执行和多轮实验闭环不作为 V1 阻断项；至少一条 K8s Job 或 SSH Job 受控执行路径必须通过验收。

### 6.1 明确限制

- GPU 实际分配仍由 GPUAllocator + GPUAllocation 管理；当前 scope quota 只展示 GPU 请求量，不做第二套硬配额。
- V1 必须在真实或等价环境中验收至少一条 K8s Job 或 SSH Job 路径，覆盖资源准入、提交、状态同步、取消、日志和结果回收；Slurm 专用 Adapter 可后置。
- 生产封版前仍需在干净环境中执行一次全量后端回归，避免历史残留测试进程污染耗时和结果判断。
- Artifact 列表已支持按 `manifest_json.metadata.model_name`、`model_version`、`evidence_level`、`endpoint_ref` 和 `applicability_domain_status` 做服务端筛选；更复杂的模型族聚合仍属于规模化增强。
