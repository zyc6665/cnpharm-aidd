## 1. 引言

### 1.1 编写目的

本文档用于指导 AI 制药研发平台在开发、演示、私有服务器和集群生产环境中的部署、配置、启动、停止、备份、恢复、监控、安全加固和故障处理。

### 1.2 部署目标

平台部署应满足以下目标：

- 支持本地开发、单机演示、私有服务器和集群生产四类形态。
- Web 服务、任务队列、文件存储和计算执行解耦。
- 支持 builtin、python、docker、ssh、remote_api、k8s、slurm 执行方式。
- 支持任务取消、日志查看、状态同步和结果回收。
- 支持 Artifact 文件权限控制和企业内网安全部署。

## 2. 环境规划

| 环境 | 使用场景 | 数据库 | 文件存储 | 队列 | 执行方式 |
| --- | --- | --- | --- | --- | --- |
| DEV | 开发联调 | SQLite | local | direct / memory | builtin、python、少量 ssh |
| DEMO | 单机演示 | SQLite/PostgreSQL | local/MinIO | Celery + Redis | builtin、python、docker |
| LAB | 实验室私有部署 | PostgreSQL | MinIO | Celery + Redis | docker、ssh、remote_api |
| PROD | 多用户生产/集群 | PostgreSQL HA | MinIO/S3 | Redis/RabbitMQ | docker、k8s、slurm、ssh、remote_api |

### 2.1 版本部署范围

| 版本 | 推荐部署形态 | 必启组件 | 可选组件 | 说明 |
| --- | --- | --- | --- | --- |
| V1 首期交付 | DEMO 或 LAB | Backend、Frontend、PostgreSQL/SQLite、Redis、MinIO/local、Worker、builtin、docker、ssh、remote_api | K8s/Slurm 只保留配置入口 | 验收主链路和基础执行，不以 K8s/Slurm 生产化为阻断。 |
| V1.1 决策与反馈 | LAB | PostgreSQL、Redis、MinIO、Worker 分队列、监控、审计日志、科学证据附件存储 | 更多 worker 节点、对象存储生命周期策略、实验导入隔离区 | 支撑任务工作台、保存视图、候选决策、实验摘要导入、预测-实测比较和质量看板。 |
| V2 生产化扩展 | PROD | PostgreSQL HA、对象存储、队列 HA、K8s/Slurm Adapter、监控告警、备份恢复 | 多副本 API、GPU 队列、成本/配额统计 | 支撑对接、MD、批量筛选和生产级重计算。 |

### 2.2 验收规模假设

| 部署形态 | 用户规模 | 任务规模 | Artifact 规模 | 文件规模 | 并发假设 |
| --- | --- | --- | --- | --- | --- |
| 单机演示 | 1-10 用户 | 500-1000 任务 | 1000 Artifact | 单文件 500 MB 内 | 1-3 个轻任务，1 个重任务 |
| 实验室私有部署 | 10-50 用户 | 5000-20000 任务 | 10000-50000 Artifact | 单文件 1-5 GB，推荐对象存储 | 5-20 个轻任务，2-5 个重任务 |
| 集群生产部署 | 50+ 用户 | 50000+ 任务 | 100000+ Artifact | 大文件走对象存储/共享存储 | 按队列和资源 tier 配置 |

V1 默认验收按实验室私有部署低档规模设计：不少于 10 个用户、5000 条任务、10000 个 Artifact、500 MB 单文件、20 节点工作流和 Docker/SSH/Remote API 基础执行。

## 3. 逻辑部署架构

```text
用户浏览器
  │
  ▼
Nginx / HTTPS Gateway
  │
  ├─ Frontend Static
  │
  └─ FastAPI Backend
       │
       ├─ PostgreSQL / SQLite
       ├─ Redis / RabbitMQ
       ├─ MinIO / S3 / Local Storage
       ├─ Celery Workers
       │    ├─ builtin worker
       │    ├─ python worker
       │    ├─ docker worker
       │    ├─ ssh worker
       │    ├─ remote api worker
       │    ├─ k8s job adapter
       │    └─ slurm job adapter
       └─ WebSocket / Polling status channel
```

## 4. 主机与资源建议

### 4.1 单机演示配置

| 资源 | 建议配置 |
| --- | --- |
| CPU | 8 核以上 |
| 内存 | 16 GB 以上 |
| 磁盘 | 200 GB SSD |
| OS | Linux x86_64 |
| 组件 | Frontend、Backend、Redis、MinIO、Worker、SQLite/PostgreSQL |

### 4.2 实验室私有部署配置

| 节点 | 建议配置 | 职责 |
| --- | --- | --- |
| Web/API 节点 | 8C/16G | Nginx、Frontend、Backend |
| Worker 节点 | 16C/32G | Celery、builtin、python、docker、ssh submitter |
| 数据节点 | 8C/32G/SSD | PostgreSQL、Redis、MinIO |
| 计算节点 | 按工具需求 | GPU/CPU 模型、对接、MD、批量任务 |

V1 实验室私有部署建议至少拆分 Web/API、Worker、数据存储三类职责；如果单机部署，应通过进程和目录隔离避免 Web 服务与重任务互相影响。

### 4.3 集群生产配置

| 组件 | 建议 |
| --- | --- |
| API | 多副本部署，前置负载均衡。 |
| Worker | 按 executor 类型拆分队列和资源组。 |
| PostgreSQL | 主备或托管高可用。 |
| Redis/RabbitMQ | 持久化队列，监控堆积。 |
| MinIO/S3 | 多盘或对象存储服务，启用版本和生命周期策略。 |
| K8s/Slurm | 重计算任务独立资源池，不与 Web 服务争抢资源。 |

### 4.4 队列与 Worker 规划

| 队列 | 任务类型 | 建议 worker | 资源策略 |
| --- | --- | --- | --- |
| `default` | 普通 API 触发、轻量后台任务 | 1-2 个通用 worker | CPU 小配额，快速响应。 |
| `builtin` | Fetch PDB、Fetch PubChem、RDKit、轻量转换 | 1-2 个 builtin worker | 限制单任务时长，避免阻塞。 |
| `docker` | 容器化 CADD 工具 | docker worker | 限制 CPU、内存、运行时长和挂载目录。 |
| `ssh` | 远端服务器或登录节点任务 | ssh worker | 限制并发，保留远端 job handle。 |
| `remote_api` | 自托管模型服务 | remote api worker | 配置超时、重试、取消和 allowlist。 |
| `cluster` | K8s/Slurm 生产任务 | k8s/slurm adapter worker | 按 resource tier、队列和优先级调度。 |

V1 至少需要 `default`、`builtin`、`docker`、`ssh`、`remote_api` 的逻辑队列；K8s/Slurm 可在 V2 启用。

## 7. 部署步骤

### 7.1 本地开发部署

适用：开发联调、问题复现、快速验证。

步骤：

1. 准备 Python、Node.js 和系统依赖。
2. 配置本地 `.env`，使用 SQLite、local storage、memory/direct queue。
3. 启动后端 API。
4. 启动前端开发服务。
5. 使用本地文件系统保存上传和输出。

当前开发环境参考：

```text
Backend: python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
Frontend: http://localhost:8585
Database: backend/storage/scitool.db
```

### 7.2 单机演示部署

适用：小团队试用、客户演示、离线环境验收。

步骤：

1. 安装 PostgreSQL 或确认 SQLite 演示模式。
2. 安装 Redis 和 MinIO。
3. 构建前端静态资源。
4. 使用 systemd 或进程管理器启动 Backend、Worker、Nginx。
5. 配置 Nginx 反向代理 `/api` 到 Backend，静态资源指向前端构建目录。
6. 导入初始管理员、工具模板、Artifact registry 和 renderer registry。
7. 执行 smoke test。

### 7.3 私有服务器部署

适用：实验室内部长期使用。

步骤：

1. 部署 PostgreSQL、Redis、MinIO。
2. Backend、Frontend、Worker 分进程或分节点部署。
3. 启用 Docker executor 和 SSH executor。
4. 配置 Remote API allowlist。
5. 配置对象存储桶、访问密钥和备份策略。
6. 配置 HTTPS、访问控制和日志采集。
7. 通过端到端验收链路验证。

### 7.4 K8s 生产部署

适用：容器化生产环境和弹性重计算。

设计建议：

- Frontend、Backend、Worker 使用 Deployment。
- PostgreSQL、Redis、MinIO 可使用托管服务或 StatefulSet。
- 重计算工具使用 K8s Job 独立提交。
- 使用 namespace 隔离平台和计算任务。
- 使用 ResourceQuota、LimitRange、NodeSelector、Toleration 管理资源。

部署对象：

| 对象 | 说明 |
| --- | --- |
| Deployment | frontend、backend、worker。 |
| Service | API、frontend、MinIO、Redis。 |
| Ingress | HTTPS 入口。 |
| Secret | 数据库密码、对象存储密钥、JWT secret。 |
| ConfigMap | 非敏感配置。 |
| Job | 单次工具任务执行。 |
| PVC | 可选共享缓存和 staging。 |

### 7.5 Slurm 集群接入

适用：已有 HPC 集群、MD、批量对接和超算环境。

接入方式：

1. 平台 Worker 通过 SSH 连接 Slurm 登录节点。
2. Run Preparation 准备输入并上传到共享文件系统或对象存储 staging 区。
3. Slurm Adapter 生成 sbatch 脚本并提交。
4. 周期性调用 squeue/sacct 同步状态。
5. 取消任务时调用 scancel。
6. 完成后回收输出并校验 Result Manifest。

## 8. 启停与发布

### 8.1 启动顺序

1. 数据库。
2. 对象存储。
3. Redis/RabbitMQ。
4. Backend API。
5. Worker。
6. Frontend / Nginx。
7. executor 健康检查。

### 8.2 停止顺序

1. 停止接入流量或进入维护模式。
2. 停止新任务提交。
3. 等待可完成任务结束，必要时取消长任务。
4. 停止 Worker。
5. 停止 Backend。
6. 停止 Frontend / Nginx。
7. 停止 Redis、对象存储和数据库。

### 8.3 发布流程

1. 备份数据库和关键配置。
2. 构建前端和后端镜像或安装包。
3. 在测试环境运行迁移和 smoke test。
4. 灰度或维护窗口发布。
5. 验证登录、项目、工具、任务、工作流、文件下载。
6. 观察日志、队列和错误率。
7. 发布失败时按回滚预案恢复。

## 9. 数据备份与恢复

### 9.1 备份对象

| 对象 | 备份方式 | 频率建议 |
| --- | --- | --- |
| PostgreSQL | `pg_dump` 或物理备份 | 每日全量，关键环境增加增量/WAL。 |
| SQLite | 停机或一致性快照复制 | 演示环境每日。 |
| MinIO/S3 | 桶复制、生命周期策略、离线快照 | 每日或按项目策略。 |
| 配置文件 | Git/配置中心/加密备份 | 每次变更。 |
| 工具镜像 | 镜像仓库保留 digest | 每次发布。 |
| SSH/K8s/Slurm 凭据 | 安全密钥管理系统 | 每次变更。 |
| 模型卡与算法说明 | 对象存储 + checksum + 数据库索引 | 每次工具版本发布或撤回。 |
| 验证记录与科学报告 | 对象存储 + 数据库索引 | 每次验证运行或人工审核。 |
| 实验摘要导入物 | 对象存储隔离区和 Artifact 文件 | 每次导入确认，拒绝记录按策略保留。 |
| 候选决策导出 | 对象存储或按需生成，保留快照索引 | 每次决策版本发布。 |

### 9.2 恢复步骤

1. 停止 Backend 和 Worker。
2. 恢复数据库到目标时间点。
3. 恢复对象存储文件。
4. 恢复配置和密钥。
5. 启动基础设施、Backend、Worker 和 Frontend。
6. 运行数据一致性检查：TaskOutput、File、ArtifactVersion、ArtifactFile 引用。
7. 执行 smoke test 和关键工作流测试。

### 9.3 一致性检查

恢复后需检查：

- 数据库中 File 记录是否能在对象存储找到。
- ArtifactVersion 的 required roles 是否完整。
- TaskOutput 是否能关联输出文件。
- Workflow Node Task Binding 是否能找到 Task。
- 下载接口权限是否正常。
- 模型卡、验证记录和工具版本 checksum 是否一致。
- `assay_result@1` 的 measurement_table、metadata_json、import_report_json 是否齐全。
- CandidateDecision 导出是否仍能定位到 CandidateSet、ArtifactVersion 和操作者。
- PredictionMeasurementLink 的排除原因、单位转换和配对规则版本是否可读。

## 10. 监控和告警

### 10.1 监控指标

| 类别 | 指标 |
| --- | --- |
| API | QPS、延迟、错误率、认证失败数。 |
| 数据库 | 连接数、慢查询、磁盘、锁等待。 |
| 队列 | 待执行任务数、运行任务数、失败任务数、队列等待时间。 |
| Worker | 存活数、内存、CPU、任务成功率。 |
| 存储 | 桶容量、对象数量、下载失败率。 |
| Executor | docker/ssh/remote_api/k8s/slurm 成功率、取消成功率、日志同步状态。 |
| GPU/CPU | 使用率、显存、队列等待、节点故障。 |
| 任务工作台 | 查询延迟、分页耗时、筛选耗时、系统视图命中数。 |
| Artifact | Artifact 数量、版本数量、下载失败率、预览生成耗时、对象缺失数。 |
| 工具治理 | 工具发布次数、contract validation 失败率、smoke test 失败率。 |
| 科学证据 | 模型卡缺失数、验证记录过期数、证据等级不匹配数、scientific profile 校验失败率。 |
| 实验导入 | 导入成功率、拒绝行数、重复行数、无法配对行数、全无效导入数。 |
| 候选决策 | 快照数量、导出失败率、重开次数、待审批决策数。 |
| 审计 | 下载审计量、权限拒绝量、配置变更量、Agent 审批量。 |

### 10.2 告警建议

| 告警 | 触发条件 |
| --- | --- |
| API 错误率高 | 5xx 比例持续超过阈值。 |
| 队列堆积 | pending 任务数或等待时间超过阈值。 |
| Worker 掉线 | 活跃 Worker 数低于期望。 |
| 存储容量不足 | 使用率超过 80%。 |
| 远端执行失败率高 | executor 连续失败或取消失败。 |
| Artifact 持久化失败 | Result Manifest 校验失败率异常。 |
| 下载越权尝试 | 权限拒绝次数异常。 |
| 任务查询变慢 | 任务列表或系统视图查询超过阈值。 |
| Preview 队列堆积 | 异步预览任务等待时间超过阈值。 |
| 工具发布失败率高 | Tool Contract validation 或 smoke test 连续失败。 |
| Executor 状态失联 | Docker/SSH/Remote API/K8s/Slurm 连续 inspect 失败。 |
| 模型证据缺失 | 已发布预测/打分工具缺模型卡、验证记录或 endpoint 定义。 |
| 实验导入异常 | 全无效导入、拒绝行比例或重复导入请求超过阈值。 |
| 配对失败率高 | 预测-实测比较中 not_comparable 或 unresolved 超过阈值。 |

## 11. 安全加固

| 安全项 | 加固要求 |
| --- | --- |
| HTTPS | 生产必须启用 HTTPS。 |
| 密钥 | SECRET_KEY、数据库密码、对象存储密钥不得提交到代码库。 |
| 文件下载 | 所有下载通过后端鉴权接口或短期签名 URL。 |
| Remote API | 启用 allowlist，禁止 loopback、link-local、metadata service 和跨 host 重定向。 |
| Docker | 限制容器权限、资源、网络和挂载目录。 |
| SSH | 使用专用账号和最小权限目录，禁止共享管理员私钥。 |
| K8s | 使用 namespace、service account、RBAC 和 resource quota。 |
| Slurm | 使用受控分区、QoS、时间限制和作业账号。 |
| 审计 | 记录管理员工具发布、任务取消、Artifact 下载和 Agent 审批。 |
| 科学数据 | 模型卡、验证记录、实验摘要导入物和候选决策导出按项目权限和审计策略访问。 |

### 11.1 权限边界

| 角色 | 运维权限边界 |
| --- | --- |
| 科研人员 | 只能访问授权项目和本人/项目任务，不接触执行器凭据。 |
| 项目负责人 | 管理项目成员、模板、项目资产归档，不管理全局工具和执行器。 |
| AI 模型开发者 | 提交工具版本和样例，不直接发布到全局可用。 |
| 平台管理员 | 管理工具、标签、Artifact 标准、renderer、审计和策略。 |
| 运维 / 集群管理员 | 管理基础设施、队列、凭据和执行资源，不默认绕过科研数据权限。 |

下载、跨项目绑定、工具发布、模型卡发布/撤回、验证记录审批、实验摘要导入、候选决策导出、任务取消、Agent 审批和治理配置变更必须写入审计日志。

## 12. 运维操作

### 12.1 常规巡检

每日巡检：

- API 健康检查。
- 队列长度和失败任务。
- Worker 存活状态。
- 存储容量。
- 数据库连接和慢查询。
- Remote API、SSH、Docker、K8s、Slurm executor 健康。

每周巡检：

- 备份恢复抽检。
- 工具失败率统计。
- 大文件和过期任务输出清理策略检查。
- 权限和管理员操作审计。
- 模型卡、验证记录、endpoint 和 score definition 发布状态抽检。
- 实验摘要导入拒绝率、配对失败率和候选决策待审批数检查。

### 12.2 常见故障处理

| 故障 | 排查路径 | 处理建议 |
| --- | --- | --- |
| 页面无法打开 | Nginx、Frontend 静态资源、Backend 健康 | 重启 Web 服务，检查反向代理。 |
| 登录失败 | 认证配置、数据库用户、Token secret | 检查用户状态和 SECRET_KEY。 |
| 任务一直 running | Worker、Executor 状态同步、远端 job 状态 | 手动 inspect executor，必要时同步或取消。 |
| Artifact 下载失败 | 权限、File 记录、对象存储路径 | 检查项目权限和对象是否存在。 |
| 工作流节点不可运行 | Tool Contract、Run Preparation、Artifact readiness | 查看 Readiness Report 和节点绑定。 |
| Remote API 注册失败 | allowlist、manifest、网络、schema validation | 检查 URL、超时、重定向和 manifest 格式。 |
| SSH 任务失败 | SSH key、远端目录、环境、日志 | 检查远端账号权限和脚本路径。 |
| Docker 任务失败 | 镜像、资源限制、挂载目录、输出 manifest | 检查镜像 digest 和容器日志。 |
| 工具发布失败 | Tool Contract、Result Manifest、smoke test、标签/role/renderer 引用 | 查看发布校验报告，修正后重新提交。 |
| 任务列表查询慢 | 数据库索引、筛选条件、分页、任务规模 | 检查任务索引和慢查询，必要时归档历史任务。 |
| Preview 生成慢 | 文件大小、renderer、preview worker、对象存储 | 启用摘要预览或异步 preview，检查 preview 队列。 |
| Result Manifest 不合规 | 输出文件缺失、role 未注册、checksum 不匹配 | 标记任务失败或 partial_failed，通知工具维护者。 |
| 模型证据不匹配 | 工具版本、模型卡 checksum、endpoint 或运行环境不一致 | 降级显示 unknown/未验证，暂停对应科学声明并补验证记录。 |
| 实验导入失败 | 字段映射、单位、endpoint、molecule/state 或 batch 无法识别 | 查看导入预览和拒绝报告，修正映射后生成新版本。 |
| 预测-实测配对为空 | endpoint、单位、protocol、qualifier 或结构状态不兼容 | 检查配对规则版本和排除原因，不手工填零。 |

## 15. 回滚预案

发布失败时按以下步骤回滚：

1. 停止新流量接入。
2. 停止 Worker 接收新任务。
3. 保留当前日志和失败现场。
4. 回滚前端静态资源和后端服务版本。
5. 如数据库已迁移且不兼容，恢复发布前备份。
6. 恢复对象存储配置。
7. 启动服务并执行基础验收。
8. 形成故障记录和修复计划。
