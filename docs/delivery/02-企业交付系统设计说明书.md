## 1. 引言

### 1.1 编写目的

本文档用于说明 AI 制药研发平台的总体设计、领域模型、模块划分、关键流程、接口契约、数据设计、安全设计、异常处理和测试设计，为研发实现、代码评审、集成测试、部署上线和企业交付提供系统设计依据。

### 1.2 设计原则

| 原则 | 说明 |
| --- | --- |
| 标准 Artifact 驱动 | 工作流和智能体基于平台标准 Artifact 类型、role 和 metadata 处理上下游。 |
| Tool Contract 先行 | 新工具先形成 Tool Contract，再进入工具库、工作流和 Agent。 |
| Run Preparation 权威 | 所有运行入口共享运行准备逻辑，前端只做预览展示。 |
| 深模块 Interface | 核心复杂度收敛到小而稳定的 Interface 内部，避免页面和工作流复制规则。 |
| 执行器隔离 | K8s Job 和 SSH Job 通过 Executor Gateway 屏蔽差异；Docker/Python 作为 Job runtime。 |
| 结果标准化 | 工具输出通过 Result Manifest 持久化为 Standard Artifact。 |
| 可审计可追踪 | Task、ArtifactVersion、WorkflowRun、Agent Plan 均保留可追踪记录。 |

### 1.3 与需求基线的对应关系

本设计以需求规格说明书中的 V1 首期交付范围作为默认实现边界。V1 目标是打通 `Fetch PDB -> Protein Preparation -> LVpocket` 与 `Fetch PubChem -> Ligand Preparation -> RDKit -> ADMET` 两条核心链路，并证明 Standard Artifact、Tool Contract、Run Preparation、Result Manifest 和 Executor Gateway 这条地基链路可用。

| 需求基线能力 | 设计承载模块 | V1 设计要求 | 后续扩展 |
| --- | --- | --- | --- |
| 标准 Artifact 驱动 | Artifact Registry、Artifact Persistence、Lineage | 冻结核心 Artifact type、role、metadata 和 readiness 判定 | 扩展 docking、MD、ADMET 报告等类型 |
| 工具统一接入 | Tool Contract、Tool Release、Admin Governance | 支持 Tool Package、K8s Job、SSH Job 归一化 | 旧 executor 迁移和工具质量治理 |
| 多入口运行一致 | Run Preparation、Task Command | 工具详情页、节点独立运行、全流程运行共享 PreparedRun | Agent 计划执行也复用同一入口 |
| 工作流傻瓜化 | Workflow Orchestration、Node Task Binding | slot-to-slot edge、保存加载、节点任务恢复 | 工作流模板、失败续跑、批量流程 |
| 结果可视化 | Renderer Registry、Preview Payload、Download Options | protein、ligand、pocket、table、report 基础展示 | 大文件异步 preview、MD trajectory 展示 |
| 管理可治理 | Governance Registry、AuditLog、Quality Metrics | 标签分类、工具审核、资源配置和基础审计 | 数据治理自动化、高级审计报表 |

V1 不把完整 MD 生产链路、复杂 Agent 自动编排和多租户计费作为验收阻断项；受控 SSH Job 或 K8s Job 执行路径属于当前基础执行基线。Slurm 仅作为后续 Adapter 或 SSH 登录节点实现细节。

V1.1 在不替代 ELN/LIMS 的前提下补候选决策、受控实验摘要导入、预测-实测比较和科学质量看板；V2 再引入多轮 DesignCycle、对接/MD 生产链路和集群重计算。任何版本的运行成功都不自动等同于科学验证通过。

### 2.2 架构主线

| 主线 | 核心对象 | 设计说明 |
| --- | --- | --- |
| 数据主线 | Standard Artifact、ArtifactVersion、FileRole、Lineage | 把文件变成平台可理解、可验证、可复用的数据资产。 |
| 能力主线 | Tool、ToolVersion、Tool Contract、Tool Package | 统一描述工具能力、输入输出、资源和执行方式。 |
| 执行主线 | Run Preparation、Task、Execution Record、Executor Gateway | 所有运行入口最终落成 Task，由执行器完成运行。 |
| 编排主线 | WorkflowDefinition、WorkflowRun、Node Task Binding | 工作流只表达节点、边、状态和任务绑定，不复制工具规则。 |
| 展示主线 | Renderer Registry、Artifact Renderer、PreviewPayload | 按 Artifact 类型和 role 复用可视化和下载逻辑。 |
| 智能主线 | Agent Plan、Plan Version、Approval、Workflow Draft | Agent 基于平台契约提出可验证计划，不绕过任务系统。 |
| 科学治理主线 | ModelCard、VerificationRecord、Scientific Result Profile、ScoreDefinition | 约束预测、生成、评分和筛选结果的证据、适用域和解释边界。 |
| 决策反馈主线 | CandidateSet、CandidateDecision、AssayResult、PredictionMeasurementLink、DesignCycle | 将计算结果、人工选择、实验摘要和复盘关联为可审查闭环。 |

## 3. 领域模型设计

### 3.1 核心聚合

| 聚合 | 主体对象 | 关键职责 | 生命周期 |
| --- | --- | --- | --- |
| 用户与组织 | User、Organization、Role | 认证、授权、成员关系 | 长期稳定 |
| 项目 | Project、ProjectMember、ProjectActivity | 研发上下文、资产归属、权限、活动流 | 长期稳定 |
| Artifact | Artifact、ArtifactVersion、ArtifactFile、ArtifactLineage | 标准科研数据和谱系 | ArtifactVersion 不可变 |
| 工具 | Tool、ToolVersion、ToolContract、ToolCategory、Tag、ToolExample | 能力声明、版本、示例和治理 | ToolVersion 不可变 |
| 任务 | Task、TaskInput、TaskOutput、TaskLog、ExecutionRecord、TaskView | 一次运行实例、执行尝试和用户视图 | 运行实例 |
| 工作流 | WorkflowDefinition、WorkflowRun、WorkflowNode、WorkflowEdge、NodeTaskBinding | 编排定义、运行状态和节点任务 | 定义可版本化，运行实例可追踪 |
| 智能体 | Conversation、AgentRun、PlanVersion、PlanDecision | 计划、解释、审批和审计 | PlanVersion 不可变 |
| 治理 | GovernanceRegistry、AuditLog、ToolQualityMetric、RendererMapping | 标签、分类、标准、审核、审计和质量治理 | 配置可更新，审计不可变 |
| 执行资源 | ExecutorConfig、ResourceProfile、ExecutionHandle、QueueMetric | 执行环境、资源画像和队列状态 | 配置可更新，执行记录不可变 |
| 科学证据 | ModelCard、VerificationRecord、EndpointDefinition、ScoreDefinition | 模型说明、验证证据、endpoint 和评分协议 | 证据记录不可变，发布状态可治理 |
| 候选决策 | CandidateSet、CandidateDecision | 固定候选集合和人工决策快照 | 决策版本不可变，更正生成新版本 |
| 实验反馈 | AssayResult、CompoundBatch、PredictionMeasurementLink、DesignCycle | 实验摘要、外部批次引用、预测-实测配对和轮次复盘 | ArtifactVersion 不可变，轮次状态可变 |

### 3.2 领域关系

```text
Project 1 ── * Artifact
Project 1 ── * Task
Project 1 ── * WorkflowDefinition
Project 1 ── * Conversation

Tool 1 ── * ToolVersion
ToolVersion 1 ── 1 ToolContract
ToolVersion 1 ── * Task

Task 1 ── * ExecutionRecord
Task 1 ── * TaskOutput
TaskOutput * ── * ArtifactVersion

WorkflowDefinition 1 ── * WorkflowRun
WorkflowRun 1 ── * NodeTaskBinding
NodeTaskBinding * ── 1 Task

ArtifactVersion * ── * ArtifactVersion 通过 ArtifactLineage 关联

Project 1 ── * CandidateSet
CandidateSet 1 ── * CandidateDecision
Project 1 ── * DesignCycle
DesignCycle * ── * CandidateDecision
DesignCycle * ── * AssayResult
AssayResult * ── * PredictionMeasurementLink
ToolVersion 1 ── * ModelCard / VerificationRecord
```

### 3.3 生命周期规则

- ToolVersion、ArtifactVersion、PlanVersion 应不可变。
- Task 是用户可见运行实例，ExecutionRecord 是底层执行尝试。
- 任务重试创建新的 ExecutionRecord，但保留原 Task 语义。
- 工作流保存时必须保留 contract snapshot、节点、边、workflow inputs 和 Node Task Binding。
- 跨项目复用 ArtifactVersion 必须显式导入或复制，不能静默跨项目绑定。

### 3.4 角色权限设计

系统采用“平台角色 + 项目成员角色 + 对象级权限”组合授权。平台角色控制全局治理入口，项目成员角色控制项目内资产访问，对象级权限用于文件下载、任务操作、工作流模板和 Agent 计划审批。

| 能力域 | 权限判定对象 | 关键规则 |
| --- | --- | --- |
| 项目空间 | Project、ProjectMember | 项目成员可访问项目资产；项目负责人可管理成员、模板和归档。 |
| Artifact | Project、ArtifactVersion、File | 预览和下载必须校验项目权限；跨项目复用必须导入或复制。 |
| 工具 | ToolVersion、ToolRelease | 已发布工具可运行；草稿、禁用、废弃工具只能由授权人员查看或验证。 |
| 任务 | Task、ExecutionRecord | 用户可查看本人或项目授权任务；取消和重试需校验任务状态和权限。 |
| 工作流 | WorkflowDefinition、WorkflowRun | 项目内工作流按项目权限控制；模板发布需要项目负责人或管理员权限。 |
| 智能体 | PlanVersion、PlanDecision | 未审批计划不能执行；Agent 不能调用未授权工具或 Artifact。 |
| 科学证据 | ModelCard、VerificationRecord、EndpointDefinition、ScoreDefinition | 模型卡和验证记录按工具发布权限治理，项目外部验证按项目权限访问。 |
| 候选与实验 | CandidateSet、CandidateDecision、AssayResult、DesignCycle | 候选决策、实验摘要和预测-实测报告按项目权限访问，更正保留版本历史。 |
| 管理后台 | GovernanceRegistry、AuditLog | 全局配置和审计默认仅平台管理员可访问。 |
| 执行资源 | ExecutorConfig、QueueMetric | 运维可管理执行资源，但不默认绕过科研数据权限。 |

所有权限拒绝事件应进入审计日志，文件下载、工具发布、任务取消、Agent 审批和配置变更必须可检索。


职责：运行前解析输入来源，计算 Binding Decision，校验权限和 Artifact readiness，完成上传 staging、role 选择、metadata 校验、legacy 参数投影和资源画像准备。

## 5. 关键流程设计

### 5.1 工具运行流程

```text
Run Surface
  -> Tool Contract Module 加载契约
  -> Run Preparation preview 展示预检
  -> Run Preparation prepare 生成 PreparedRun
  -> Task Command 创建 Task
  -> Executor Gateway 提交执行
  -> Executor Gateway collect 输出
  -> Result Manifest 校验
  -> Artifact Persistence 持久化 ArtifactVersion
  -> Renderer Registry 提供预览和下载
```

### 5.2 工作流节点绑定流程

```text
Workflow edge: source_node.output_slot -> target_node.input_slot
  -> 读取 source output slot 的 Artifact type、role、cardinality
  -> 读取 target input slot 的 accepted_versions、required_roles、readiness_policy
  -> Run Preparation 计算 Binding Decision
  -> ready: 自动绑定
  -> needs_preparation: 提示插入准备工具
  -> needs_conversion: 提示插入转换工具
  -> needs_selection: 用户选择具体 ArtifactVersion 或结果项
  -> invalid: 禁止运行并给出原因
```

### 5.3 Result Manifest 持久化流程

```text
Executor collected outputs
  -> 读取 result_manifest.json
  -> 校验 output_slot 存在于 Tool Contract
  -> 校验 artifact type 存在于 Artifact Registry
  -> 复算文件 checksum 和 size
  -> 校验 required roles 和 metadata
  -> 生成 ArtifactVersion、ArtifactFile、ArtifactLineage
  -> 更新 TaskOutput 和 Node Task Binding
```

### 5.4 历史 Remote API 工具迁移流程

本流程只适用于需要迁移的既有 Remote API 工具，不是新模型上线方式。新工具按 Tool Package 绑定 K8s Job 或 SSH Job，见 [执行环境与资源调度重构方案](../architecture/19-执行环境与资源调度重构方案.md)。

```text
管理员填写 Remote API URL
  -> 平台拉取 manifest
  -> SSRF / redirect / size / timeout 校验
  -> manifest 转 Tool Contract
  -> 拉取 examples 和 smoke test 描述
  -> contract validation
  -> 管理员审核标签、分类、资源画像
  -> 发布工具
```

### 5.5 任务工作台查询流程

```text
用户进入任务中心
  -> Task View Module 加载系统视图和用户保存视图
  -> 选择我的任务 / 项目任务 / 工作流任务 / 需要关注 / 重计算队列
  -> Query Builder 组合权限、筛选、排序、分页和分组
  -> Task Command / ExecutionRecord 查询运行状态
  -> Artifact / Workflow 查询补齐输出和节点上下文
  -> 详情侧栏展示输入、输出、日志、错误、Artifact 和操作按钮
```

任务工作台必须避免一次性加载全部任务。列表、分组统计、详情侧栏应按需查询，并支持 5000 条任务规模下的筛选和搜索。

### 5.6 保存工作流恢复流程

```text
加载 WorkflowDefinition
  -> 读取 nodes、edges、workflow inputs、contract snapshots
  -> 对每个节点加载当前 Tool Contract
  -> 当前 contract 兼容：hydrate 缺失 slot
  -> 当前 contract 不兼容：保留 snapshot 并提示重新预检
  -> 加载 Node Task Binding
  -> 重新校验 ArtifactVersion 权限和 lifecycle
  -> 输出 HydratedWorkflow 和 WorkflowReadiness
```

该流程用于避免保存工作流加载后出现空节点、任务丢失或旧 ArtifactVersion 被错误绑定。

### 5.7 治理发布流程

```text
管理员提交配置或工具发布
  -> Governance Registry / Tool Contract validation
  -> Artifact type、role、renderer、executor 引用完整性校验
  -> smoke test 或 preview check
  -> 生成 release report
  -> publish 或 reject
  -> 写入 AuditLog
```

治理发布流程覆盖工具发布、标签分类、Artifact 标准、renderer 映射和 executor 配置，保证“管理员好管理”的需求落到统一机制。

### 5.8 科学结果发布流程

```text
模型或算法工具提交
  -> Tool Contract validation
  -> 模型卡/算法说明校验
  -> endpoint / score definition 引用校验
  -> smoke run 记录工程运行证据
  -> 科学基准或项目外部验证记录按需关联
  -> 计算展示证据等级 E0-E4
  -> 发布、限制用途或拒绝
```

科学结果发布流程只决定“可以如何解释结果”，不替代工具执行发布状态。V1 可人工归档模型卡和验证附件，V1.1 再自动接入工具发布门禁和质量看板。

### 5.9 候选决策流程

```text
molecule_table / ranked_molecules ArtifactVersion
  -> 固定 CandidateSet 和筛选规则
  -> 展示预测、评分、实测、证据等级和不可比状态
  -> 科研人员选择 select / exclude / hold
  -> 记录理由、阈值、操作者和时间
  -> 生成 CandidateDecision 快照
  -> 导出候选清单或进入实验摘要回写
```

CandidateDecision 必须引用不可变输入版本；后续模型重跑或实验更正不得覆盖原快照。

### 5.10 实验反馈与预测-实测对齐流程

```text
受控 CSV/JSON 实验摘要
  -> 字段映射和导入预览
  -> 行级校验 molecule/state、CompoundBatch、endpoint、单位、protocol、qualifier
  -> 确认有效子集
  -> 生成 assay_result@1 ArtifactVersion 和导入报告
  -> 按配对规则生成 PredictionMeasurementLink
  -> 输出比较报告和排除原因
```

全无效导入不得生成可用 AssayResult；删失值、重复测量、单位转换和 protocol 差异必须保留原始值和排除原因。

## 8. 安全设计

| 安全项 | 设计要求 |
| --- | --- |
| 认证 | API 访问必须绑定登录用户或受控服务身份。 |
| 授权 | Project、Artifact、Task、Workflow 访问按项目成员和角色校验。 |
| 文件访问 | 文件下载通过受保护接口，不暴露真实存储路径。 |
| Remote API 兼容 | 仅管理员可迁移注册，限制协议、host、重定向、大小、超时和 checksum；不得用于新模型生产部署。 |
| 执行隔离 | K8s/SSH Job 按批准的资源档位、身份和运行目录隔离；Docker/Python 作为内部 runtime。 |
| 凭据管理 | SSH key、API token、kubeconfig、K8s Namespace 和 ServiceAccount 不进入 Tool Contract 明文字段；由执行环境绑定。 |
| 审计 | 工具发布、任务运行、Artifact 下载、Agent 审批记录审计日志。 |

### 8.1 审计事件

| 事件 | 触发动作 | 必填字段 |
| --- | --- | --- |
| 工具发布 | 发布、禁用、回滚 ToolVersion | actor、tool_version_id、action、validation_result |
| 权限变更 | 项目成员、角色或访问策略变化 | actor、project_id、target_user、before、after |
| Artifact 下载 | 预览、下载、批量打包 | actor、artifact_version_id、file_id、project_id |
| 任务操作 | 创建、取消、重试、标记已处理 | actor、task_id、operation、result |
| Agent 审批 | 批准或拒绝计划 | actor、plan_version_id、decision |
| 治理配置 | 标签、分类、role、renderer、executor 变更 | actor、registry_kind、key、version |
| 模型证据 | 发布、撤回、替换模型卡或验证记录 | actor、tool_version_id、model_card_ref、verification_ref、decision |
| 候选决策 | 创建、审批、导出或更正 CandidateDecision | actor、candidate_set_id、decision_version、operation、result |
| 实验导入 | 预览、确认、拒绝或更正 AssayResult | actor、project_id、assay_result_id、accepted_count、rejected_count |

## 9. 异常处理设计

| 异常类型 | 处理策略 | 用户提示 |
| --- | --- | --- |
| 缺少输入 | Run Preparation 返回 missing。 | 请上传文件、选择 Artifact 或连接上游节点。 |
| 类型不匹配 | 返回 invalid_type。 | 当前连线的 Artifact 类型不满足下游工具。 |
| role 缺失 | 返回 invalid_role 或 needs_preparation。 | 需要先进行准备或格式转换。 |
| metadata 不满足 | 返回 invalid_metadata。 | 当前产物缺少必要科学状态信息。 |
| 权限不足 | 返回 permission_denied。 | 无权限访问该项目或产物。 |
| 上游未完成 | 返回 waiting_upstream。 | 等待上游节点完成。 |
| 执行失败 | Task 标记 failed，保留日志。 | 查看任务日志并决定是否重试。 |
| 输出不合规 | Result Manifest 校验失败。 | 工具输出不符合平台标准，联系管理员或工具维护者。 |
| 契约升级不兼容 | 保存工作流保留 snapshot，要求重新预检。 | 工具契约已更新，请重新预检该节点。 |
| ArtifactVersion 失效 | 返回 stale_binding，阻止自动运行。 | 原绑定产物已过期、删除或无权限。 |
| 多候选输入 | 返回 needs_selection。 | 存在多个可用输入，请选择一个。 |
| Executor 断连 | 任务进入待检查或失败状态，保留执行 handle。 | 执行环境暂时不可达，请稍后查看。 |
| 大文件预览延迟 | 展示摘要或异步 preview 状态。 | 文件较大，正在生成预览。 |
| 科学证据不匹配 | 返回 evidence_mismatch 或 scientific_unknown。 | 当前模型版本、endpoint 或环境证据不足，不能作该科学声明。 |
| 评分不可比 | 返回 not_comparable。 | 当前分数协议、单位或准备策略不同，请选择可比子集。 |
| 实验导入无效 | 返回 assay_import_invalid。 | 查看字段映射、单位、endpoint、批次和拒绝行原因。 |
| 预测-实测无法配对 | 返回 no_comparable_pair。 | 没有满足身份、endpoint、单位和 protocol 规则的记录。 |

## 11. 设计落地分期

| 阶段 | 设计重点 | 必须冻结的 Interface | 验收关注 |
| --- | --- | --- | --- |
| V1 首期交付 | 主链路打通和地基统一 | Artifact Registry、Tool Contract、Run Preparation、Result Manifest、Task Command、Workflow Hydration | Fetch PDB -> Protein Preparation -> LVpocket；Fetch PubChem -> RDKit -> ADMET；工具注册；任务取消；权限下载 |
| V1.1 决策与反馈 | 任务工作台、候选决策、实验摘要、科学质量治理 | Task View、Governance Registry、Renderer Registry、Scientific Result Governance、Candidate Decision、Experimental Feedback | 大量任务查看、保存视图、工具质量看板、候选快照、实验导入、预测-实测比较 |
| V2 生产化扩展 | 重计算、智能体深化和多轮 DMTA | K8s Adapter、Slurm Adapter、Agent Plan Approval、DesignCycle、Data Lifecycle Policy | 对接/MD、批量筛选、Agent 可执行计划、审计报表、多轮复盘 |

V1 实施不得绕过 Run Preparation、Tool Contract 和 Result Manifest 做页面或工作流特判；否则会破坏后续新工具扩展能力。

## 12. 设计验收标准

1. 需求规格说明书中的 P0 需求均能映射到明确设计模块。
2. 新工具接入路径只依赖 Tool Contract、Artifact Registry、Result Manifest、Renderer Registry 和 Executor 配置。
3. 工具详情页、节点独立运行、全流程运行和 Agent 计划共享 Run Preparation 和 Task Command。
4. 工作流不直接解析工具私有文件路径或执行器输出目录。
5. 任务中心支持系统视图、筛选、分组、详情侧栏和大量任务查询设计。
6. 管理后台具备工具、标签、Artifact 标准、renderer、executor 和审计治理设计。
7. 部署架构能支撑本地开发、受控 SSH Job 和 Kubernetes Job；Slurm 专用接入作为后续可选演进。
8. 科学结果能追溯 endpoint、单位、模型版本、模型卡、证据等级和适用域状态。
9. 候选决策、实验摘要导入和预测-实测对齐有明确模块、数据对象、接口和异常处理。
10. V1、V1.1、V2 的设计边界清楚，不把后续模板或文档设计表述为已上线能力。
