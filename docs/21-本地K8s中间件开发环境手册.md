# 21 · 本地 K8s 中间件开发环境手册

> 定位：**本地开发 / 演示**环境，不是甲方交付形态。中间件（PostgreSQL / Redis / MinIO）
> 跑在 kind 集群里，后端（FastAPI）与前端（Vite）仍在本机直接启动；集群内服务通过
> `kubectl port-forward` 暴露到本机固定端口，以便“后端连真实 PG、真实对象存储”，
> 避免用 SQLite + 本地目录把问题掩盖到上线才暴露。

## 1. 拓扑

| 组件 | 命名空间 | 工作负载 | 持久卷 | 本机端口 |
|---|---|---|---|---|
| PostgreSQL 16 | `sciminer-system` | `deploy/sciminer-postgres` | `sciminer-postgres-data` | `15432 → 5432` |
| Redis 7 | `sciminer-system` | `deploy/sciminer-redis` | `sciminer-redis-data` | `16379 → 6379` |
| MinIO | `sciminer-storage` | `deploy/sciminer-minio` | `minio-data` | `19000 → 9000`（API）/ `19001 → 9001`（控制台） |

- 集群：`kind` 三节点（Docker Desktop 内置，`desktop-control-plane` / `desktop-worker` / `desktop-worker2`）。
- 清单：`deploy/kubernetes/namespace.yaml`、`data-services-dev.yaml`、`minio-dev.yaml`、`minio-dev-nodeport.yaml`。
- 镜像使用标准 `docker.io/library/postgres:16-alpine`、`docker.io/library/redis:7-alpine`、
  `docker.io/minio/minio:RELEASE.2024-06-13T22-53-53Z`（kind 节点已预载，离线可拉；
  此前 `docker.1panel.live` 的 digest 镜像因镜像站 403 无法再拉，已改写）。

## 2. 一键拉起 / 停止

```bash
# 拉起（幂等）：建命名空间/Secret、部署三件套、启动端口转发、生成 backend/.env（仅首次）、自举管理员
bash scripts/dev_middleware_up.sh

# 只停端口转发（集群里数据继续跑）
bash scripts/dev_middleware_down.sh

# 连工作负载一起删（PVC 保留，数据不丢）
bash scripts/dev_middleware_down.sh --purge
```

随后：

```bash
cd backend && python -m alembic upgrade head && python -m uvicorn app.main:app --port 8000
cd frontend && npm run dev        # http://localhost:3000，/api 已代理到 :8000
```

## 3. 账号与密钥

- **管理员**：账号 `admin`（历史邮箱 `admin@sciminer.com`；2026-10-30 起登录用**账号名**而非邮箱），
  密码由 `scripts/dev_middleware_up.sh` 生成并写入 `backend/.tmp_mw.env` 的 `ADMIN_PASSWORD`
  （该文件被 `.gitignore` 忽略，不入库）。
- 重置/新建管理员：
  ```bash
  cd backend && python -m app.cli.ensure_admin \
    --username admin --password 'NewPass_123' --reset-password
  ```
  不带 `--reset-password` 时只校正角色/状态，不改口令。`--username` 缺省时由 `--email` 本地部分派生。
- 后端配置在 `backend/.env`（同样不入库），关键项：`DATABASE_URL`（15432）、
  `MINIO_ENDPOINT=127.0.0.1:19000`、`CACHE_BACKEND=redis`/`REDIS_PORT=16379`。
- **LDAP（可选，默认关闭）**：`LDAP_ENABLED=False` 时完全不触达目录服务；需要时在 `backend/.env` 配
  `LDAP_SERVER_URI`、`LDAP_BASE_DN`、`LDAP_USER_FILTER`、`LDAP_BIND_DN`/`LDAP_BIND_PASSWORD`、
  `LDAP_ATTR_UID/MAIL/DISPLAY_NAME`、`LDAP_START_TLS`、`LDAP_CA_CERT_FILE`、`LDAP_TLS_VALIDATE`、`LDAP_TIMEOUT_SECONDS`，
  并把对应用户的 `auth_source` 置为 `ldap`。参数改动只需重启后端，无需改代码。

## 4. 数据持久化与重建

- 三块 PVC 走 kind 默认 `local-path`，落在节点容器的磁盘上；**Pod 重建/滚动更新不会丢数据**
  （已实测：滚动更新后 59 张表、20 万级数据、MinIO 对象均保留）。
- 彻底重来（**会丢数据**）：`kubectl -n sciminer-system delete pvc --all && kubectl -n sciminer-storage delete pvc --all`，
  再执行一次 `up` 脚本（`backend/.tmp_mw.env` 里的密码必须与新建 Secret 一致，脚本会自动复用）。
- 重启 Docker Desktop 后 kind 集群会停，需重跑 `up` 脚本（`kubectl` 端口转发也要重建）。

## 5. 已知边界

- **GPU/DCU 不在此集群**：kind 跑在 WSL2 内，本机无 NVIDIA 卡，DCU 更无法透传。
  本环境只承载**数据服务**；模型任务（真实推理）不在此集群执行。
- MinIO 走 NodePort `30900/30901`，本机开发统一用 `port-forward` 的 `19000/19001`，不依赖 NodePort。
- 若端口被占用，先 `bash scripts/dev_middleware_down.sh` 再 `up`。
