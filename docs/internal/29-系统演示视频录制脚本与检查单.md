## 2. 环境前置检查单（录制前 30 分钟）

按顺序打勾，任一不满足就不要开录：

- [ ] 后端健康：`curl --noproxy '*' -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8000/docs` → `200`
- [ ] 前端可访问：浏览器打开 `http://127.0.0.1:5173` 能登录
- [ ] 数据库在 head：`python -m alembic -c backend/alembic.ini current` 与 `heads` 一致
- [ ] 10 个预置工具全部 `published`（工具管理页一眼能看完，且**没有**「mock 包」字样）
- [ ] K8s 执行侧可用：`kubectl get nodes` 全 `Ready`，且 `kubectl get jobs -n default` 无长期 `Failed`
- [ ] 镜像 digest 是当前版本：`gromacs-md` / `gmx-mmpbsa` 为 `1.0.1`（`docs/26` §7 有说明，旧 digest 跑的是旧脚本）
- [ ] **预热一条 MD 任务**：MD 单条 5~20 分钟，必须在录制前跑完，录制时只展示「已完成」的结果页
- [ ] 演示项目已建：靶点 1 个、蛋白 1 条、结构 2 条（1 条预测、1 条已准备）、口袋 3 个、候选物 ≥ 3、候选集 1 个
- [ ] **所有数据来自真实任务**：`protein_structures` / `pockets` 行上的 `task_id` 非空（这是 P0-1 之后才成立的，旧数据仍可能是种子）
- [ ] 浏览器时区与本机一致（页面时间是 naive UTC 补 Z 后展示，时区错会全体差 8 小时）
- [ ] 通知/弹窗全部关闭，任务栏隐藏，输入法切英文（避免候选框挡画面）

## 3. 分镜脚本

总时长目标 **8~10 分钟**。每段先写「这一段的目的是证明哪条需求」，录的时候不要即兴加戏。

### 段 1 登录与项目空间（约 40 秒）

- 目的：证明统一身份认证 + 项目成员访问控制（V3.0 §6.2）。
- 操作：登录 → 项目列表 → 进入演示项目 → 项目总览（6 张统计卡）。
- 旁白要点：「所有数据都在项目权限范围内，跨项目不可见」；随后用第二个账号（非成员）打开同一项目 URL，显示无权限——**这一步必须录，否则『权限』只是口头承诺**。
- 画面要点：项目总览卡片上的靶点/结构/口袋/候选物数量要与演示数据一致。

### 段 2 数据底座：导入与检索（约 70 秒）

- 目的：V3.0 §4.2 的导入、去重、相似性检索（AIYF-DATA-01/02/05）。
- 操作：数据资产页 → 导入 SDF/CSV → 列表出现新行（显示 InChIKey、分子式、2D 结构）→ 用相似性检索查一个分子。
- 旁白要点：按 InChIKey 去重；同一化合物不会因为重复导入出现两行。
- 坑位：导入文件提前放在桌面，**不要现场选文件对话框找路径**（会录到一堆无关目录）。

### 段 3 靶点与结构预测（★ §5.1 的前半，约 90 秒）

- 目的：V3.0 §4.3（AIYF-TGT-01/02）+ ★5.1「口袋预测与关键残基」的前置。
- 操作：靶点详情 → 蛋白 → 「结构预测」→ 选模型、填参数 → 提交 → 任务详情页展示**运行中进度与实时日志** → 返回结构列表，出现新的 `PREDICTED` 结构（含 pLDDT）。
- 旁白要点：结构预测产物**自动回写到结构列表**，不需要人工登记（这正是 P0-1 修的链路）。
- 坑位：结构预测单条 2~4 分钟，录制时只截「进度在动」的 3~5 秒，其余用已完成任务的结果页。

### 段 4 口袋预测与关键残基（★ §5.1 主体，约 90 秒）

- 目的：★5.1 全文——口袋位点、评分、体积、关键残基。
- 操作：结构详情 → 「口袋预测」→ 提交 → 结果 → 口袋列表（按评分排序）→ 点开某口袋 → 残基表（`is_key` 标记）→ 3D 视图里口袋框与残基高亮 → 「设为选定口袋」。
- 旁白要点：口袋与残基都来自本次任务（指着任务 ID 说这句话）；选定口袋会作为下游对接的输入。
- 画面要点：残基表要有真实的链号/残基号（`A:745` 这种），不能是 `-`。

### 段 5 分子设计（★ §5.2 截图项，约 60 秒）

- 目的：V3.0 §4.4 生成 + 评分（AIYF-MOL-01/05）。
- 操作：设计页 → 选口袋 → 选生成模型 → 填参数（数量、随机种子）→ 提交 → 结果页展示生成的分子卡片（2D 结构 + 打分）→ 加入候选集。
- 旁白要点：生成结果落成候选物，可在候选物列表与候选集里继续使用。
- 截图：本段结束暂停 3 秒，作为 ★5.2 的功能截图来源。

### 段 6 亲和力与 ADMET（★ §5.3，约 70 秒）

- 目的：V3.0 §4.5（AIYF-ADMET-01/05）。
- 操作：选候选物 → 亲和力预测 / 性质预测 → 结果页（亲和力数值 + ADMET 指标）→ 候选物详情页「相关计算结果」表 → 打开对比页看多候选物横向对比。
- 旁白要点：结果页底部有「仅作为研发辅助参考」的说明（**这句要念出来**，是 V3.0 §1.1(5) 与业务规则的要求）。
- 坑位：对比页只做「有哪些列可比」，不要现场解释模型精度。

### 段 7 虚拟筛选与分子动力学（约 90 秒）

- 目的：V3.0 §4.6（AIYF-VS-01~05）。
- 操作：对接任务提交 → 结果页（打分排序、相互作用残基）→ 打开**预热好的** MD 任务结果页 → 轨迹信息 + RMSD/Rg 曲线 + **逐残基 RMSF 图** → 下载轨迹。
- 旁白要点：MD 的 Rg 与 RMSF 是 P0-6 新增的两条曲线；曲线数据来自 `analysis.csv` / `rmsf.csv`。
- 坑位：MD 不要现场跑。

### 段 8 工作流编排（约 60 秒）

- 目的：V3.0 §4.7（AIYF-WF-01~04）+「平台预置，用户不得修改执行节点」。
- 操作：工作流页 → 选「靶点结构准备」模板 → 展示节点已连成一条链（输入→准备→结果）→ 再选「MD + 自由能」模板 → 运行 → 运行详情页看节点状态依次变化。
- 旁白要点：节点与工具由平台预置，用户只填输入与参数（这句话正是 V3.0 业务规则原文）。

### 段 9 结果追溯（★ 复盘，约 80 秒）

- 目的：V3.0 §4.8 + §6.2（AIYF-RES-01~07）。
- 操作：结果中心 → 打开任一结果 → 追溯包详情（六类元数据：输入快照含 SHA-256、执行环境含镜像 digest、运行参数含随机种子、执行过程含退出码与日志、输出产物含哈希、归属关系）→ 一键导出追溯包 JSON → 展示下载文件内容。
- 旁白要点：「任一结果详情页一键导出追溯包」是验收原文（`docs/01` §13）。
- 画面要点：追溯包里能看到**本次任务的真实任务 ID 与镜像 digest**。

### 段 10 审计与运维（约 40 秒）

- 目的：V3.0 §6.2 审计只追加、导出留痕。
- 操作：管理员 → 审计日志 → 按「动作=导出」筛选 → 看到刚才两次导出的记录（操作者/资源类型/IP/结果）。
- 旁白要点：导出的内容摘要与哈希都进了审计，内容本体不入库。

### 段 11 收尾（约 15 秒）

- 画面：项目总览，统计卡数字与开头一致。
- 一句话：「以上所有结果均来自本次演示环境中的真实任务。」

## 6. 常见失败与兜底

| 现象 | 原因 | 兜底 |
|---|---|---|
| 任务一直「运行中」 | K8s Job 未调度（GPU 被占） | 提前用 `kubectl get pods` 确认卡位空闲；预热任务就是为此 |
| 进度条不动 | 镜像未打印 `__DRP_PROGRESS__`（目前只有 GROMACS 打印） | 段 7 只讲「日志在实时滚动」，不承诺所有模型都有百分比 |
| 自由能页空白 | 镜像还是 1.0.0 旧 digest | 按 `docs/26` §7 重建并确认 `1.0.1` |
| 结构列表没有新行 | 回写失败（看日志 `domain_writeback` 标记） | 换成段 3 的「手工导入结构」路线，并当场说明这是降级路径 |
| 页面时间差 8 小时 | 浏览器时区/系统时间被改 | 录制前校准系统时间，别用改时区「修」 |
| 录到内部术语（H-16、P0-9 之类） | 口误 | 重录该段，交付版不出现内部编号 |
