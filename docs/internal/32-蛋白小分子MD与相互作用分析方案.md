## 1. 目标与不在范围内

**目标**：让「MD 跑完之后能回答什么问题」形成闭环——不只是 RMSD/Rg 曲线，而是「配体在结合口袋里跟哪些残基、以什么方式、持续了多久」，并让任意小分子都能进入 MD。

| 能力线 | 输入 | 输出 | 章节 |
|---|---|---|---|
| 相互作用分析 | 拓扑 + 轨迹（+ 可选配体模板） | `contacts.csv`、`interactions.json` | §3、§4 |
| 配体参数化 | SDF/MOL/MOL2 或用户自备拓扑包 | 配体 `.itp`/`.gro`/atomtypes、复合物 `.gro`、改写后的 `.top` | §5 |

**本期不做**：自由能计算（FEP/TI，已有 gmx_MMPBSA 端点法保持原样）；蛋白-蛋白界面打分与口袋检测；执行调度（L1）、数据库表结构、前端页面的改动；运行期在线下载依赖（antechamber/acpype 的力场数据必须随镜像提供）。

## 3. 阶段 A：相互作用分析内核

### 3.1 引擎选择：ProLIF 优先，mdtraj 兜底

| 引擎 | 判定内容 | 依赖 | 定位 |
|---|---|---|---|
| ProLIF | 氢键、疏水、盐桥、π 堆积、cation-π、卤键、水桥、vdW 接触 | MDAnalysis + ProLIF + RDKit | 首选，语义最全，直接映射到类型词表 |
| mdtraj | 重原子距离阈值内的接触（归为 `vdw_contact`） | mdtraj | 兜底，ProLIF 不可用或失败时降级并在 `warnings` 明示 |

降级是**运行时行为**，不是构建期开关：`analyze_trajectory()` 先试首选引擎，抛出任何异常都转兜底；两者都失败才抛 `RuntimeError`。

ProLIF 路径有四条硬性约定：

1. **逐帧 AtomGroup**：每一帧都以 MDAnalysis 的原子组视图交给 `Fingerprint.run(frames, ligand, protein)`，绝不把静态 `plf.Molecule` 当帧传；
2. **模板只用来传键级（无模板/部分 CONECT/水选区均逐原子补猜）**：传入的配体模板 SDF 先校验原子数与元素顺序（比较**完整元素符号**，`Cl` 不能截断成 `C`），再逐键写回键级；模板的键下标是配体内部 `0..N-1`，写回时必须映射成 MDAnalysis 的**系统级原子下标**（`ligand_atoms[i].index`），否则多组分的轨迹会把键级写到别的分子上。写回不是给 `bond.order` 赋值（Bond 视图上的赋值不持久化，ProLIF 读到的仍是原值）：先快照 `universe.bonds` 里已有的蛋白/力场键（缺键级按 `1.0`）；**只要蛋白选择内部存在任何尚未成键的原子**（`group_ids.issubset(bonded)` 为假——无论是完全无 `CONECT`、只有配体/水 `CONECT`，还是只有一条局部蛋白 `CONECT`）时，必须先调蛋白 `AtomGroup.guess_bonds()`（拿不到再退回 `universe.atoms.guess_bonds()`）补猜蛋白键再快照——否则只有 1 条蛋白 `CONECT` 时也会跳过整组补猜导致蛋白键不全、ProLIF 漏报接触；**无 SDF 模板时对蛋白与配体两选区分别按逐原子判据触发 `guess_bonds()`**，且**启用 `WaterBridge` 时在构造 `Fingerprint` 前也要对非空 `water` 选区按同一逐原子判据触发 `guess_bonds()`**（否则无水分子 `CONECT` 时 O–H 键缺失会导致水桥静默漏报）。快照与模板键合并后构造成 `MDAnalysis.core.topologyattrs.Bonds(pairs, order=orders, types=orders, guessed=False)`，交给 `universe.add_TopologyAttr(bonds_attr)`（或 `universe.add_bonds(bonds_attr)`）。MDAnalysis **2.10.0 既没有 `orders=` 关键字，也拒绝 `add_TopologyAttr("bondorders", ...)`**——旧实现吞掉异常后蛋白键级 `1.5` 和配体键级 `2.0` 会全部丢成 `None`，所以只有真实 `Bonds` 对象这一条写入路径，旧版没有 `Bonds` 时才退回 `bonds` + `bondorders` 两个属性。写入后**读回 `universe.bonds` 逐键比对**（含既有蛋白键与各自原键级，不精确相等即失败），读不回就返回失败并留 warning，绝不假定「赋值成功」；模板本身永远不作为帧或分子对象进入指纹计算；
3. **水桥显式开启**：ProLIF 2.1+ 的 `WaterBridge` 在构造时就要拿到水的 `AtomGroup`，写法是 `Fingerprint(interactions, parameters={"WaterBridge": {"water": water_ag}})`；**绝不**给 `fp.run(..., water=...)` 传关键字（该签名不接受 `water`）。默认类型表**不含**水桥，只有配置了 `water_resname` 且选择非空时才追加。
4. **建 Universe 前先防合并重编**：MDAnalysis 2.10 在解析 PDB 构造 `Universe` 时，会把 `TER` 前后同链、同残基号、同残基名的残基（如两个 `A:ALA10`）**合并成一个 `Residue`**，此后再由 `_renumber_protein_residues` 拆分已无从下手，ProLIF 会漏掉第二个 `TER` 段的接触。故在调用 `mda.Universe(...)` **之前**先按原子表生成一份临时拓扑副本：仅当存在跨 `TER` 段（`segment > 0`）或插入码/空链合并冲突时，把每条 `ATOM`/`HETATM` 的 `resSeq`（严格 4 位 `(seq_id-1)%9999+1`）/`icode`/`segid`（固定 4 列 `S{(seq_id-1)//9999:03X}`，绝不随 `segment >= 100` 溢出挤占第 77 列元素与第 79 列电荷）改成按原始 `PdbResidue` 唯一的序号（`resName`、原子名、元素、坐标与 `CONECT` 原样保留），用该副本建 `Universe`，并置于 `TemporaryDirectory` 中；后续接触映射仍以原始原子表/残基表为准，准确还原真实 `(链, 残基号, 残基名, 插入码, 段)`。

阈值以 nm 配置、以 Å（`×10`）交给**接受 `distance` 的构造器**（氢键、疏水、盐桥）。`VdWContact` 的构造签名是 `VdWContact(tolerance, vdwradii, preset)`，**不接受 `distance`**，传了会抛 `TypeError` 并把整条 ProLIF 路径打成兜底——因此 vdW 接触一律走 ProLIF 默认半径/容差，`interactions.json` 的 `cutoffs_nm` 在 `engine == "prolif"` 时**不写 `contact`**，如实反映「阈值未生效」。

距离不是从 DataFrame 的布尔值来的，而是回读 `fp.ifp`：结构是 `{frame: {(lig_res, prot_res): {interaction: ({...metadata...}, ...)}}}`，每个接触是一个 metadata 字典元组，带 `"distance"`（Å，也可能以列表形式给出）。取该帧该残基对的有效最小值，`/10` 还原 nm，全部缺失写 `None`。DataFrame 的列是 `(ligand, protein, interaction)` 三元组、行索引是真实帧号；解析按元组取值，并用真实帧号回填 `frame` / `time_ps`。

**残基身份**：ProLIF 的 `ResidueId` 与 mdtraj 1.10.3 的 `Topology` 都会丢失 PDB 插入码（`42A` 与 `42` 合并），空链还会让 `str()` 少掉点号（`ALA42` 而不是 `ALA42.A`）。所以两条引擎都先按原子顺序预解析输入 `topology_pdb`，得到 `(链, 残基号, 插入码, 残基名)` 精确表。解析时在连续当前残基内按 `atom_name -> {altLoc}` 对齐 OpenMM/MDTraj `Residue._add_atom` 口径：对每个连续残基键 `(链段, 链, 残基号, 插入码)` **锁定首个出现的 `resName`**（如 `A=ALA10` 锁定 `ALA`），同名**不同 `altLoc`** 只保留首个构象，**同残基同名同 `altLoc` 的重复原子（如未编号区分的配体 `C`/`C`）保留**；后续构象的独有重原子仍保留并归入锁定残基名（`B=SER10` 的骨架 `N/CA/C/O/CB` 因不同 `altLoc` 跳过，独有 `OG` 保留并记为 `A:ALA10`）；跨新残基即清空当前原子表（故 GROMACS `%10000` 回绕不误删原子），`TER` 会**开启新的链段**，`TER` 后复用链号 `"A"` 的同号残基不与前段合并。MDAnalysis/ProLIF 路径不去重，保留全量 altLoc 原子，原子表与它们建的拓扑 1:1 对齐。**链段要一路带到底**：`PdbResidue.segment`（`TER` 计数）经 `FrameContact.residue_segment` 进入聚合、时间线与网络的分组键，`(链, 残基号, 插入码, 残基名)` 相同时靠段号区分——`TER` 前后各有一个 `A:ALA10` 时聚合出**两条独立记录**、网络是**两个残基节点**（节点 ID 冲突时写成 `A#<段>:ALA10`，无冲突仍保持 `A:10:ALA`）、同一帧时间线计 2 个接触；`CONTACTS_CSV_COLUMNS` 列不变，段号只参与内部分组与排序。

ProLIF 侧的残基身份还有三处必须做对，否则接触会静默丢或串到别的残基上：

1. **`parent_indices["protein"]` 是蛋白选择集的局部下标**，不是体系全局下标：先用 `prot_ag.indices[local_idx]` 映射回全局原子下标，再查 PDB 原子表；只有没有 `parent_indices` 的旧版 ProLIF 才退回 `entry["protein"]`；
2. **进入指纹前把蛋白残基重编号为唯一临时 `resid`（1..N）**，同时记下「临时 resid → PDB 残基」映射。ProLIF 的 `ResidueGroup` 只按 `ResidueId(resid, resname)` 建键，同链的 `42`/`42A`、或空链与有名链的同号残基会直接**撞键合并、丢掉一组接触**；重编号后键唯一，接触回来再经映射还原成原始 `(链, 残基号, 插入码, 残基名)`；
3. 映射失败才退回「解析字符串 id + 唯一匹配」。残基字符串的正则同时接受 `ALA42.A`、`ALA42`、`ALA42A` 三种写法，也接受带 `name/number/chain/icode` 属性的对象，空链不再被丢弃。

mdtraj 兜底只统计**重原子**对（剔除氢），存在晶胞时用 `periodic=True`；`stride` 抽样后仍保留**原始帧号**（`frame = 抽样序号 × stride`）。兜底路径只认 `contact` 一个阈值，因此 `interactions.json` 的 `cutoffs_nm` / `cutoffs_angstrom` 在 `engine == "mdtraj"` 时**只写 `contact`**，不搬未使用的占位阈值。时间轴两条引擎同一口径：配置了 `frame_dt_ps` 就一律 `time_ps = 原始帧号 × frame_dt_ps`；DCD 的 `time` 是帧号而非物理时间，遇到 `.dcd` 且未提供 `frame_dt_ps` 时写一条 warning，并按帧号记 `time_ps`。这保证 `contacts.csv` / `interactions.json` 的时间列不因降级换引擎而改变语义。

### 3.2 模式判定

`InteractionConfig.mode` 支持 `auto` / `protein_ligand` / `protein_interface`：

1. 拓扑中出现 `ligand_resname`（默认 `LIG`）→ `protein_ligand`；
2. 否则蛋白链数 ≥ 2 → `protein_interface`（取一条链为锚点，其余为环境）；
3. 都不满足（单链且无配体）→ `single_chain`：**不报错**，写出只有表头的 `contacts.csv` 与 `engine: "skipped"` 的 JSON，并附一条 warning。

第 3 条是刻意的：批量任务里混进一个纯蛋白轨迹，不应该让整批任务失败。

边界口径：拓扑或轨迹文件缺失时直接抛 `FileNotFoundError`，**不静默降级成 `skipped`**；`skipped` 只表示「文件齐全但没有可分析对象」。显式指定 `protein_interface` 时不会被 `LIG` 残基劫持回配体模式。模式判定按 PDB 固定列解析，空链 `""` 与 `"A"` 是两条不同的链。

### 3.3 类型词表与聚合口径

规范化后的 9 类：`hbond_donor`、`hbond_acceptor`、`hydrophobic`、`salt_bridge`、`pi_stacking`、`cation_pi`、`halogen`、`water_bridge`、`vdw_contact`。ProLIF 原始名（`HBDonor`、`Anionic`、`FaceToFace`、`CationPi`、`XBDonor` …）通过显式映射表转换，未知类型丢弃而不透传——保证 CSV 列值可枚举、前端可稳定着色。

- **帧内去重**：同一帧里同一 `(链, 残基号, 插入码, 残基名, 类型)` 只算一次，距离取帧内最小；同一帧后到的 `None`（引擎没给距离）**不得覆盖**已经记下的有效距离；插入码参与区分（`42` 与 `42A` 是两个残基）。
- **占据率** `occupancy = 命中帧数 / 抽样总帧数`，分母是**抽样后的帧数**（`stride > 1` 时不是原始帧数），并把 `contact_frames` 截断到不超分母，保证严格落在 `[0, 1]`。
- **距离统计**：`min_distance_nm` 取全轨迹最小，`mean_distance_nm` 取各帧最小值的平均；全部缺失时两者均为 `None`，**不补 0**。
- **排序**：`(-occupancy, 链, 残基号, 插入码, 残基名, 类型)`，保证同数据两次运行字节一致；`min_occupancy` 用于过滤转瞬即逝的接触。

## 4. 产物契约

### 4.1 `contacts.csv`

固定 10 列，UTF-8，无 BOM，数值保留 4 位小数，`None` 写空串：

| 列 | 类型 | 含义 |
|---|---|---|
| `residue_chain` | str | 蛋白残基链 ID（空链写空串） |
| `residue_seq` | int | 残基序号 |
| `residue_icode` | str | PDB 插入码（无则空串） |
| `residue_name` | str | 三字母残基名 |
| `interaction_type` | str | §3.3 的 9 类之一 |
| `occupancy` | float | 占据率，0~1 |
| `contact_frames` | int | 命中帧数 |
| `total_frames` | int | 统计总帧数 |
| `min_distance_nm` | float/null | 最小距离（nm） |
| `mean_distance_nm` | float/null | 平均距离（nm） |

只有表头没有数据行的 CSV 是合法产物（`single_chain` 场景）。

### 4.2 `interactions.json`（`schema_version: "1.0"`）

顶层字段：`schema_version`（`"1.0"`）、`mode`、`engine`（`prolif` / `mdtraj` / `injected` / `skipped`）、`ligand_resname`、`stride`、`total_frames`、`cutoffs_nm`、`cutoffs_angstrom`、`summary`、`timeline`、`network`、`warnings`。

- `summary`：`total_interactions`、`residue_count`、`by_type`（按类型计数）、`max_occupancy`。
- `timeline`：逐帧 `{frame, time_ps, total_contacts, hbond_count, hydrophobic_count, salt_bridge_count, other_count}`，空帧补零——前端画曲线不用自己对齐帧号。
- `network`：以配体（或界面锚点）为中心的无向加权图。节点 `id` 为 `链:残基号+插入码:残基名`，带 `kind`/`degree`/`weighted_degree`；**每条边唯一对应一个 `(source, target, interaction_type)`**，`occupancy` 独立且严格落在 `[0, 1]`（同一对残基的多种作用是多条边，不再用 `+` 拼类型），加权度单独记在节点的 `weighted_degree`（等于相邻边占据率之和，不会和 `occupancy` 混用）；`stats` 含 `node_count`、`edge_count`、`connected_components`（有 networkx 用 networkx，没有则用纯 Python BFS）、`hub_residues`（加权度前 5 的非锚点残基）。
- `warnings`：降级、跳过、模板缺失等非致命信息，前端直接展示，不用日志兜。

`contacts.csv` 面向「表格/导出」，`interactions.json` 面向「画图/二次分析」，两者由同一份聚合结果写出，不允许各算一遍。

## 5. 阶段 B：小分子力场参数化

### 5.1 两种模式，一个入口

`parameterize_ligand()` 统一编排，模式可显式指定或由输入自动判定：

| 模式 | 触发 | 做什么 | 适用 |
|---|---|---|---|
| `custom_itp`（Mode 0） | 传入 `.itp`/`.prm`/`.gro` 或拓扑 zip | 递归校验 → 内联展开 `#include` → 拆分全局参数段 → 探测 `[ moleculetype ]` → 交付后校验 | 用户自备 CGenFF/OPLS/已有 GAFF 参数；离线最稳 |
| `gaff2_acpype`（Mode 1） | 只传入 SDF/MOL/MOL2 | RDKit 规范化 → antechamber 电荷 → acpype 生成 GROMACS 拓扑 | 新分子默认路径 |

`auto` 的优先级：有自定义包走 Mode 0，否则有结构文件走 Mode 1，都没有则报错。Mode 0 不做「猜参数」，缺 ITP 或缺 `.gro` 直接失败并说明缺哪个。

### 5.2 Mode 1 链路

1. RDKit 读取 `.sdf`/`.mol`/`.mol2`；多分子 SDF 按**原始 0 下标**取第 N 条记录，坏记录不会让索引偏移；
2. 校验：非空；构象必须 `Is3D()`（RDKit 生成的 2D 构象标记为 `False`，直接拒绝）；坐标全部有限（无 `nan`/`inf`）；不允许所有原子坐标完全重合（退化构象）。除这三条外不做别的几何判定——平面芳环、近乎平面的分子都允许进 MD；
3. 加显式氢、推断形式电荷；用户给定 `net_charge` 与推断值不一致则报错（不静默改写）；
4. 输出规范化 `.sdf` 与**标准 `.pdb`**（所有原子的 `ResidueName` 统一改成 3 位配体残基名，如 `LIG` 而不是 RDKit 默认的 `UNL`），不再输出 MOL2；
5. 每次调用都在**全新的隔离子目录**里执行 `acpype -i <绝对路径> -b <acpype_basename> -a gaff2 -c bcc|gas -n <charge> -o gmx -d`（电荷方法只允许 `bcc` / `gas`）。`acpype_basename` 就是校验过的配体残基名（默认 `LIG`），命令与产物查找**共用同一个变量**：acpype 按 `-b` 命名输出，若一边传 `-b LIG`、另一边按输入文件名 `ligand` 去找，真实运行必然「找不到产物」；
6. 产物必须**同时**满足两条判据：`returncode == 0`，且 `<acpype_basename>.acpype/<acpype_basename>_GMX.itp` 与 `<acpype_basename>_GMX.gro` 精确存在（`*_GMX_OPLS.itp` 不算，禁止递归搜索取首个 `.itp`）；
7. 对 `_GMX.itp` 再做一次 atomtypes 拆分，得到 atomtypes ITP 与干净配体 ITP；`[ atoms ]` 原子数与 `.gro` 原子数、残基名必须一致，不一致抛错（不合成占位文件）。

### 5.3 AmberTools 环境

与 `mmpbsa_platform.py` 共用同一套布局，避免镜像里出现两套 Amber：`AMBERHOME=/opt/amber/anaconda3/envs/AmberTools`、`OPAL_PREFIX=/opt/amber/anaconda3`；`PATH` 前置 `AmberTools/bin` 与 `anaconda3/bin`，`LD_LIBRARY_PATH` 前置 `anaconda3/lib`、`AmberTools/lib`；`OMPI_MCA_plm=isolated`、`OMPI_MCA_rmaps_base_oversubscribe=1`（容器内单机跑 MPI 工具）。环境由 `resolve_amber_env()` 纯函数生成，测试可直接断言键值。

### 5.4 复合物装配

- `merge_gro_files()`：蛋白与配体原子顺序拼接，原子号重排（`% 100000`）；前 20 列（`resnum 5 + resname 5 + atomname 5 + atomnr 5`）固定，坐标区**按首个浮点数的小数位数确定统一列宽** `width = 5 + 小数位数`（3 位 → 8 列、4 位 → 9 列、5 位 → 10 列，与 GROMACS `groio.cpp` 一致），只从 `line[20 : 20 + 3*width]` 切 x/y/z，可选速度区从 `line[20 + 3*width:]` 起按同一宽度校验。**不做「试切失败再用正则补位」**：任一坐标或速度 `nan`/`inf`/不可解析立即报错，绝不跳过坐标去读速度区再补 `nan`。输出一律 `8.3f`。盒子向量支持 3 分量与 9 分量三斜盒子并原样保留，原子数、非有限坐标、盒子分量数非法时直接报错。
- `patch_topol_top()`：幂等改写 `.top`——`;` 注释行不参与匹配，带缩进的 `#include` 也算已存在。`forcefield.itp`、已有配体 `#include`、`[ system ]`、`[ molecules ]` 都**只在预处理器深度 0 匹配**：藏在 `#ifdef WATER ... #endif` 里的 forcefield/配体 include 不算锚点，条件块里的 `[ molecules ]` 也不算区块。atomtypes 包含插在顶层 `forcefield.itp` 之后；配体 ITP 只插在**深度 0**且在第一处水模型 `#include` 或 `[ system ]` 之前，**绝不写进包住水模型的 `#ifdef`/`#ifndef` 分支里**（否则关掉水模型时配体的 moleculetype 与 posre 一起消失），也绝不写到 `[ molecules ]` 之后；posre 包在 `#ifdef POSRES_LIG` 内；`[ molecules ]` 更新或追加配体计数。第二次调用输出与第一次完全相同，避免重复任务把拓扑改花。
- 顶层找不到 `forcefield.itp`（含「只有条件编译里的」）或找不到 `[ molecules ]` 时**一律明确报错**，不再「补一个 `[ molecules ]` 段」——在这种拓扑上追加条目，写出的位置 GROMACS 根本不读。

### 5.5 输入安全

外部上传的拓扑 zip 是**不可信输入**，解压前必须逐条过闸：

| 风险 | 防御 |
|---|---|
| Zip Slip（`../`、绝对路径、盘符路径、反斜杠路径） | 成员名先归一化 `\`→`/`，逐条校验，解析后的目标必须落在解压根目录内 |
| 符号链接成员 | 检查 ZIP 属性位，命中即拒绝 |
| Zip Bomb | 条目数上限 32（**目录条目也计数**）、解压后总字节上限 50 MB，读取时按块扣减预算 |
| 大小写/路径归一化重复 | **文件、目录条目、以及由子文件隐式建出的父目录**都先归一化再按 `casefold` 去重；`Ligand.itp` 与 `ligand.itp`、`params/` 与 `PARAMS/`、`params/x.prm` 与 `PARAMS/y.prm`、文件 `params` 与目录 `Params/` 同时出现即拒绝 |
| 不支持的压缩方式 | 只允许 STORED / DEFLATED，其余（BZIP2/LZMA 等）直接拒绝 |
| 写文件时父目录被符号链接带出根目录 | 全部成员的路径归一化、越界判定与无符号链接校验都在**建任何目录/写任何文件之前**完成；落盘阶段只做 `mkdir` / `open`，不会再出现「校验没过但目录已经建出来」的中间状态 |
| 解压失败留下半个目录 / 覆盖掉旧结果 | 先解到临时暂存目录，全部校验通过后原子发布：`dest_dir` 不存在时单步 `os.replace(stage, dest)`；已存在时先改名为备份、再换入新结果，成功才删备份，失败则严格把备份换回去；若换入后目标位置又出现非预期目录，**保留备份并报错**，绝不删掉唯一的旧结果。任何异常都清理暂存目录 |

ITP 校验是**递归**的：非空、至少一个 `[ section ]`；`#include`（含 `# include` 这类带空格写法）先归一化再逐层展开。**相对路径按「发出 include 的那个文件所在目录」解析**（与 GROMACS 一致，而不是一律按包根），逐层目标都必须严格落在校验过的包根内，绝对路径、`..`、盘符、跳出包根、循环包含一律拒绝；拓扑包里的 `.prm`、`#include` 链上的每个文件、独立的 posre 文件都要过同一套校验（不能只查主 ITP）。递归用「当前递归栈（`visiting`）+ 已校验集合（`visited`）」两套记录：命中 `visiting` 才是真循环并报错，命中 `visited` 说明是共享/菱形依赖，直接跳过，不误判成循环。

Mode 0 交付的 ITP 落在 `work_dir`（包根之外），那里的相对 `#include` 解析不到，因此**不再复制 include 图**，而是把递归校验通过的相对 `#include` **按 GROMACS 预处理展开顺序内联**进正文（`#ifdef`/`#endif` 等条件编译行原样保留，越界/缺失目标一律拒绝，无法引入未校验的外部文件），再拆分全局参数段。拆 atomtypes 时跟踪 `#ifdef/#ifndef/#else/#endif` 作用域：全局参数段必须位于深度 0；多余的 `#endif` 直接报错；只要全局段与 `#define`/`#ifdef` 之类的条件编译交错（搬迁会改变宏作用域与生效顺序），就**拒绝拆分**而不是猜。

拆分完成后在 `work_dir` 对**最终交付的** `ligand_itp` 与 `atomtypes_itp` 做交付后校验：两者都不得残留任何 `#include`；全局参数节只能出现在 `atomtypes_itp`；`atomtypes_itp` 不得含非全局节，且 `[ atomtypes ]` 必须排在其他全局节（`[ bondtypes ]` 等依赖它的节）之前——顺序错了 GROMACS 会在读 `[ bondtypes ]` 时报未知原子类型。

配体残基名限定 1~3 位大写字母数字，并拒绝 20 种标准氨基酸与常见溶剂/离子名，否则写进 `.top` 会与蛋白残基撞名。
