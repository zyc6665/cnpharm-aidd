# 命名空间与资源命名迁移手册（sciminer → aidd）

| 项 | 内容 |
|---|---|
| 文档编号 | DRP-OPS-NAMESPACE-MIGRATION-v1.0 |
| 适用 | 2026-11 命名收敛：模型作业命名空间由 `sciminer-model-jobs` 迁移到 **`aidd-model-jobs`**，配套资源统一 `aidd-*` |
| 上游 | `deploy/kubernetes/namespace.yaml`、`execution-rbac.yaml`、`execution-worker.example.yaml`、`docs/05-部署/24` |
| 状态 | 清单已改，集群侧按本手册执行 |

## 1. 为什么不能只改代码

平台切换 `K8S_ADAPTER_NAMESPACE` 后：

- 新 Job 写入 `executions/aidd-model-jobs/<job>/...`，**in-flight 旧任务**的产物仍在 `executions/sciminer-model-jobs/...`，`kubernetes_artifacts.py` 会以 `external_id namespace does not match` 拒绝回收。
- 旧命名空间的 SA/Role/RoleBinding/Secret 不会自动出现在新命名空间，提交会 403 或 Pod 卡 `CreateContainerConfigError`。
- PVC 是命名空间级资源，**换命名空间等于换数据**；本手册只迁移「模型作业」命名空间，数据服务（PostgreSQL/Redis/MinIO/Registry）如仍在旧命名空间，应保持不动或单独评估。

## 2. 前置检查

```bash
# 1) 确认无运行中的模型任务（status 非终态）
kubectl -n sciminer-model-jobs get jobs -o wide
# 2) 记录待清理 Job/Pod，确认产物已回收（平台任务详情状态为终态）
# 3) 备份当前清单与 Secret
kubectl -n sciminer-model-jobs get sa,role,rolebinding,secret -o yaml > /tmp/old-model-jobs-rbac.yaml
```

**切换窗口要求**：Worker 重启后才会读取新 `K8S_ADAPTER_NAMESPACE`；切换期间不要提交新任务。

## 3. 迁移步骤

### 3.1 创建新命名空间与标签

```bash
kubectl apply -f deploy/kubernetes/namespace.yaml
kubectl get ns aidd-system aidd-model-jobs aidd-storage
```

### 3.2 创建 SA / Role / RoleBinding

```bash
kubectl apply -f deploy/kubernetes/execution-rbac.yaml
kubectl auth can-i create jobs -n aidd-model-jobs \
  --as=system:serviceaccount:aidd-system:aidd-execution-worker   # 期望 yes
```

### 3.3 创建 Job 上传凭据

Job 通过 `secretKeyRef` 读取 `access-key` / `secret-key`：

```bash
kubectl -n aidd-model-jobs create secret generic aidd-minio-client \
  --from-literal=access-key='<MINIO_ACCESS_KEY>' \
  --from-literal=secret-key='<MINIO_SECRET_KEY>'
```

> 凭据来源以部署环境为准；不要从 `cnpharm-aidd-credentials`（键为 `MINIO_ROOT_USER/PASSWORD`）直接复制。

### 3.4 放行 NetworkPolicy

```bash
kubectl apply -f deploy/kubernetes/network-policies-dev.yaml
# 确认 storage 侧允许 aidd-model-jobs 访问 9000/5000
```

### 3.5 切换 Worker 配置并重启

```bash
# execution-worker.example.yaml 已改为：
#   K8S_ADAPTER_NAMESPACE: aidd-model-jobs
#   K8S_ADAPTER_JOB_NAME_PREFIX: aidd
#   K8S_ADAPTER_OBJECT_STORAGE_STAGING_ROOT: /tmp/aidd-k8s-artifacts
kubectl apply -f deploy/kubernetes/execution-worker.example.yaml
kubectl -n aidd-system rollout restart deployment/aidd-execution-worker
```

平台 `.env` 同步：

```
K8S_ADAPTER_NAMESPACE=aidd-model-jobs
K8S_ADAPTER_JOB_NAME_PREFIX=aidd
K8S_ADAPTER_OBJECT_STORAGE_STAGING_ROOT=/tmp/aidd-k8s-artifacts
```

### 3.6 冒烟

```bash
# 用平台提交一个最小任务，或手工创建 Job 验证调度与产物前缀
kubectl -n aidd-model-jobs get jobs,pods
# MinIO 侧确认对象前缀：executions/aidd-model-jobs/<job>/result.json
```

## 4. 回滚

1. Worker/.env 改回 `K8S_ADAPTER_NAMESPACE=sciminer-model-jobs` 并重启；
2. 新命名空间中的 Job 全部删除（`kubectl -n aidd-model-jobs delete jobs --all`）；
3. 旧命名空间资源未删除，回滚无需重建。

## 5. 已知不兼容点

| 项 | 说明 |
|---|---|
| in-flight 任务 | 切换前必须排空；旧 `external_id` 不要改写，历史追溯保留 |
| 对象前缀 | 新旧产物分别位于 `executions/<旧ns>/` 与 `executions/<新ns>/`，平台按当前 namespace 查找，不跨前缀 |
| 镜像内路径 | `/opt/sciminer/**` 由新镜像的 `/opt/sciminer -> /opt/aidd` 符号链接兼容；本手册不涉及 |
| 日志/指标 | 应用名与指标前缀已改 `aidd`，旧看板查询需同步 |
